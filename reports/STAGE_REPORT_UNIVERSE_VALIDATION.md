## 4. 发现的新缺陷（7 项，全部已修或有明确处置）

### 4.1 测试收集错误的根因：**命令不对，不是代码坏**

`ModuleNotFoundError: No module named 'tests'`。真因是三个条件缺一不可：
工作目录必须是 `backend/`、`PYTHONPATH=src`、**Windows 下 `PYTHONPATH` 用 `;` 不是 `:`**。

→ 修复：固化 CI 的命令（`cd backend && PYTHONPATH=src python -m pytest tests/`）。
**这个"错误"挡了我两轮，代价是"工程可信度未知"持续了很久。**

### 4.2 ⚠️ V2 交叉验证不检查日期覆盖（**最严重的一个**）

旧实现只比对 `set(a) & set(b)` 的**交集数值**。**变异测试**实测：

```
把 exec_all 的 000001.SZ 砍掉最后 200 行
旧 V2 判定：common=4940、数值差异=0 → PASS（漏检！）
实际缺失 200 个交易日
```

→ 这就是 002916.SZ 的截断能存活两轮的原因。
→ 修复：加"区间内日期集合双向比对"。修复后重跑：**549 只，数值 + 日期，双向 0 不一致**。

### 4.3 30 只退市股被当成"缺失"，实为"未知未获取"

`URLError: Tunnel connection failed: 502 Bad Gateway`（代理故障）。直连探测 **30/30 都有数据**。

→ 修复：补抓后 `exec_all` 从 5,442 → **5,472（100%）**。
→ 教训：**"缺失"必须区分"确认不存在"与"未知未获取"**。

### 4.4 ⚠️ D-1 缺陷第三次复现：205 只的分红文件缺失导致 ADJ 未建

`div_source_unavailable` 被当成"确认无公司行为"，实际是**文件不存在**。
补抓后发现：**205 只 A 股里 204 只有分红事件**——它们本该被复权。

→ 修复：补抓 + 重建 → `qfq_all` 从 5,239 → **5,444**。
→ **三次复现**（249 只退市股、30 只补抓股、205 只分红缺失股），机制完全相同。

### 4.5 28 只差额的三态标注（把"未知"变成"已知"）

| 类别 | 只数 | 性质 |
|---|---:|---|
| B 股 | 14 | **结构性排除**（本不该在 A 股宇宙） |
| 新股（数据不足） | 14 | **无影响**（不满 252 日） |

→ **真正"该进 ADJ 却进不去"的 = 0 只。**

### 4.6 B 股是靠"ADJ 缺失"隐式排除的，不是显式规则

如果补上 B 股分红，它们会**静默进入 A 股宇宙**。
→ Gate 6 已冻结不改；**阶段 C 起必须显式排除**（登记在 `ASOF_UNIVERSE_AUDIT` §4.2）。

### 4.7 我自己的检查写错了 4 次（性质检查的自纠）

| 检查 | 错法 | 后果 |

| PC2 v1 | `limit × (1 + TOL)`，TOL=1.02 → 阈值 ×2.02 | 报 PASS 但**什么都没检** |
