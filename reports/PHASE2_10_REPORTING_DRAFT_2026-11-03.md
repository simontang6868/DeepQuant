## 3. 申报数字怎么做到"不是编的"

这是 2.10-b 的实质。做法不是「抄写时小心」，而是三层：

**第一层：单一来源。** 所有申报数字只写在 `forward/execution_config_v1.json`，每个数值配一个 `_source_<键名>` 指向产生它的代码位置。测试 `test_every_number_has_a_declared_source` 强制"每个数值都得有来源"——**没有来源的数值就是编的**，而这份配置唯一的用途就是喂给申报材料。

**第二层：配置与代码的一致性测试。**

| 申报数字 | 断言它等于 |
| --- | --- |
| 单日 12 笔 | `RiskLimits.for_strategy_capital(max_daily_orders=12).max_daily_orders` |
| 价格偏离 0.3% | `planner.DEFAULT_PRICE_DEVIATION` |
| 整手 100 股 | `PlanInput.lot_size` 默认值 |
| 持仓 5 只 | `sp4_config_v1.json` 的 `n_hold` |
| 每秒上界 4 笔 | `RateLimiter.orders_per_second_upper_bound()` |

**第三层：数字的描述也要被验证。** `02` 里写「12 笔约 6 秒发完」，`test_single_order_window_claim_is_consistent` 就**实际跑一遍限速器**，测出 12 笔用了几秒。写错了会红。

另外 `test_daily_cap_is_tighter_than_rate_for_one_minute` 断言「一分钟能发 122 笔 ≫ 日上限 12 笔」，用来支撑材料里「主约束是日笔数、不是高频」这个判断——这句话如果写反了，会被当成高频策略。

### 3.1 写材料时自己抓到的一处错（登记在此，不改历史稿）

`01_策略说明.md` 第一版写「年换手 约 23%（月度，单边）」——两处都错：

1. **数值错**：exQ5 的实测**月度单边换手是 0.18862**（18.86%，n=237，来自 `phasei`），不是 23%。23.1% 是**低波动信号**的换手，我串了另一个信号的值——这正是 MEMORY 里「换手禁止沿用别的信号」那条铁律说的错法，只不过这次是发生在写文档而非算数里。
2. **量纲错**：「年换手」与「（月度，单边）」并列本身就是矛盾的。

处置：改为「月度单边换手 18.86%（实测，n=237；口径 `0.5×(|增|+|退|)/k`）」，并**明确不填年换手**——月度×12 不是实测年换手（持仓跨月延续），而频率类指标填错会直接影响是否被认定为高频。宁可不填，也不给一个推出来的数。

## 4. 一句必须写进材料的话

「唯一的报单出口是接口层」——这句话我把它做成了测试 `test_only_broker_layer_can_submit_orders`：`execution/` 下不得出现继承 `BrokerAdapter` 的类。要发单必须有一个 adapter 实例，实例只能由 `broker/` 提供；execution 层若自己实现一个 adapter，就等于开了第二个出口。

配一条反向测试 `test_broker_adapter_subclasses_live_only_in_broker_package`，确认 `broker/` 里确实有实现——否则上一条会因为"根本没实现"而空转（假绿）。

## 5. ⚠️ 对 Phase 2.2 判定的更正

写材料时逐条核对，发现 **2.2 此前判 `PASS` 过宽**。原文不改，在此更正。

| 验收项 | 内容 | 实际状态 |
| --- | --- | --- |
| 2.2-a | 差额订单、先卖后买、整手取整 | ✅ 已实现 |
| 2.2-b | `client_order_id` 幂等、不含时间戳/随机数 | ✅ 已实现 |
| 2.2-c | 次一交易日 **09:35 后**限价单 | ❌ **未实现**（无发单循环，无时点调度） |
| 2.2-c | 对手价最多让 **0.3%** | ✅ 已实现（`DEFAULT_PRICE_DEVIATION` + 涨跌停夹取） |
| 2.2-c | **10:30、14:30 各最多重定价一次** | ❌ **未实现** |
| 2.2-c | 收盘未成交记失败并**顺延，最多 10 个交易日** | ❌ **未实现** |
| 2.2-d | 同一 id 重定价次数上限 2 | ❌ **未实现**（只有 `make_client_order_id(..., revision)` 支持 `-r1` 后缀，没有计数与调度） |
| 2.2-e | 卖出回款不假定可用于买入 | ✅ 已实现 |

**更正后的判定**：2.2 应为 **`PASS_WITH_GAPS`**，缺口是执行调度（09:35 时点、重定价、顺延、次数上限）。

**为什么当时没发现**：2.2 的 22 条测试全部围绕"目标 → 差额订单"这个纯函数，而重定价与顺延是**跨日的调度状态机**，不在 `plan_orders` 的职责里。测试覆盖的是实现了的部分，没实现的部分没有任何测试会红——这不是测试写错，是**测试范围与验收项范围不一致**，而我当时按"测试全绿"判了 PASS。

**影响**：`02` §4 的重定价与顺延条款目前**不能作为申报内容**，它们描述的是尚未存在的调度器。已在材料与配置中显式标注。

**处置**：不改原文，不补测试充数。缺口需在 Phase 3（有发单循环之后）实现，届时按新预登记做。
