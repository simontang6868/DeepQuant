## 2. 任务 B2：与 `exec_long` 的重叠核验

### 2.1 ⚠️ 先说一个被变异测试揭出来的漏洞

旧版 V2 的实现是：

```python
common = sorted(set(a) & set(b))        # 只要交集
for d in common: 比 5 个字段          # 只比交集内的数值
```

**它对"日期缺失"完全无感。** 变异测试实测：把 `exec_all` 的 000001.SZ **砍掉最后 200 行**，
旧版判定 **PASS**（`common=4940`、数值差异 0），而实际缺失 200 个交易日。

> 这正是 002916.SZ 的截断能存活两轮的原因：**"逐行交叉验证"如果只验交集，就等于没验覆盖。**

### 2.2 修复

V2 现在验两条：

1. **区间内交集的 5 个字段**（open/high/low/close/volume）逐行全等（容差 1e-9）；
2. **区间内日期集合双向比对**（`da − db` 缺失、`db − da` 多出）。

区间取 `[max(各自首日), min(各自末日)]`，避免把 `exec_long` 从 2004-12 开始、
`exec_all` 从 2005-01 开始的窗口差算成"缺失"。

### 2.3 修复后的结果

```
[V2] 交叉验证 549 只（与 exec_long）| 数值/日期不一致 0 只 | 缺失文件 0 只 | exec_all 多出日期 0 只
[V2] 口径：①区间内交集数值 5 字段全比对 ②区间内日期集合双向比对（变异测试已证实可检出 200 天截断）
```

**这是本轮最强的一致性证据**：549 只 × 平均 ~2,000 个交易日 × 5 个字段，**加日期集合**，全等。

## 4. 任务 B4：as-of 股票池接口

### 4.1 为什么不能返回布尔值

`not in universe` 至少有五种原因：未上市、已退市、当日停牌、抓取失败、从未有数据。
**混成一个 False，就会让"数据缺失"伪装成"当时不存在"** —— 这是 D-1 的同构错误。

因此 `scripts/asof_universe.py` 用五态枚举：

| 状态 | 含义 | 能否推断"不存在" |
|---|---|---|
| `HAS_DATA` | 当日有行情 | — |
| `SUSPENDED_LIKELY` | 上市区间内但当日无行情 | 疑似停牌，**不可交易** |
| `BEFORE_LISTING` | 首个行情日之前 | **确认**未上市 |
| `AFTER_LAST_DATA` | 末个行情日之后 | **不可区分**退市 / 抓取失败 |
| `NO_DATA` | 全区间无行情 | **未知** |

### 4.2 刻意删掉的一个选项

原设计有 `include_after_last_data`（允许序列终止后的标的入池）。**已删除**，理由：

- 序列终止后当日无价，只能用最后价估值 → 等于假设"退市时能以最后价卖出"，**凭空造收益**；
- 而且"已退市"与"抓取失败"本来不可区分，放行等于把未知当已知。

如确需这类敏感性分析，必须另开预登记并显式声明估值假设。
