### 2.2 决策日被数据「钉死」在 20260930

`p13_forward.py:91-105`：

```python
def latest_closed_month():
    me = fast_calendar()                       # 交易日并集，来自 qfq_all
    months = sorted({d[:6] for d in me})
    last_month = months[-1]                    # 数据中最后一个「月」
    closed = [d for d in me if d[:6] < last_month]
    return closed[-1]                          # 上一个完整月末
```

数据末日 = **2026-10-16** ⇒ 日历最后一个月是 `202610`，它「未完结」⇒ 函数返回 `20260930`。

**这意味着：只要不更新数据，每天 16:30 跑一次都只会重算 20260930，并因 `gap > 3` 自动降级为 SELFTEST。** 恢复调度必须与数据更新同时做，只做一件没有用。

`gap` 守卫（第 205-213 行）：

```python
today = time.strftime("%Y%m%d")
if me < today and not args.selftest:
    gap = (today - me).days
    if gap > 3:
        args.selftest = True   # 自动降级，不计入观察期
```

这条守卫是**正确的**（防回溯伪装成前瞻），任务书 §3 已登记。但它与 2.2 的钉死效应叠加，产生了「恢复调度也拿不到 FORWARD 记录」的结果。
