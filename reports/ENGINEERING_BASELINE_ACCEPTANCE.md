## 1. 任务 A1：定位测试收集错误

### 1.1 现象

```bash
$ cd backend && PYTHONPATH=src python -m pytest tests/api/test_dataset_unavailable.py -q
ImportError while importing test module 'backend/tests/api/test_dataset_unavailable.py'
backend/tests/api/test_dataset_unavailable.py:20: in <module>
    from tests.api.conftest import ingest_dataset
E   ModuleNotFoundError: No module named 'tests'
```

### 1.2 根因

**运行方式错误，不是代码缺陷。** 三个必要条件缺一不可：

| 条件 | 正确值 | 我之前的错误做法 |
|---|---|---|
| 工作目录 | `backend/` | 仓库根目录 |
| `PYTHONPATH` | `src`（让 `import deepquant` 成功） | `backend/src`（路径本身没错，但**工作目录也不对**） |
| 分隔符 | Windows 下 `PYTHONPATH` 用 `;` 而非 `:` | 用过 `backend/src:backend`，**被当成一个字面路径**，两个包都找不到 |

两者叠加导致：`tests` 包找不到（工作目录不对）→ 报 `ModuleNotFoundError: No module named 'tests'`，
看起来像"测试文件坏了"，实际是**测试没被正确启动**。

### 1.3 影响范围

**仅影响测试运行方式，不影响任何生产代码路径**。证据：
- 修复运行方式后该文件 **11 passed**；
- 全量套件 **1997 passed / 0 failed**（§2）；
- 该文件测的是"数据集不可用时 API 的降级行为"，与数据管线、复权、Gate 实验均无耦合。

### 1.4 修复

不改代码，只固化正确命令（与 `.github/workflows/ci.yml` 第 32–40 行一致）：

```bash
cd backend
PYTHONPATH=src python -m pytest tests/ -q --no-header
```

CI 里的注释已经写明为什么用 env 而不是 `pytest.ini` 的 `pythonpath`：

> 部分用例会派生子进程（如 `test_deserialization_is_isolated_from_original_process`），
> 子进程只继承环境变量，不继承 pytest 的 pythonpath 配置。

**教训**：一个"收集错误"被我当成"可能有 bug"搁置了两轮，实际只是命令不对。
以后 CI 的启动方式就是唯一权威，本地跑测试必须复制它，不自己拼 `PYTHONPATH`。

## 4. 性质检查：9/9 PASS（不依赖市场结果）

审阅要求"增加不依赖具体市场结果的性质测试"。新增 `scripts/property_checks.py`，
每条绑定一个"若它错了结论必错"的不变量。

| # | 不变量 | 结果 |
|---|---|---|
| **PC1** | ADJ 价格必须全为正（乘性复权若有加性残留会出负价） | **PASS**：5,239 只，非正价 **0** |
| **PC2** | 非除权日不得出现"除权量级"跳变 | **PASS**：抽样 250 只，除权量级跳变 **0**；贴边噪声 40 处（舍入/复牌） |
| **PC3** | as-of 掩码无前视 | **PASS**：5,239 只 × 5,311 日；(a) 无价 0 (b) 不足 252 日 0 (c) 过早入选 0 |
| **PC4** | as-of 池规模应随扩容增长 | **PASS**：2004→2026 由 9 增至 5,243，异常下降年 **0** |
| **PC5** | 同一输入重建两次必须逐字节相同 | **PASS**：3 只两次重建 sha256 全等 |
| **PC6** | 组合权益恒等式 | **PASS**：200 组随机 (k,W,价格) 满足 3 条恒等式 |
| **PC7** | 费用 = 2 × 单边换手 × 12 × 费率 | **PASS**：30 组，不一致 0 |
| **PC8** | 反转 d 与动量 d 必须互为相反数 | **PASS**：125 个截面，`max\|d_rev + d_mom\| = 0.00e+00` |
| **PC9** | 每个除权事件后必须有对应交易日 | **PASS**：29,007 个事件，无对应交易日 **0** |

### 4.1 这三条最值得说

- **PC8 是本轮最强的构造检验**：它把"排序方向写反"这类最致命的错误变成可自动检出的量。
  `max|d_rev+d_mom| = 0` 是精确 0（不是 1e-12），说明两条腿确实只差一个符号。
  **这间接确认了 Gate 2/3/6 的方向定义与预登记一致**（同一套 `longs/shorts` 逻辑）。
- **PC3 把"前视偏差"变成了可数指标**：`过早入选 0` 意味着没有任何标的在第 252 个有效交易日之前进池。
- **PC9 确认事件没被静默丢弃**：29,007 个个案里没有一个落在"无交易日"上。

### 4.2 PC2 是三次自纠的产物（判据设计的教训）

| 版本 | 判据 | 结果 | 问题 |
|---|---|---|---|
| v1 | `limit × (1 + TOL)`，TOL=1.02 | 0 处超限"通过" | **`1+1.02=2.02`**，阈值被放大成 40.4%，等于没检 |
| v2 | `limit × TOL` | 40 处超限 | 未豁免**新股上市前 5 日无涨跌幅限制**（301060.SZ 首日 +55.99%） |
| v3 | 加 `warmup=5` | **6,395 处超限** | 分布：6,153 处在 10~12%、241 处在 15~22%、**0 处 >22%** |
| **v4（采用）** | 双档：FAIL > 涨跌停×2.2；WARN 只计数 | **0 处 FAIL** | 判据语义改为"有没有未处理的除权" |

**v1 是最危险的一种错**：它报 PASS，但实际什么都没检。
和 D-1 的"零事件 → A4 不适用"完全同构——**判据写得太松，通过率就是假的**。

v4 的语义依据是 D-1 那个真实缺陷：000616.SZ 2008-05-09 的 **−37.7%**（10送2转3 理论 −33.3%）。
所以阈值应按"除权量级"设（>22%），不按涨跌停设。**这不是放宽，是把标尺换对。**

### 4.3 PC6 也自纠过一次

初版把"现金上界"写成"最便宜标的的一手金额"，**200 组全部 FAIL**。
正确上界是 `Σ lot_i`（每只的残留都 < 它自己的一手金额）。
又一次印证：**性质测试的第一作用是抓到自己写错的断言**。
