## 0. 结论

1. **结论不变**：`ma_cross` 三档费率的收益中位数仍全为负（−1.84% / −2.10% / −2.87%），
   **144 个单元中 0 个从负翻正**，亏损窗占比**完全不变**（0.565 / 0.565 / 0.609）。
2. **但"改善"不能当成修复有效的证据**：聚合中位数从 −2.15%/−2.13%/−3.11% 变为 −1.84%/−2.10%/−2.87%，
   而**逐单元 Δ 中位 = 0.0**、144 个单元中仅 **10 个改善 / 8 个恶化**、总成交只少 **14 笔**（5,256 → 5,242）。
   → 聚合层的移动来自**少数股票的横截面中位数位移**（Δ 范围 −5.03 ~ +2.37pp），不是系统性效应。
3. **涨跌停约束在这套装置里几乎不触发**：原因是大市值池 + "T+1 开盘价成交"的撮合方式，
   一字板开盘很少挡住成交；因此 v3 与 v2 的差别天然很小。
4. **配对口径同样不变**：v3 的逐窗配对差中位 **−2.73pp**（v2 为 −2.93pp），聚类 95% CI **[−5.26, −3.28]**，仍整段低于 0。

> ⚠️ 因此正确的表述是：**"修复涨跌停模拟后结论未变"**，而**不是**"涨跌停建模让策略变好了"。

## 3. 为什么 v3 与 v2 差别这么小（机制解释）

1. **成交被挡的条件很窄**：`open_fill_block_reason()` 只在**开盘价触及涨跌停边界**时判定不可成交；
   大市值股在 T+1 开盘一字板的概率本身很低。
2. **ma_cross 的交易频率低**：中位 **2 笔/窗口**（75 个交易日），样本里能被挡的机会本来就少。
3. **只影响"那一笔"**：被挡后引擎不顺延补单（与 SP-5 侧的 `DEFER` 逻辑不同），因此后续持仓结构变化有限。

> 这条同时说明：**涨跌停不是这条策略的致命问题**——真正的问题在别处（见 P0-4 的成交笔数与相对损失单调关系）。

## 4. v3 自身的已知简化（必须随数字声明）

来源：`data/step75/research.py` 注释（B18 / D2 修复说明）

1. **创业板 2020-08-24 前实际为 10%，模型统一按 20%** → 早期创业板标的判定偏松（更少被拦），
   方向上**高估**其可成交性；
2. `MarketRules` 是静态配置，**引擎不支持按日期切换比例**；
3. 不模拟排队、部分成交、盘中开板、ST 5% 档（池已剔除 ST）。

## 5. 与 v2 的可比性边界

| 项 | 是否可比 | 说明 |
|---|---|---|
| 收益/亏损窗/成交/费用 | **可比** | 同池同窗同费率，唯一差异是涨跌停开关 |
| 与 `b50_v3` 目录 | **不可比** | 那是 96 条单费率试跑，且早于本次修复（见 P0-1 §4） |
| 与 `design_version` 字段 | **不可比** | 该字段被硬编码为 `oos75-v3`，v2/v3 都会写成同一个值；**必须看 `price_limit_mode`** |
