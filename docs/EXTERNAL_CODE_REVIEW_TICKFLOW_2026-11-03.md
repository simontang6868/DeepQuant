## 2. 与我们的对照（哪些我们已有、哪些值得吸收）

**我们已经做了、属于交叉验证（不必改）**：
- 涨停不可买 / 跌停不可卖 / 无下一根 bar → 我们 `fill_engine` 位图，实测 buy 失败 1,375 笔（含 FAIL_LIMIT_UP 149）、sell 失败 2,228 笔（FAIL_LIMIT_DOWN 256）；
- 原始价落盘 + 读取时投影复权 → 我们 `exec_all` + 自算 ADJ，且我们更进一步（他们免费档**没有复权因子**，我们自算 `f_s`）；
- 成本拆分（佣金双边 / 印花仅卖 / 过户双边）→ 我们 `cost_of()` 等价单边 0.051%；
- 进程资源上限 → 我们 `MemoryMax=1200M` + 峰值内存 CSV。

**值得吸收的两条（本轮不实施，登记为候选）**：
1. **「静默降级」检查**（他们最贵的一课）：`except Exception → 空表` 让用户看到「今天没有符合条件的票」而非「程序坏了」。我已自查：我们执行层/broker **仅 1 处** `except Exception`，无「异常→空表」兜底；`p13_forward.py` 8 处多数是「返回 None + 写明原因」的失败关闭。**结论：我们形态正确，无需改造**（此项作为一次已验证的对照，不产生代码变更）。
2. **成交时点口径的敏感性**：他们默认 `open_t+1`（次日开盘），我们 sp4 用「次月首个交易日**收盘价**」。用收盘价隐含「能按收盘价成交」的假设，方向偏乐观。**处理**：申报材料须明确披露该口径；「收盘价 vs 次日开盘」的敏感性对比属**新实验**（须新预登记），排在 11-30 与 G1/G2 之后，不得临时加跑。

**不采用**：其数据源强绑 TickFlow（免费档仅日 K、无复权因子）；其回测为单标的规则型 + 多标的等权，**表达不了我们的横截面 top5**；其 LLM 同进程 exec 是反面教材（我们明确不做 LLM 生成策略，保持）。
