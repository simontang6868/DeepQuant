# P2-1 财报 PIT 验证结论（阶段 2 · P2-1）

> 生效日期：2026-10-20 ｜ 阶段：数据体系修复（路线图 §6 · P2-1）
> 性质：**验证，不改数据**。回答一个问题：财报"最新公告日期"是否等于首次披露日？
> 派生约束（C3 / 路线图 §8）：**这项不过，不做质量/价值/盈利因子**（阶段 4.3 前置）。
> 复现：`python scripts/p2_1_financial_pit_check.py --limit 20` → `docs/P2_1_FINANCIAL_PIT_2026-10-20.json`

---

## 1. 一句话结论

> **不通过（FAIL）。** 常用接口（akshare `stock_yjbb_em`）暴露的「最新公告日期」实为**记录更新日 `UPDATE_DATE`**，
> 与真实首次披露日 `NOTICE_DATE` **160 对里 0 对相等**，系统性晚 **333~733 天（中位 366 天）**。
> **但原始字段 `NOTICE_DATE` 可用**——160/160 落在法定披露窗口内。
> → 做 PIT 必须用 `NOTICE_DATE`，**禁止**用 akshare 的「最新公告日期」。

---

## 2. 方法（20 只 × 8 期 = 160 对）

- 样本：主池前 20 只（`data/pool_manifest.json`），报告期 2022-12 ~ 2024-09 共 8 期。
- 数据：直连东财 `RPT_LICO_FN_CPD`，取每对 `(股票, 期)` 的两个字段：
  - `NOTICE_DATE`：公告日（真实披露）；
  - `UPDATE_DATE`：记录最后更新日（akshare 把它映射成"最新公告日期"）。
- 判据：
  - `NOTICE_DATE ≤ 法定截止`（年报次年 4/30；一季报 4/30；半年报 8/31；三季报 10/31）→ 验证它=首次披露；
  - `UPDATE_DATE == NOTICE_DATE` 的比例 → 验证 akshare 字段能否作 PIT。

## 3. 结果

| 指标 | 值 |
|---|---|
| 样本对 | **160**（20 只 × 8 期） |
| `NOTICE_DATE` 落在法定窗口内 | **160 / 160 = 100.0%** ✅ |
| `UPDATE_DATE == NOTICE_DATE` | **0 / 160 = 0.0%** ❌ |
| `UPDATE_DATE` 落在法定窗口内 | **0 / 160 = 0.0%** ❌ |
| `UPDATE_DATE − NOTICE_DATE`（天） | min **333** / p50 **366** / mean **375.5** / max **733** |
| 判定 | **`FAIL_as_exposed__USE_NOTICE_DATE`** |

### 单只样例（2024 年报）

| 股票 | NOTICE_DATE（真实） | UPDATE_DATE（akshare 字段） | 差 |
|---|---|---|---:|
| 平安银行 000001 | 2025-03-15 | 2026-03-21 | +371 天 |
| 中国平安 601318 | 2025-03-20 | 2026-03-27 | +372 天 |
| 招商银行 600036 | 2025-03-26 | 2026-03-28 | +367 天 |
| 贵州茅台 600519 | 2025-04-03 | 2026-04-17 | +379 天 |
| 五粮液 000858 | 2025-04-26 | 2026-04-30 | +369 天 |

**解读**：`UPDATE_DATE` 是"这条记录最后一次被刷新"的时间（下一期报告披露时被顶上来），
所以它天然晚**一个报告周期（约一年）**。拿它做 PIT = 用 2026 年的信息去算 2024 年的因子 = 彻底前视。

## 4. 根因

`akshare.stock_yjbb_em` 的列映射把东财原始字段 **`UPDATE_DATE`** 当成了「最新公告日期」。
东财原始响应里其实同时有 `NOTICE_DATE`（公告日）与 `UPDATE_DATE`（更新日），**真正该用前者**。
这不是"东财数据错"，是**调用层的字段选错**（akshare 映射问题）。

## 5. 对阶段 4.3 的硬约束（写死）

1. **质量 / 价值 / 盈利预期因子**：财报时点必须用 `NOTICE_DATE`（或 Tushare `ann_date`、巨潮公告日），
   **禁止**用 akshare `stock_yjbb_em` 的「最新公告日期」。
2. **回测的"财报可用日"**：取 `NOTICE_DATE`，不得取 `UPDATE_DATE`；若某数据源只给"最新更新日"，一律视为不可用。
3. **交叉核对**：新接入的财报源，必须先跑本脚本同款抽验（≥20 只 × ≥8 期），
   `NOTICE_DATE 落在法定窗口 ≥90%` 且能区分 `NOTICE_DATE` 与 `UPDATE_DATE`，才允许用于因子。
4. **报告期对齐**：财报 PIT 的"生效日" = `NOTICE_DATE`（盘后披露则次日生效），不得用报告期末 `REPORTDATE`。

## 6. 局限

- 只测了东财 `RPT_LICO_FN_CPD` 一条链路（含 akshare 封装）。Tushare/巨潮/CSMAR 的字段语义**未实测**，
  接入时须各自复跑本抽验。
- 样本为 20 只大盘股（主池）；小盘/北交所的披露节奏可能不同（但本次 100% 落在窗口内，大盘股很稳）。

## 7. 结论对路线图的影响

- **P2-1 判定：不通过**（对 akshare 字段）→ 按 C3，**阶段 4.3 的横截面因子仍不得开跑**（直到所有财源都验过 `NOTICE_DATE`）。
- **但 blocker 变轻了**：问题不是"财报没有 PIT"，而是"某个接口的字段选错"。**用正确字段即可**。
  → 阶段 4.3 的前置条件从"必须采购 PIT 财报"降级为"**用 `NOTICE_DATE` + 抽验通过**"。
