## 1. 研究对象与待估计量

- **一句话问题**：gm-paper 通道能否在**受控、最小、可回滚**的真实委托上，产出可被 `sim_reconcile.py` 消费的成交回报，并确认状态码语义与 5 元最低佣金事实？
- **预期用途**：只验执行链路与数据契约，为「仿真执行门」提供字段级依据。**不得**用于判断策略能否赚钱、不得进样本外证据。
- **样本／时点**：2 只标的 × 各 1 手，T 日买入、T+1 交易日卖出；**必须**在 2026-11-30 前完成并回到空仓（R8 §5）。若授权到达时已来不及 ⇒ 不执行，不挤到 11-30 之后。
- **as-of 截断**：只用授权时点已就位的行情与台账；不回溯补数据。
- **基线／主指标**：基线＝**零委托**（现状 `cum_trade=0` / `nav=100000`）；主指标＝「零未授权／重复／错误订单」的**计数**（不是收益率）。
- **辅助诊断**：回报字段名与取值域、`exec_type`↔本地 `status` 映射、单笔佣金（元）、对账器判定。
- ⭐ **MDE：`MDE_NOT_ESTIMABLE`**。n=2 笔委托、单窗口工程验证、无收益率序列 ⇒ 不做统计推断、不报 se／t／p、不借用别的信号 MDE。

## 3. 成功标准与不做清单

**通过标准（R8 原文，逐字落地，四条全满足才 PASS）**：

| # | 判据 | 可算量 |
| --- | --- | --- |
| P1 | **零未授权／重复／错误订单** | `n_unauthorized=0`、`n_duplicate=0`、`n_wrong=0`（计数） |
| P2 | **状态码语义确认** | 真实回报 `exec_type` 与本地 `status` 逐值映射表**完整且无歧义**；未识别值 ⇒ `HALT:UNKNOWN_STATUS`（不猜） |
| P3 | **佣金实测** | 每笔回报里佣金字段可解析、单位明确（元）；与「5 元最低」事实**一致或明确不一致**（两种结果都如实报，不预设答案） |
| P4 | **对账器 PASS** | `sim_reconcile.reconcile()` 对真实回报返回 `PASS`；空输入 ⇒ `NO_INPUTS` 停机，不得当「无差异」 |

**失败/异常留痕**：任一不满足 ⇒ 保留原始产物 + 出更正，**原文不改写**；停机后不得重试、不得降级、不得手工补单。

**明确不做**：不评估收益／净值／夏普；不写正式 `forward/ledger/` 台账；不计 G1/G2/S4；不改策略参数；不新增因子；不启动实盘；不合并两机；不代用户创建/修改授权文件；不把探针授权当 U-16；不把 `--execute` 打开。

## 4. 预期方向 + 机制 + 结构假设（落在可算量上）

| # | 可算预测 | 机制 | ⭐ 结构假设（锚未验证＝模板不是定律） |
| --- | --- | --- | --- |
| Q1 | 每次真实委托前调用 `paper_authorization_guard.check` 的次数 = 委托笔数；`DENY` 时委托笔数 = 0 | 守卫是**唯一**放行闸门，调用点在所有下单路径之前 | 假设适配器只有一条下单路径；若将来新增旁路，此式失效 ⇒ 须新预登记 |
| Q2 | 同一 `(probe_id, symbol, side, day)` 重放 ⇒ `n_duplicate = 0`、实际委托笔数不增 | 幂等 `client_order_id` 由该四元组确定 | 假设 SDK 以 `cl_ord_id` 去重；**未**在真实 gm-paper 上验证过 ⇒ 探针目的之一 |
| Q3 | 回报字段集合 ⊇ `FIELD_MAP` 所需键；`n_missing_field = 0` | `--truth-probe` 已按 protobuf `DESCRIPTOR.fields` 读通 | 假设 ExecRpt 在**有成交**时字段与空查询结果同构；空查询返回 0 条时 `dir()` 探测不足以证明 ⇒ 探针目的之一 |
| Q4 | 单笔佣金 `fee ≥ 5.00`（元）当且仅当「5 元最低」对该账户生效 | 券商费率表 + 5 元下限 | 假设该仿真账户沿用券商默认费档；**实测前不得写成已知事实** |
| Q5 | 对账器对真实回报返回 `PASS` 而非 `NO_INPUTS` | 真实成交 ⇒ 回报非空 | 假设 T 日买入限价单能成交；若未成交 ⇒ `NO_INPUTS` 是**正确停机**，不是失败但也不算 P4 通过 ⇒ 须另立记录 |

⭐ **不得替规则添加它没有的性质**：R8 只说「2 只、每只 1 手、买入次日卖出」，**未**承诺「一定成交」「一定不亏」「佣金一定 ≥5 元」。本预登记不得把这些写成通过标准，也不得因未成交就放宽 P4。

### 4-A 符号与幅度约定（模板 v2 必填）

| 量 | 约定 |
| --- | --- |
| 所有计数量（P1、Q2） | **非负整数**，0 = 无事件；不使用有符号数、不取 `abs()` |
| 佣金 P3/Q4 | **正数金额（元，CNY）**，`fee ≥ 5.00` 比较的是**有符号正数**，不取绝对值 |
| 名义金额上限 | `notional ≤ BUDGET_PER_SYMBOL` 比较**正数金额**；`max_notional` 守卫口径另按 `paper_authorization_guard` 六项校验，二者单位一致（元） |
| 「回撤／收益」 | **本预登记不出现任何收益、回撤、pp/小数比较**；若执行后有人引用探针净值 ⇒ 违规 |
| 比较式 | 全部为计数等式或金额不等式；**无** `MDD` 类负值量，故不涉及 PA-OCT2026-1 的符号陷阱 |
| 单位 | 金额一律**元**（不是万元、不是 pp）；计数一律**笔/条** |
| 方向一致性自检（冻结前用已知值代入，不用被测函数） | 代入 `n_unauthorized=1` ⇒ P1 假（应 FAIL）；`fee=5.00` ⇒ `fee ≥ 5.00` 真；`fee=3.20` ⇒ 假 ⇒ 应如实报「不一致」，不得判 P3 失败也不得判「5 元下限成立」。手算确认方向符合直觉 ✔ |

## 5. 变异与闸门

- 变异必须在**实现之前**先设计、实现之后**先跑**；每条变异必须**真改行为**：`DENY→ALLOW`（六项校验各一条）、跳过守卫、幂等键改成随机数、放开市价/大单、打开 `--execute`。
- ⭐ 闸门**禁止调用被测函数**推导期望值：期望值来自产物或独立算术（`Fraction`／手写计数），不用 `check()` 自己算「应该 ALLOW 几条」。
- 每条变异的判定式：`原实现拒绝该动作` → `变异体放行/不拒绝` ⇒ **检出**；否则该变异是假变异，作废重做。
- 「文件不存在」≠「确认无事件」；空输入必须失败关闭（`NO_INPUTS`）。
- 容差：本单无浮点估计量；涉及金额一律 `Fraction`/`Decimal` 精确比较，**不设浮点容差**。
- 变异脚本原地改源码期间**禁止**任何其他 pytest／git 提交（串行）。
