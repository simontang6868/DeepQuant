## 一、先说清「模拟盘」在本项目里到底缺什么

本项目的 SHADOW 对账管道已于 2026-11-08 接入日更链（见
`docs/SHADOW_RECONCILE_WIRING_2026-11-08.md`），但 **G2 计数仍是 0 天**，
原因是缺一个**真实的「实际资金 / 实际持仓」来源**：

```
forward/account_snapshot.json   ← 需要模拟盘提供（asof / cash / positions / source）
        ↓
SHADOW 比对「台账目标」与「本应下的单」
        ↓
连续 20 个交易日无未解释差异 ⇒ G2
```

所以选型的硬需求只有四条，与"界面好不好看"无关：

| # | 需求 | 原因 |
| --- | --- | --- |
| 1 | **能用 API 读到 cash / positions** | 这是 `AccountSnapshot` 的唯一输入；只有手动界面、导不出来的不行 |
| 2 | 沪深 A 股、含主板 | d4 严格口径；美股/港股平台不对口径 |
| 3 | 能在 **Linux 云主机**上跑 | 日更链在 TencentOS 4，Windows 专用客户端会被排除 |
| 4 | 免费（或长期免费额度） | 当前只是攒证据阶段，不为此付费 |

**不需要**的：真实资金、真实券商柜台、极低延迟（本策略月频、单日 ≤12 笔）。

⚠️ 两个容易混淆：
- 「回测 / 平台内模拟交易」≠ 「有独立账户 API」。聚宽这类策略跑在平台里，
  本机拿不到 `get_positions()`，对账管道就接不上。
- 「券商模拟账户」≠ 「实盘授权」。它仍属仿真，不改变 `LIVE_ENABLED=false`，
  也不构成 U-12 的完成。

## 二、候选（按与本项目契合度排序）

| 优先 | 方案 | 免费口径 | 能否读到 cash/positions | Linux 云主机 | 关键限制 |
| --- | --- | --- | --- | --- | --- |
| **① 首选** | **掘金量化·仿真交易**（`sim.myquant.cn`，`gmtrade` Python SDK） | 官网称仿真子系统已作为**独立线上服务免费向用户开放** | ✅ `get_cash()` / `get_positions()`，SDK 另有 `order_volume()` | ✅ 连 `api.myquant.cn:9000` 的纯 Python SDK（**Linux 兼容性未实测**） | 需注册取 token、申请仿真账户 ID；终端 GUI 是 Windows，但线上服务不需要它 |
| ② 次选 | **聚宽 JoinQuant** 模拟交易 | 基础回测 + 模拟交易长期免费；每日回测时长/数据额度受限 | ⚠️ 策略在平台内运行，**本机无独立账户 API** | 不适用（云端平台） | 适合做**独立对照**，不适合直接喂 SHADOW 对账管道 |
| ③ 本地兜底 | **VeighNa `vnpy_paperaccount`**（MIT 开源） | 完全免费、永久 | ✅ 本地 PaperAccount 有虚拟资金/持仓 | ✅ 纯 Python | 生态以期货 CTP 为主，**A 股股票 gateway 弱**；需自行接行情；撮合规则与交易所不同 |
| ④ 最终通道 | **QMT / miniQMT 券商模拟账号**（`xtquant` / `xttrader`） | 软件本身免费、多数券商提供免费模拟号 | ✅ 模拟柜台可查资金持仓 | ❌ 客户端是 Windows | 需券商开户、C4 风测、6 个月经验；正式权限常见 20 日日均资产 ≥10 万。**与 U-12 是同一条路** |
| ⑤ 参考 | **米筐 RiceQuant** | 基础版免费，本地 SDK / 实盘对接需付费 | ⚠️ 同平台内模拟 | 不适用 | 与聚宽同类受限 |
| — | 不考虑 | Alpaca paper trading（美股）、SimNow（期货 CTP）、Tushare/AKShare（只有数据无账户） | — | — | 市场/品种不对，或纯数据源 |

**为什么不推荐直接用 ④**：它要求券商开户与适当性审核，正是 U-12 待你处理的事，
时间不可控；而 ① 是独立线上仿真服务，能立刻补上"缺账户快照"这一环，
且将来换到 QMT 时，`account_snapshot.json` 的契约不变，只需换适配器。

## 三、若选 ①，接入路径（**现在不做**）

1. 你自行注册 `sim.myquant.cn`、取 token、申请一个仿真账户 ID（我不代注册、不代开户、不索取凭证）。
2. 在云主机隔离目录装 `gmtrade`（不进 `/opt/quant/.venv`，不复用 `/opt/quant/env`，与既有两套任务隔离）。
3. 写一个**只读适配器**：每个交易日收盘后调用 `get_cash()` / `get_positions()`，
   落成 `forward/account_snapshot.json`：
   ```json
   {
     "asof": "YYYYMMDD",
     "source": "gm-paper",
     "cash": {"available": 12345.67, "frozen": 0.0, "total": 12345.67},
     "positions": [{"code": "600990", "quantity": 700, "available": 700, "avg_cost": 5.41}]
   }
   ```
   `asof` 必须等于当日交易日；陈旧快照会被 `shadow_daily_reconcile.py` 拒绝（变异 M2 守着）。
4. 适配器只读，**不调用任何 `order_*` 下单函数**；是否允许向仿真账户报单，须你另行书面确认。
5. 从第一个 `REAL_PAPER` 日起，G2 的 20 个交易日才开始累计；可用
   `python scripts/shadow_daily_reconcile.py --summary` 随时查看连续段。

⚠️ **佣金口径**：本项目实盘成本被「5 元最低佣金」主导（见
`docs/BROKER_STATEMENT_CALIBRATION_2026-11-03.md`）。掘金仿真官网称股票佣金/印花税/过户费
**可设定**，但**能否设置「每笔不足 5 元按 5 元」未核实**。若不能，仿真净值会系统性偏乐观，
必须在报告里标注「仿真费率与真实券商不一致，不得用于经济性判定」。
