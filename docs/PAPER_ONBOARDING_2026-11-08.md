## 一、为什么我替不了你注册（该步已由用户本人完成）

按掘金官方《5 分钟上手指引》与 Python SDK 文档，接入需要先：

1. 在 `https://www.myquant.cn` **注册一个用户**（官网首页右上角「新用户注册」）；
2. 登录仿真服务 → 「交易」页 → **新建账户** → 选「股票」→ 设置初始资金；
3. 在「个人中心 → 安全设置」**生成 token**（官方原文：token「相当于您的用户 ID+密码」）；
4. 复制**账户 ID**（`account_id`）。

这四步都以你的身份在第三方网站完成，涉及账号归属、服务条款同意、以及
token 这种等同密码的凭证。**我不会代注册、不会代你同意条款、不索取你的
账号密码**；官方文档没有写明注册需要哪种验证方式，所以也不该由我臆测。

## 五、⭐ 三条必须知道的局限（别把接入当成"验证通过"）

1. **G2 判据目前不校验实际成交**。`compare_with_ledger` 比的是
   「台账目标」与「规划器算出的买单」，账户快照只用来决定买多少股。
   所以接入仿真账户能让 G2 开始计数，但它衡量的是**规划器一致性**，
   **不是「实际持仓与目标吻合」**。要真正验证执行，必须允许向仿真账户报单——
   那是另一次明确授权，且需要重新评估时点与成本口径。**本文不含该授权。**
2. **时点**：掘金沪深账户 **18:00 结算**，本链路 17:10 取快照，属「收盘后、结算前」。
   当前不报单、没有当日未结委托，故自洽；将来一旦允许报单，必须重评时点。
3. **费率**：官网称手续费可按账户自定义，但**能否设「每笔不足 5 元按 5 元」未核实**。
   本项目实盘成本正被 5 元下限主导，若仿真不含它，仿真净值会系统性偏乐观，
   **不得用于经济性判定**。

Linux 版 `gmtrade`、真实登录、字段返回、账户资金均已于 2026-11-08 实测（见 §六）。
仍未实测：**真实下单与成交**（本次不授权）、费率里的 5 元最低佣金、
账户 3 个月无交易会被置为「未激活」（官网说明）。

**2026-11-08 12:50 复核官网《5分钟上手指引》原文后的三点精确化**（见 `reports/STAGE_SUMMARY_2026-11-08.docx` §四/§五）：
- 原文为「账户超过 `3` 个月没有交易时，会被设置为『未激活』状态，不能交易；重新交易需要手工『激活』账户」。**原文只说不能交易，未说明是否影响只读查询**；当前链路只查资金/持仓，故**不得断言会导致快照失败或 G2 断链**。若将来授权报单，须在约 2027-02 前确认并按需手工激活。
- 官网「交易规则说明」原文：**「仿真撮合无法模拟交易冲击成本，可能会导致较大笔委托的成交价格优于实际价格」**⇒ 仿真成交价天然偏乐观，新增为经济性局限。
- 官网 API 一览列 `get_position()`（单数），实测 `gmtrade 3.0.6` 只有 `get_positions()`（复数）；适配器已兼容两者。**文档不能当实现**。
- 手续费原文只写「股票的佣金/印花税/过户费，支持按设定的费率收取」，**未提 5 元最低佣金** ⇒ 该项仍为「未核实」。
