# 组合回测与「不可用标的可见」（2026-10-18）

上一版（`docs/PRODUCT_READY_2026-10-18.md` §9.5）列了四条「仍不解决」。
本文处理其中的**两条**，并把另外两条改成「可以核对的事实」而不是「口头免责」，
最后一条（Gate 1 `--execute`）仍然不动。

| 上一版遗留 | 本轮 | 说明 |
|---|---|---|
| 只能单标的回测 | ✅ **已解决** | 新增 `POST /portfolio-backtests` 与「组合回测」页 |
| 界面里没有 600809，无法理解为何缺失 | ✅ **已解决（改为可见）** | `/datasets` 新增 `unavailable_datasets`，带名称与原因码 |
| 区间只到 2024-12-31 | ⚠️ **不能解决，但已证实并声明** | 50 个原始 CSV **全部**止于 2024-12-31（数据源上限） |
| 池是 2026-10 快照（幸存者偏差） | ⚠️ **不能解决，但已声明** | 没有历史成分股数据；`/datasets` 与组合结果都写入声明 |
| Gate 1 `--execute` 未调用 | 🔒 **不动** | 硬闸门，需用户单独授权 |

「不能解决」不等于「可以不说」。这一轮的策略是：能修的修掉，修不掉的变成
**接口里可核对的字段**，而不是文档里的免责声明——文档没人读，界面上的字会被读到。

---

## 1. 组合回测：为什么必须新写一层，而不是「把单标的跑 N 遍」

`POST /backtests` 是「单标的、单持仓、单现金」模型。把它套在循环里跑 N 只，
得到的是 **N 个独立账户**，不是组合：

- 现金不能互相调济：账户 A 有钱、账户 B 想买，组合里这是同一笔钱；
- 无法表达「卖出 A 换 B」：两个独立账户的调仓在时间上无关联；
- 没有一条连续净值：N 条曲线加起来不是组合净值（除非权重恒定，那已经不是调仓）。

`backtest/portfolio.py` 早就实现了正确的记账循环（共享现金池、卖出先于买入、
停牌冻结估值、涨跌停顺延），`backtest/cross_section.py` 实现了截面动量取分，
`month_end_signal_dates` 实现了月末信号。缺的只是**接线**与界面。

`api/portfolio.py` 因此只做接线，不含任何撮合逻辑：

```
读数据集（同一道 validate_daily 闸门）
  → 日历 = 各标的日期并集（限请求区间）
  → 信号日 = month_end_signal_dates(calendar)
  → 分数 = CrossSectionPanel(...).scores_by_date(信号日)
  → 目标权重 = build_rebalance_schedule(...)
  → run_portfolio_backtest(...)
  → 序列化
```

**没有第二套规则**。改这一层不会改变撮合结果；要改撮合必须改 `portfolio.py`，
那条路径由 `docs/A3_ACCOUNTING_SPEC.md` 与既有 400+ 条 backtest 测试守着。

## 2. 口径：默认值就是 Gate 1 主实验

界面不提供「随便调」的旋钮，默认值直接取预登记口径：

| 参数 | 默认 | 出处 |
|---|---|---|
| 调仓频率 | 月末最后一个交易日 | `month_end_signal_dates` |
| 信号 → 成交 | T 日收盘信号，T+1 开盘 | 与 `engine.py` 一致 |
| 动量窗口 | `lookback=60`, `skip=5` | 预登记 §3~§4 |
| 选股 | 等权取前 `top_fraction=0.2` | 预登记 §5 |
| `min_assets` | 5（不足则当期空仓） | 预登记 §5 |
| 初始资金 | 1,000,000 | 附录 B |
| 涨跌停 | **flat 10%** | 附录 C（组合层单一标量，无 per-symbol 通道） |
| 记账 | `allocation=weights`（不受整手约束） | B18 Q3(a) 主口径 |

改任何一个，响应 `limitations` 会显式记下偏差。例如把 `min_assets` 降到 2：

> `min_assets=2 低于预登记 §5 的 5：候选不足时不再空仓，本期结论与研究报告口径不同`

## 3. 一个容易做错的地方：池子凑不满 `min_assets`

如果只选 3 只、`min_assets` 保持 5，每个调仓日都「凑不满可排序标的」→ 每期空仓
→ 净值是一条水平线，`fills=0`。这在数据上完全合法（空仓是合法状态），
但用户看到的是「跑成功了，但什么都没买」。

上一版已经因为同类问题栽过一次（10 万本金 + 茅台 → 60 笔全拒）。

处理：**在参数校验阶段 422 拒绝**，并说明原因。

```
min_assets=5 大于标的数 3：每期都凑不满可排序标的，整段回测会全程空仓。
请多选标的，或把 min_assets 降到不超过标的数。
```

前端 `utils/portfolioPayload.ts` 用同一口径先拦一遍（不发出注定 422 的请求），
但**后端仍然独立校验**——前端不是守门员。

## 4. 顺手修掉的一个真 bug：浮点边界让自检误报

写测试时 3 只等权（`equal_weight_all`）稳定失败：

```
RuntimeError: 组合回测内部一致性检查失败：
['2022-03-09 权益 1095910.44 != 现金+市值 1095910.45']
```

**账是对的**。`PortfolioState.total_equity` 存的是 `round_money(cash + market_value)`，
与未舍入的和最多差 0.005（合法舍入）。但差分恰好是 0.01 时，二进制表示是
`0.010000000009313226`，旧实现的 `abs(diff) > MONEY_EPS`（0.01）把它判成不一致。

实测这个案例里 **59 个交易日全部命中**，整次回测直接抛异常。它不是「只在测试里出现」
——真实的 51 只等权跑一次也可能踩上，取决于舍入恰好落在哪。

修法（`portfolio.py`）：新增 `ACCOUNTING_TOLERANCE = MONEY_EPS + 1e-9`，
自检三处改用它。1e-9 远小于一分钱，不会掩盖真实错账。

回归测试 `tests/backtest/test_portfolio_consistency_tolerance.py` 锁四条：

1. 容差必须严格大于 `MONEY_EPS` 且余量 < 1e-6（不许靠放大容差换「不报错」）；
2. 恰差一分（真实故障数值）→ 不报；
3. 差两分 → **仍然报**；
4. 成交额与「价×量」不符 → 仍然报。

## 5. 「为什么界面里没有 600809」：把缺失变成可见

被数据闸门拒绝的标的**从未入库**，所以它既不在 `datasets` 里、也不在
`invalid_datasets`（那个是「元数据已存在但坏了」）里——界面上就是凭空少一只。

`GET /datasets` 新增：

```json
"unavailable_datasets": [
  {"symbol": "000568.SZ", "display_name": "泸州老窖", "reason": "invalid_price(1)",   "checked_at": "..."},
  {"symbol": "600809.SH", "display_name": "山西汾酒", "reason": "invalid_price(131)", "checked_at": "..."}
]
```

四条边界（缺一条这个字段就会开始骗人）：

1. 只读 `data_root/pool_manifest.json`，不读仓库外路径、不联网；
2. 只取 `status=rejected` 且**当前仓库确实没有**该代码的（后来补上了就以仓库为准）；
3. `reason` 是**导入时**的判定，字段名与文案都按此表述，不冒充实时校验；
4. 它只是解释性信息，**不能**用来发起回测（回测仍返回 404）。

界面上它单独列在标的池下方，附一句「数据不修就直接用，会得到一份与研究报告
不对应的行情，所以宁可导入失败也不修价」。

### 与 Gate 1「排除对照」的关系（说清楚，不美化）

Gate 1 有一条对照实验是「把 600809 从池里排除，看结论是否翻转」。在界面上：

- **做不到「包含」版本**：600809 的数据本身就是负价，闸门拒绝；
- **界面里的 51 只已经等于「排除 600809 与 000568」的池**。

所以那条对照在软件里无法复现，原因不是缺功能，而是**缺干净的数据**。
这一点比「界面没有 600809」更准确，写在这里以免下次又当成 bug 查一遍。

## 6. 数据覆盖：为什么区间停在 2024-12-31

不是接口截断，也不是软件限制。实测 50 个原始文件：

```
$ for f in b50_v3/*.qfq.csv; do tail -1 "$f" | cut -d, -f1; done | sort | uniq -c
     50 2024-12-31
```

`/datasets` 因此新增 `coverage`：

```json
"coverage": {
  "start_date": "2017-01-03",
  "end_date": "2024-12-31",
  "n_datasets": 51,
  "n_unavailable": 2,
  "note": "51 个数据集覆盖 2017-01-03 ~ 2024-12-31；全部数据集都止于 2024-12-31：
           回测区间无法超过数据覆盖终点；标的池来自导入清单 b50_v3（清单登记 50 只）；
           2 只标的在导入时被数据闸门拒绝，见 unavailable_datasets；
           若标的池是「当前成分股」快照，回看历史存在幸存者偏差；
           软件没有历史成分股数据，无法修正这一偏差"
}
```

组合结果里也有 `coverage.note`，并且逐标的给出 `symbol_end_dates`——
区间被截断时能看出是「全部止于同一天」还是「各标的不一致，尾部只有部分数据」。

**幸存者偏差没有解决**：池是 2026-10 的成分股快照，回看 2017 年时，当年退市/
被剔除的公司不在池里。软件没有历史成分股数据，做不出「时点成分股」。
能做的是不让这些数字被误读成「当年能赚多少」——所以它出现在 `/datasets`、
出现在组合结果的第一个 banner、也出现在 `limitations` 里。

## 7. 实测结果（真实实例 `http://127.0.0.1:8123`）

51 只池 × 2019-01-02 ~ 2024-12-31（1456 个交易日），初始 100 万：

| 口径 | 累计 | 年化 | 最大回撤 | 夏普 | 换手(单边/年) | 成交 | 被阻挡 |
|---|---|---|---|---|---|---|---|
| 动量 top20%（正式口径） | **+168.76%** | 18.66% | 45.72% | 0.74 | 5.34 | 938 | 47 |
| 全池等权（不筛选） | **+207.55%** | 21.46% | 21.49% | — | — | 3132 | 164 |
| 动量 top20% + 整手记账 | **+165.52%** | 18.41% | 45.06% | — | — | 912 | 74 |

耗时：51 只 **约 5 秒**（含数据载入与截面取分），响应约 460 KB / 900 KB（等权）。

`consistency_issues` 在三种口径下都是 **0 条**（权益恒等式、现金非负、成交额自洽）。

**怎么读这三个数**（重要）：

- 等权（+207%）跑赢动量（+168%），说明在这 51 只快照上「选股」没有加分，
  反而放大了回撤（45.7% vs 21.5%）。这不是「等权更好」的结论，
  而是「这个池子 + 这个区间下，动量筛选没有产生价值」——两者的差别本身是信息；
- 动量口径 45.7% 的回撤、5.34 倍年化换手，配合「成本占毛收益 4.2%」，
  说明这条曲线的收益大部分不是靠高换手撑起来的（这条检查正是为了排除
  「靠频繁再平衡制造的错觉」）；
- 证据等级 `low`：51 只 < 100，系统自己判定「截面分散化不足、单只极端值影响过大」。
  **这不是可以忽略的提示**，它意味着上面三个数字都不该被当成策略结论。

被阻挡订单的分布（正式口径，47 笔）：
`跌停顺延 21 / 资金不足 11 / 跌停 6 / 涨停放弃 5 / 无有效价格 4`。

## 9. 这一版仍然不解决的

1. **幸存者偏差**：池是 2026-10 快照，无历史成分股数据 → 只能声明，不能修；
2. **区间上限 2024-12-31**：数据源限制，要更长区间得重新取数（`import_pool.py`
   的 sha256 校验会拦住「换了一版行情但没记录」）；
3. **组合结果不写历史记录**：`/backtests` 的历史库是单标的 schema，组合结果没有
   对应表。界面上明确写了「需要留存请自行截图或导出」——不假装存了；
4. **单标的与组合的口径不完全对称**：单标的是 flat 10% + 整手；组合默认权重记账。
   两者不是同一个问题，别拿两边的收益率直接比较；
5. **Gate 1 `--execute` 仍未调用**，`gate1_out/` 不存在。
