> 定位：这是一次**口径复核**，不是新假设、不是新闸门、不产生任何放行结论。
> 预登记：`docs/gates/l3q_prereg.json`（sha256 `176cd8c3b1d4661194fa9b1f32d2487436a60a7b4114efc247b4d0e665f86857`，
> 脚本启动时校验，被改动即拒绝运行）。
> 产物：`reports/gates/H-L3Q-CASH-AUDIT/{l3q_audit.json,l3q_audit.md}`、
> `reports/L3Q_CASH_AUDIT_EVIDENCE.json`。

## 1. 为什么要有这次审计

L3p 报告里对现金只有一句：

```
avg_cash_ratio_median = 11.71%
```

然后它被当成「稀释程度」的代理，用于解释对照臂的 `per_invested_excess_mean = −7.87pp`
（"折算掉现金拖累后，选择没有正贡献"）。

问题在于同一个数字至少混了六种机制，处置方式互不相同：

| 分量 | 含义 | 该怎么办 |
|---|---|---|
| `cap` | 目标权重和 < 1（单标的上限压住等权） | 调模型参数 |
| `rounding` | 折算股数后的取整残差 | 资金门槛 / 股价 |
| `dead` | 行情已终止的标的仍被记为持有 | **修状态重建**（数据缺陷） |
| `not_listed` | 信号日早于该标的行情起点 | 修标的池（时点成分） |
| `suspended` | 当日停牌 | 现实约束，无法避免 |
| `insufficient` | 先卖后买后资金仍不够（部分成交） | 现实约束 + 换手 |
| `fees` | 交易费用 | 成本口径 |

把「死票占权重」当成「主动留现金」，会让 `per_invested` 折算把**不可投的现金**
当成**可投而未投**，从而系统性地改写"选择有没有用"的结论。所以在引用 11.71%
之前，必须先把它拆开。

## 2. 审计问题（六条可算量预测，跑前冻结）

见 `l3q_prereg.json` 的 `predictions`。摘要：

| 编号 | 预测 |
|---|---|
| P1 | 整手增量中位 < 0.5pp、最大 < 2pp |
| P2 | 权重上限触发期 < 10%、中位贡献 < 1pp |
| P3 | 死票权重与现金占比 Spearman > 0.7；末折比首折高 5pp 以上 |
| P4 | 对照臂现金中位 > 8pp，其中未上市 + 数据终止占 > 70% |

方向性不计。其余五条的量级未在冻结前观察。

## 3. 口径（全部正确性压在一条恒等式上）

调仓日 `t`，`q_pre` 为调仓前持仓、`px` 为执行参考价：

```
cash_after = cash_before + Σ卖出gross − Σ买入gross − fees
           = equity_open − MV_after − fees
           = equity_open × (1 − Σw)                       ← 结构缺口 cap
             + Σ_s (equity_open×w_s − realized_s)         ← 逐标的缺口
             − fees
```

其中 `realized_s = q_pre,s × px_s + 买入gross_s − 卖出gross_s`。**缺口必须按资金流算，
不能按"市值差"算**：引擎的成交价会先按最小变动单位取整（`execution_price` 即使零滑点
也走 `apply_slippage`），用未取整开盘价算市值会凭空多出几百元缺口（首版实测折 1 的
残差 4,605.61 元就是这么来的）。

逐标的缺口按「为什么没买够」分类：无开盘价 → `classify_unpriced` 三分（dead /
not_listed / suspended）；有价但缺口 > 一个交易单位且无拒单记录 → `insufficient`
（引擎用 `min(want, affordable)` 部分成交，不记拒单）；缺口 ≤ 一个单位 → `rounding`；
缺口为负（卖不出导致超配）→ `overweight`。

两个残差，都超容差就抛错、不出数：

- `residual_identity = cash_after − Σ分量`（容差 1 分）：不为 0 说明分解漏了标的或分量。
- `residual_ledger = 资金流现金 − 成交回放现金`（容差 50 分）：不为 0 说明本模块对
  执行价/权益的理解与引擎不同。

逐日分摊：分量取最近一次调仓日的**实测值原样保留**，区间内现金变动（顺延卖出回款）
单独计入 `other`，首个建仓日之前单列 `prestart`。这样「分量 × 天数」逐日等于
`cash/equity`，可加性不被分摊方式破坏。

## 4. 五个臂

| 臂 | 口径 | 作用 |
|---|---|---|
| A | `weights` @ 1000 万 | 基线；必须逐折复现 L3p 存档的 `avg_cash_ratio`（容差 1e-12） |
| B | `lots` @ 1000 万 | 同调度同资金，唯一差别是整手粒度；B−A = 整手增量 |
| C | `weights` @ 1000 万，`control_schedule`（30 只等权） | 区分「池子本身不可交易」与「策略选到不可交易的票」 |
| D | `lots` @ 100 万 / 300 万 / 1000 万 / 3000 万 / 1 亿 | 整手增量随资金变化；**逐折配对**后取中位 |
| E | `weights` @ 1000 万，剔除执行日无价持仓后归一（预登记口径） | 量化现金拖累吃掉多少折收益 |
| E2 | 同 E，但**只剔** `dead` / `not_listed`，保留停牌（**未预登记**，事后） | 只修数据缺陷，避免「复牌即卖」混进来 |

参数一律不重选：逐折直接读 `l3p_result.json` 存档的 `best_params`。重选参会把
「现金口径」换成「参数选择」问题，两者混淆后无法归因。

## 5. 验收标准

1. **可复现**：A 臂 28 折的 `avg_cash_ratio` 与 L3p 存档逐位一致（容差 1e-12），
   否则整个审计作废。
2. **可加性**：每折 `|Σ分量 − avg_cash_ratio| < 1e-12`。
3. **恒等式**：每折 `|residual_identity| < 0.01`、`|residual_ledger| < 0.5`，
   否则抛错。
4. **回放一致**：成交回放的逐日现金与引擎 `states[].cash` 逐日差 < 0.01。
5. **口径不混**：`component_median` 不可相加（不同折取中位的分量不在同一折），
   报告必须同时给可加的 `share_total` 与逐折 `components`。
6. **不越界**：不修改 L3p 终态、不修改回测引擎、不修改被测策略、不修改标的池冻结文件。

## 6. 明确不做的事

- **不修引擎**：审计中遇到 `total_equity` 与 `cash + market_value` 差 1 分钱的
  内部一致性守卫触发（2 个「折 × 资金」格），只记账不改代码——改引擎属于另一场实验。
- **不改 L3p 终态**：`L3P_BLOCKED_PREREQUISITE`（初判 `L3P_REJECTED_INCONSISTENT_FOLDS`）
  保持不变。即使发现现金里有一半是数据缺陷，也不据此宣布放行。
- **不把诊断臂当收益结论**：E / E2 修复的是数据缺陷，不是模型。若要把修好的口径
  升为主口径，必须另开预登记重跑 L3p（新实验，新哈希）。
- **不重做对照臂**：`per_invested` 折算的错配已经定性，但要给出"选择有没有用"的
  正确数字，需要一个「只在可成交标的上等权」的新对照臂——那属于新实验。

## 7. 结果落点（跑完之后的定稿）

实跑结果见 `reports/gates/H-L3Q-CASH-AUDIT/l3q_audit.md`。三条需要写进引用规范的结论：

1. **11.71% 不是「钱不够」**：整手约束的中位贡献只有 +0.15pp（1 亿时 +0.01pp，
   但 100 万时 +2.51pp，所以"整手无关"只对千万级以上成立）。
2. **主因是「买不进」**：停牌 37.8%、行情终止仍记为持有 35.0%、权重上限压仓 21.1%
   （合计口径）。逐折主因：停牌 11 折、行情终止 7 折、上限 5 折、折首空仓 4 折、
   资金不足 1 折。
3. **`per_invested_excess_mean = −7.87pp` 需要加限定**：策略臂现金的 69.2%、
   对照臂的 95.3% 来自不可成交标的，`1−cash` 不是「主动投出去的比例」而是「能投出去
   的比例」。该数字不能被读成「选择没有正贡献」。

六条预测中 P5、P6 被反驳（见报告第八节），照原样保留，不改判据、不重写预测。

## 8. 已知限制

- 现金占比是逐日 `cash/total_equity` 的均值，不是「平均未投资金额」。
- 归因是「调仓日缺口 → 逐日按实测值分摊」，不是逐笔因果推断。
- 组合层未启用涨跌停判据（`BacktestConfig` 默认 `price_limit=None`），所有数字
  **不含**涨停买不进的摩擦；真实摩擦只会更大。
- 整手敏感性只做 100 股一档；科创板 200 股起未单独建模。
- `suspended` 会把「长期停牌后摘牌」与「短期停牌」混在一起，两者对策略的含义不同。
- 本审计不解决标的池的生存偏差；死票（行情终止）与生存偏差是两个独立缺陷。
