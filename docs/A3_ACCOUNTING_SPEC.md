# A3 组合记账规格（B19 前置，口径先定稿再写代码）

> 这份文档的存在理由：组合回测的**结果差异大多来自口径，而不是策略**。
> 同一批信号，换一种「卖出先于买入」或「停牌怎么估值」的约定，净值曲线就会不同，
> 而两边都自称「跑了一次回测」。所以先把口径写死，代码只许照着实现。

## 0. 先说清楚：为什么不「直接调用 `run_backtest`」

B18 写的是「复用 `run_backtest` 与 `compute_fees`，不重写核心撮合」。这句话需要一次
**如实的技术澄清**，否则会变成一句自我欺骗：

`run_backtest` 的签名是「一份行情 + 一个策略 + 一份现金 → 一条账户曲线」，
内部维护**单一** `quantity` / `avg_cost`，且买入时 `already_holding` 直接拒绝加仓。
它没有「多标的持仓表」这个概念，也没有「跨标的共享现金池」。因此：

- **把 `run_backtest` 套在循环里、每只标的一份现金** → 那是「N 个独立账户」，
  不是组合（现金池不共享、权重无法约束、组合级换手无意义）；
- **为改变这一点去改 `engine.py`** → 违反「不修改核心交易规则」的硬约束。

所以本规格的做法是：**复用引擎的撮合原语，而不是复用它的循环**。

| 复用对象 | 用途 | 是否重写 |
|---|---|---|
| `costs.compute_fees` | 佣金/印花税/过户费，含 `min_commission` | ❌ 不重写，直接调 |
| `costs.execution_price` | 买卖滑点后的拟成交价 | ❌ 直接调 |
| `costs.round_money` | 金额四舍五入到分 | ❌ 直接调 |
| `market.ashare.limit_prices` | 涨跌停边界价 | ❌ 直接调 |
| `market.ashare.open_fill_block_reason` | 涨停买不进 / 跌停卖不出判定 | ❌ 直接调 |
| `engine.run_backtest` 的**循环** | 单标的单持仓的记账顺序 | ✅ 由组合层重新实现（无法复用，理由同上） |

**验证方式不是声明，是测试**：`tests/backtest/test_portfolio_engine_parity.py`
构造「单标的、单笔买入」的等价场景，断言组合层与 `run_backtest` 给出**完全一致的
成交价、股数、费用、期末权益**。两者口径若有一天分叉，这条测试会先炸。

## 1. 口径一：卖出先于买入（现金释放顺序）

**判定：同一执行日，先执行全部卖出，再执行全部买入。**

| 项 | 规定 |
|---|---|
| 执行时点 | 信号日（月末最后交易日）**次一交易日开盘** |
| 顺序 | ① 卖出（含减仓与清仓）→ ② 买入 |
| 组内顺序 | 按**代码升序**（无此条则同一天两笔单的先后取决于 dict 迭代序，不可复现） |
| 现金基准 | 卖出所得现金**当日即可用于买入** |
| 权重基准 | 买卖都用**同一份期初权益**（开盘价估值）计算目标金额，不随卖出过程中现金变化而重算 |

**为什么允许当日卖出资金当日买入**：A 股卖出所得资金当日可用于买入（T+1 只限制
「当日买入的股票当日卖出」，不限制资金买入）。这与实际规则一致，不是为了多买而放宽。

**如果反过来（先买后卖）会怎样**：多数调仓日会出现「现金不足 → 买入被压减 →
卖出后现金闲置」的顺序性损耗。这个损耗与策略无关，纯粹由实现顺序产生，
是最典型的「口径决定结论」陷阱。

**对称约束**：因为卖出先执行，买入可用资金包含卖出所得，因此本口径对买入**略宽容**。
这一偏置的方向是已知的（偏乐观），但幅度未知、未量化 —— 故结果表必须与成本一并读。

## 2. 口径二：权重记账的费用粒度与 `min_commission`

**判定：订单名义金额 = 组合权益 × |Δweight|；`min_commission` **生效**，且**逐笔**计算。**

| 项 | `weights`（主口径） | `lots`（可执行性口径） |
|---|---|---|
| 目标金额 | `equity_open × w_target` | 同左 |
| **买入**数量 | `floor(Δ金额 / 成交价)`，最小单位 **1 股** | `floor(Δ金额 / 成交价 / 100) × 100` |
| **卖出**数量 | `floor(Δ金额 / 成交价)`，最小单位 **1 股** | **同样 1 股**（见下） |
| 费用 | `compute_fees(side, price, qty, cfg)` | 同左 |
| 最低佣金 | **生效**，且**每笔订单**单独判定 | 同左 |

**买卖两侧的粒度不对称，这是 A 股规则，不是疏漏**：买入必须以 100 股（整手）为单位，
卖出允许零股（且零股需一次性卖出）。因此 `lots` 口径里买入按整手取整、
卖出按 1 股取整。若卖出也按整手取整，`lots` 口径会残留卖不掉的零股，
反而偏离真实可执行性 —— 这个错误在本轮实现时被端到端测试抓到并修正
（`tests/backtest/test_portfolio_end_to_end.py` 只断言**买入**是整手倍数）。

**为什么 `weights` 用 1 股而不是「分数股」**：分数股能让 `Δ权重` 精确命中，
但 `compute_fees` 要求整数股数（`_require_positive_int`）。若为分数股另写一份费用公式，
就会出现「两套佣金算 法」——这正是本规格要避免的。1 股粒度把截断误差压到「每标的
最多 1 股」，同时费用仍是**唯一一份实现**。

**为什么 `min_commission` 必须生效**：这是本轮最容易出错的地方。
若在组合层「按权重记账」时跳过最低佣金，单笔小额订单的成本会被系统性低估：
10 万本金、5 只等权 → 每笔 2 万元，佣金万 3 = 6 元 > 最低 5 元，**不触发**；
但 20 只等权 → 每笔 5000 元，佣金 1.5 元 → **按 5 元收，实际费率 万 10**。
跳过 `min_commission` 就等于凭空给策略降低 3~7 倍佣金成本。

**Δweight 的正负**：`Δw > 0` 买入，`Δw < 0` 卖出，`Δw = 0` 不产生订单（不生成
0 股订单，避免无谓的最低佣金）。清仓时 `Δw = −w_current`，按**当前全部持仓**卖出，
不按目标金额反算（避免因价格变动残留零股）。

## 3. 口径三：停牌 / 缺价的估值冻结

**判定：冻结最后可用收盘价估值，计 `stale_valuation_count`；冻结价**只估值、不交易**。**

| 情形 | 处理 |
|---|---|
| 当日该标的**无行情行**（停牌） | 用该标的**最后一次有效收盘价**估值；当日不可交易 |
| 当日有行但 `close` 缺失/非正 | 同上，冻结 |
| 冻结价从未存在（买入前就无价） | 不可能出现：买入要求当日有有效开盘价 |
| 估值状态 | 该标的计入 `stale_valuation_count`；组合权益仍可计算 |
| 单期 stale 权重 > **5%** | 该期标记 `low_confidence_valuation=True`，并写入 `data_quality_issues` |
| 连续冻结 > **60 个交易日** | 仍按冻结价估值，但额外记一条 `prolonged_stale`（不强行清仓：无价可卖） |

**为什么不「按 0 估值」**：把停牌股记 0 会让组合净值在某天凭空跳水、复牌那天凭空暴涨，
产生一条**看起来像极端回撤、其实是记账错误**的曲线。

**为什么不「剔除该标的、把权重分给别人」**：那等于在停牌当天**偷偷调仓**，
且调仓方向由「谁停牌」决定 —— 引入了不可控的选择偏差。

**为什么不「停牌就清仓」**：停牌期间根本卖不出去。允许清仓等于假设了一个不存在的流动性。

## 4. 口径四：涨跌停导致的「该买买不进 / 该卖卖不出」

**判定：买侧放弃（不追），卖侧顺延（不放弃）。两侧不对称，是刻意的。**

| 方向 | 遇涨停/跌停 | 处理 | 理由 |
|---|---|---|---|
| **买入** | 开盘触及涨停（或拟成交价 ≥ 涨停价） | **当日放弃该笔买入**，记 `blocked_buy`，**不顺延、不追高** | 顺延等于「以更高的价格买入本来买不到的股票」，会把「买不进」偷换成「追涨停」，系统性高估动量类信号 |
| **卖出** | 开盘触及跌停（或拟成交价 ≤ 跌停价） | **顺延到后续交易日**每天开盘重试，直到成交或被下一次调仓取代，记 `deferred_sell` | 卖不出是**流动性约束**，不是策略选择；直接放弃等于假装在跌停板上卖掉了 |
| 买入遇跌停 | 不构成阻挡（跌停更容易买到） | 正常成交 | — |
| 卖出遇涨停 | 不构成阻挡 | 正常成交 | — |

**顺延卖出的现金语义**：顺延期间该持仓仍在组合里，其市值照常计入权益；
**这笔「本该到账的现金」不计入可用现金** —— 否则会用一笔还没卖出的钱去买新股票。

**顺延的终止条件**（三条，任一触发即结束）：① 成交；② 下一次调仓日到来（新目标覆盖旧指令）；
③ 回测结束（记 `unfilled_at_end`，不虚构成交）。

**涨跌停比例**：由 `PortfolioBacktestConfig.fee_config.market_rules.price_limit` 决定，
**每只标的同一个比例**（组合层不按板块分别配置）。这是已知简化：真实市场里
创业板/科创板是 20%、主板是 10%。若要用板块比例，调用方需按板块分组分别建组合，
或等后续支持「按标的传入 rules」——**本轮不做**，因为那会改动 `PortfolioBacktestConfig`
的契约，属另行立项。

## 5. 记账与输出的其他约定

| 项 | 规定 |
|---|---|
| 交易日历 | 各标的日期索引的**并集**，限制在 `[start_date, end_date]` |
| 期初建仓 | 第一个信号日的次一交易日按目标权重建仓；此前为空仓持现金 |
| 权益估值 | `cash + Σ(quantity × 当日收盘价 或 冻结价)`；每日记录一条 `PortfolioState` |
| 分红 | 使用前复权价格（隐含分红再投资），**不单独记账现金分红**；与单标的引擎一致 |
| 做空 | 不支持（`TargetPortfolio` 已拒绝负权重） |
| 部分成交 | 不模拟（与引擎一致：日线简化模型） |
| 换手率口径 | 单边成交额之和 / 平均权益 / 年数（`compute_turnover` 内已定义，不在本层重复） |
| 绩效入口 | **只在有连续净值后**调用 `compute_portfolio_performance`（A6）；这是 R12 的正解 |

## 6. 明确**不**在本轮解决的事（防止被误读为已解决）

1. **时点成分股**（幸存者偏差）：股票池仍是当日快照，组合层不引入时点成分。
   结果必须标「上界估计」。
2. **板块差异化涨跌停**：见 §4 末。
3. **分红现金流**：前复权隐含再投资，与实际现金分红有时间差。
4. **真实券商费率**：仍用三档假设，`simulation_placeholder` 必须标注为占位。
5. **部分成交 / 冲击成本 / 流动性**：均未建模；组合层不因「多标的」而变得更真实。
6. **A4/A5 双口径的结论效力**：两口径都是**同一批信号**的记账方式差异，
   `lots` 口径只用于回答「整手约束下还能不能执行」，**不得用来挑更好的那个**（R11）。

## 7. 验收标准

| # | 标准 | 验证方式 |
|---|---|---|
| 1 | 单标的单笔场景与 `run_backtest` 完全一致 | `test_portfolio_engine_parity.py` |
| 2 | 现金恒等式成立：`cash_t = cash_{t−1} − Σ买入(含费) + Σ卖出(净额)` | 逐日断言（容差 0.01 元） |
| 3 | 权益恒等式成立：`equity_t = cash_t + Σ市值_t` | 逐日断言 |
| 4 | 无未来函数：信号日 T 的目标只在 T+1 开盘执行 | 构造「T 日收盘暴涨」用例，断言 T 日不成交 |
| 5 | 卖出先于买入：构造现金不足场景，断言买入笔数/金额 | 定向用例 |
| 6 | `min_commission` 生效：20 只等权时单笔佣金 = 5 元 | 定向用例 |
| 7 | 停牌冻结：停牌日权益不变、`stale_valuation_count=1`；>5% 触发低可信 | 定向用例 |
| 8 | 跌停顺延：卖单次日照常重试并成交；涨停买入放弃并记 `blocked_buy` | 定向用例 |
| 9 | 双口径并行：`weights` 与 `lots` 在同一批数据上都能产出完整绩效 | 集成用例 |
| 10 | 无连续净值时不得调 `compute_portfolio_performance` | 该函数 docstring + 调用点唯一 |
