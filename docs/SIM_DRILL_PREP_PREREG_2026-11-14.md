## 一、要解决什么，预期方向与机制（落在可算的量上）

**问题**：方案 §2 要求「外部真值优先」的成交回报对账，但 `paper_account_adapter.py` 只有 `get_cash` / `get_positions`；方案 §6 登记的演练驱动与对账器完全未实现。若不先冻结判据就写，容易重演本项目已复发过的三类假闸门：① 把「文件不存在 / 空回报」当「确认无差异」；② 闸门调用被测函数自证；③ 测试全绿但验收项未覆盖（P2.2）。

**预期方向**（三条，全部落在可算量上）：

| # | 可算量 | 冻结期望值 |
| --- | --- | --- |
| P1 | 对账器对**逐条注入**的差异的检出数 `n_detected / n_injected` | **= 1.00**（每条注入差异必须独立产生 `HALT` 与对应 `reason`；不得合并、不得忽略） |
| P2 | 外部真值「缺失 / 空 / 不可解析 / 字段缺失」四类输入的停机数 `n_no_inputs / 4` | **= 4/4**，且原因码为 `NO_INPUTS`；**不得**判 `PASS` 或「无差异」 |
| P3 | 真变异检出的变异数 / 变异总数 | **= 100%**，且每个变异须真改行为（`HALT`→`PASS` 或 `NO_INPUTS`→`PASS`），仅换个拒绝理由不算检出 |
| P4 | 驱动 `--execute` 在**无 U-16、无 12-01 台账**时的拒绝率 | **= 100%**，原因码 `NOT_AUTHORIZED`；自检模式零网络、零正式台账写入 |
| P5 | 五项演练在**离线自检**下各产生的记录条数 | **各 ≥1**，且产物 `mode=SELF_CHECK_ONLY`；⭐ **不等于**方案 §5「五项演练全部完成」 |

**机制**（可算量为什么成立）：对账器取外部真值对象作为**唯一期望来源**，对委托集合做 `client_order_id` 双向差集、逐字段比较、成交累计/持仓/资金/费用比较；任一不符即短路 `HALT`。「空输入」与「比对后无差异」是两条**不同代码路径**（前者在任何比对之前失败关闭），所以 P2 与 P1 可分别被证伪。P3 的期望值来自**独立算术与产物**，闸门不调用被测函数自身。P4 由一个显式前置条件实现，与演练逻辑解耦。

⭐ **结构假设**（必须写明，锚只验证过一条序列时它是模板不是定律）：
1. gmtrade 的成交回报 / 未完结委托是「可迭代对象或 dict」，字段访问与现有 `Cash` / `Position` 同构（`_field` 兼容 dict 与属性）；**若 SDK 字段名不同，判 `NO_INPUTS` 而不是猜字段**。
2. 本地演练订单台账是 JSONL，每行含 `client_order_id` / `code` / `side` / `quantity` / `price` / `status`；**缺字段视为输入不可用**，不填默认值。
3. 「外部真值为空」在**尚未发出任何委托**的自检场景下是合法基线，但在 12-01 执行场景下必然是异常 ⇒ 本预登记把它一律判 `NO_INPUTS`（不区分场景），12-01 若要放宽须另立预登记。
4. 离线 fixture broker 与 gmtrade 的真实协议**不保证一致**；自检 PASS 只证明判据与编排正确，**不证明** SDK 契约正确 —— 后者须 12-01 用真实回报验证。

⚠️ **不替规则添加它没有的性质**：不把「自检 PASS」写成「演练通过」；不把「五项演练离线记录」写成「方案 §5 五项演练全部完成」；不把「驱动可注入 broker」写成「已具备报单能力」；不把「外部真值能读到」写成「成交已发生」。

## 三、判据与原因码（冻结）

| 原因码 | 触发条件 | 判定 |
| --- | --- | --- |
| `PASS` | 外部真值可用 **且** 双向差集与逐字段比对全一致 | 仅自检可输出；不代表演练通过 |
| `NO_INPUTS` | 外部真值缺失 / 空列表 / 非 JSON / 必需字段缺失 / 本地台账不可用 | **停机**，⚠️ 不是「无差异」 |
| `HALT:ORDER_SET` | `client_order_id` 双向差集非空 | 停机 |
| `HALT:FIELD` | 单笔代码 / 方向 / 数量 / 价格 / 状态不符 | 停机 |
| `HALT:FILL` | 成交累计不符或重复 `fill_id` | 停机 |
| `HALT:POSITION` | 持仓 / 可用数不符 | 停机 |
| `HALT:CASH` | `available` / `frozen` / `balance` 不符 | 停机 |
| `HALT:FEE` | 费用不符 | 停机 |
| `NOT_AUTHORIZED` | `--execute` 且缺 U-16 / 缺 11-30 FORWARD 台账 | 拒绝执行 |

**失败关闭**：任何异常（SDK 不可用、字段不认识、时间不可解析、路径不可写）一律非零退出 + 停机，**不重试、不降级、不回退到「上次通过」**；不自动忽略差异、不重跑凑通过。
**容差**：金额按产物存储精度定 —— 本轮所有金额来自 JSON 十进制解析，比较用 `Fraction(str(x))` 或分单位整数独立算术，**不引入浮点容差常量**（避免「容差拍脑袋」与「4e-6 存储下限」两类已复发错误）。数量与状态为精确相等。
