## 2. 分层（冻结，不得随意跨层）

```
Strategy → TargetPortfolio → OrderPlanner → RiskGate → BrokerAdapter
                                                          ↓
                                              FillReconciler → Ledger
模式：BACKTEST / PAPER / SHADOW / LIVE，默认 PAPER
```

- **不新增因子、不改冻结参数**。`TargetPortfolio` 的输入就是 `p13_forward` 的 `target_holds`（主口径）或 `target_holds_d4`（安全过滤口径），**由调用方选择，本层不做选择**。
- **与既有 `eventloop/` 的关系**：`eventloop.matching` 是**回测撮合**（bar 内价格可及性、参与率、队列位置），`BrokerAdapter` 是**与券商交互的接口**。MockBroker **不重新实现撮合**——它按注入剧本回应；若需要撮合结果，直接读 `eventloop` 的产物。**禁止**在两处各写一套撮合逻辑。

## 3. 逐项验收（每项都要有可执行测试）

### 2.1 BrokerAdapter + MockBroker

| ID | 要求 |
| --- | --- |
| **2.1-a** | 抽象接口覆盖 8 项能力：持仓、资金、委托、成交、行情、交易日历、下单、撤单。**缺一项即失败** |
| **2.1-b** | 接口层**不出现**任何券商专有名词（`xtquant`/`ptrade`/`qmt` 等），保证换券商只改实现 |
| **2.1-c** | MockBroker 支持**按剧本注入**至少 6 类故障：拒单、部分成交、回报丢失、回报重复、超时、行情陈旧 |
| **2.1-d** | MockBroker 的初始状态（持仓/资金）必须由构造参数显式给定，**不得**内置魔数默认值 |
| **2.1-e** | 任何一次 Mock 调用都能被**重放**：给定同一剧本 + 同一调用序列，结果逐位相同 |

### 2.2 订单规划

| ID | 要求 |
| --- | --- |
| **2.2-a** | 目标持仓 → 差额订单；**先卖后买**（卖单必须在买单之前生成）；数量按**整手 100 股**向下取整 |
| **2.2-b** | 每个委托带 `client_order_id`，同一「决策日 + 代码 + 方向 + 目标股数」重复规划得到**同一个 id**（幂等）；id 中**不得含时间戳/随机数** |
| **2.2-c** | 执行策略按预登记默认值：次一交易日 09:35 后限价单，对手价最多让 0.3%；10:30、14:30 各最多重定价一次；收盘未成交记 `FAILED` 并顺延，**最多 10 个交易日** |
| **2.2-d** | **不得频繁撤单重报**：同一 `client_order_id` 的重定价次数上限为 2，超出即失败 |
| **2.2-e** | 卖出所得现金**不假定可立即用于买入**（T+1 卖出资金当日可用、买入当日不可卖——两者口径不同，必须分开建模） |

### 2.3 RiskGate 硬限

任务书列 11 条，**任何一条不过则拒单**：

| # | 硬限 | 判据 |
| --- | --- | --- |
| 1 | 授权文件金额上限 | `live_authorization.json` 内的上限；文件不存在 ⇒ 拒 |
| 2 | 单票上限 | 单只市值 ≤ 策略仓 × 20%（5 只等权） |
| 3 | 单日委托笔数上限 | 达上限即拒 |
| 4 | 单笔金额上限 | 超过即拒 |
| 5 | 委托价偏离最新价 >1% | 超过即拒 |
| 6 | 黑名单 | 命中即拒 |
| 7 | 非交易时段 | 拒 |
| 8 | 行情陈旧 | 超过阈值即拒（**不得**跳过检查） |
| 9 | 对账不一致 | 上一轮对账有未解释差异 ⇒ 拒 |
| 10 | 熔断线（D2） | 组合峰值回撤 −2.5% 或策略仓 −12.5% ⇒ 拒 |
| 11 | 停机开关 | 文件或命令触发 ⇒ 拒 |

| ID | 要求 |
| --- | --- |
| **2.3-a** | 11 条**逐条**有测试，且每条都有「刚好通过」与「刚好拒绝」两个边界用例 |
| **2.3-b** | 检查顺序固定且可测；**拒单必须给出原因码**（可检索，不是自由文本） |
| **2.3-c** | 任一检查所需输入**缺失时必须拒单，不得视为通过**。这是本阶段最容易写错的一条（见缺陷 P4） |
| **2.3-d** | RiskGate 与熔断做**变异测试**：至少 6 个变异体，其中「删掉某条检查」「把 `and` 写 `or`」「把边界 `>` 写 `>=`」必须被抓到 |

| ID | 要求 |

## 6. 缺陷记录（预登记，供事后对照）

**P1**：我预计「回报**重复**」比「回报**丢失**」更容易写错。丢失只需不返回；重复需要在**同一 `fill_id`** 上重放，多数实现会无意生成新 id，于是本地把同一笔成交记两次。→ 若成立，测试必须断言「同一 `fill_id` 到达两次后持仓只增加一次」。

**P2**：我预计 `client_order_id` 的幂等键若包含时间戳或随机数，重试会生成新 id，幂等彻底失效，而这个错误在单次运行里**完全看不出来**。→ 测试必须做「同一输入调两次 ⇒ id 相等」，且**禁止 id 依赖运行时时钟**。

**P3**：我预计日终对账最容易漏的是「**券商有、本地无**」（如手工交易、漏录回报），而不是「本地有、券商无」。多数实现只遍历本地持仓去券商侧查。→ 测试必须双向构造。

**P4**：我预计 `RiskGate` 的「委托价偏离最新价 >1%」在没有实时行情时会被**静默跳过**（因为拿不到最新价，写 `if price: check()`）。→ 这与 2.3-c 同一类错误：**缺失不等于通过**。必须显式拒单。

**P5**：我预计「熔断线」的触发会写成「当前回撤 ≤ −2.5%」，而真正要的是「峰值回撤」；若峰值在重启后丢失，回撤会被重算成 0，熔断永远不会触发。→ 峰值必须持久化，且测试要覆盖「重启后峰值仍在」。

- 不新增因子、不改冻结参数、不改 `research/` 下的策略代码

- 不在仓库、日志、报告中出现任何凭证
