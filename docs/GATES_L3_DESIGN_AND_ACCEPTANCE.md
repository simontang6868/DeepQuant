## 1. 表 7 的那句话，问题在哪

表 7 对 L3 的要求是：

- 通过标准：**滚动窗口样本外一致性**
- 一票否决：**样本外表现与样本内系统性背离**

"背离"比 L2 的"依赖极端路径"好办一点，但直接照着写仍会得到三个无法执行的判据：

1. **"样本内"指哪个窗口？** Walk-Forward 里每一折都有自己的训练窗，"样本内表现"不是一个数，是一串数。
2. **"系统性"怎么算？** 一折背离是运气，十折背离是结构。需要一个比例而不是一个均值。
3. **"样本外"到底有多外？** 这条最容易自欺：整段历史在 L1a/L2 阶段已经被反复看过，所以 L3 的"样本外"**只对参数选择成立**，不是"没见过的新数据"。

本闸门把第 1、2 条落成算式（第 4 节），第 3 条无法靠算法解决，只能**无条件写进每次运行的 `limitations`**（第 6.2 节），让引用它的人一定看到。

## 2. 三个结构性决策（每个都排除了替代方案）

### 2.1 窗口单位是交易日根数，不是自然日或月份

用自然日/月份切窗，会因停牌、长假、数据缺口而漂移：同一条规则在不同标的上切出长度不同的窗口，"504 天训练"实际上可能只有 400 个交易日。用交易日根数切，规则与标的不再耦合。

### 2.2 测试窗默认互不重叠，重叠时**不许判通过**

`step_days == test_days` 时测试窗首尾相接、两两不重叠。若把 `step_days` 调小，同一段行情会被多个测试窗重复计入——折数变多、方差变小，看起来"更稳健"，实际上是用同一批数据投票。这类"通过"是本闸门最容易产生的假阳性，所以：

> **测试窗一旦重叠，终态最高只能是 `L3_INCONCLUSIVE`。** 不是扣分，是直接取消"折数作为独立性证据"的资格。

### 2.3 折收益**不许**拼成连续净值

每折资金重置、从空仓起步，折间没有资金连续性。把折收益复利相乘得到的数不对应任何真实账户——这正是项目 R12 的教训（窗口级统计 ≠ 连续账户收益）。

所以结果结构里**没有任何净值序列字段**，只报折级统计；`summary.naive_sum_of_fold_returns` 保留但带"不可复利"标注。取证里还专门算了"如果强行复利会得到什么"（`standard_5`），用来解释这条禁令为什么存在：27 折算术和 +107.9%，复利相乘 +144.8%——两个数差 37pp，谁都不是账户收益。

## 3. 每一折做什么

```
for 每一折:
    训练窗 = [t, t+train_days)            ← 跑满参数网格，只按训练窗指标选参
    测试窗 = [t+train_days, +test_days)   ← 用选出的参数跑一次，不再回头
    WFE   = 测试收益 / 训练收益            ← 训练收益 ≤ 0 时记为不可计算并写理由
```

三条实现约束：

1. **训练窗末根的下一天才是测试窗首根**，不共用任何一天。边界共用一天是最隐蔽的泄漏——训练窗的最后一天同时成了"样本外第一天"。
2. **预热来自全序列信号**。日线引擎先在完整数据上生成信号、再裁剪到交易区间，所以测试窗开头的均线有值。但**每折仍从空仓起步**，折首踏空/踏错的成本由该折自己承担。
3. **选参与打分分离是被测试证明的，不是被注释声明的**。`test_selection_and_scoring_are_separated` 直接记录每一次回测调用的 `(起止日期, 参数)`，断言每折"训练窗调用次数 = 网格点数、参数两两不同、测试窗恰好 1 次、且用的参数等于训练窗最优"。

## 4. 判定链

按「不可判定 → 一票否决 → 一致性」排序，顺序本身有语义：

| 序 | 检查项 | 判定 | 为什么排这个位置 |
|---|---|---|---|
| 1 | 可用折数 ≥ `min_folds` | 不足 → `INCONCLUSIVE` | 折数不够时均值本身就是噪声，先判意义不大 |
| 2 | 测试窗互不重叠 | 重叠 → `INCONCLUSIVE` | 重叠的折数不能当证据，必须在任何"通过"之前拦住 |
| 3 | 符号背离：训练正收益折占比 ≥0.6 **且** 测试均值 ≤0 | 成立 → `REJECTED_SYSTEMATIC_DIVERGENCE` | 表 7 的一票否决项，第一条读数 |
| 4 | 「训练正、测试负」折占比 ≤0.5 | 超过 → `REJECTED_SYSTEMATIC_DIVERGENCE` | 同一否决项的第二条读数，见下 |
| 5 | 正收益折占比 ≥0.6 | 不足 → `REJECTED_INCONSISTENT_FOLDS` | 没有一致性，但不是"背离" |
| 6 | 中位 WFE ≥0.3 | 不足 → `REJECTED_INCONSISTENT_FOLDS`；不可算 → `INCONCLUSIVE` | 保留率太低同样是没一致性 |

### 3 和 4 为什么是两个判据

- **判据 3（符号背离）** 要求"训练普遍为正"这个前提。如果训练窗也普遍亏，那不是"样本内外不一致"，而是"从一开始就没有 edge"——把它叫背离会误导归因。
- **判据 4（折占比）** 不看均值。极端情形下均值可能被一两折的巨大盈利拉正，而多数折在失血；只报均值会掩盖它。

两者同时报，才能区分「策略在衰减」和「策略从未成立」。

### WFE 的边界处理

`WFE = 测试收益 / 训练收益` 只在**训练收益 > 0** 时有经济含义。训练亏损时除出来是负数或无穷，看起来像"样本外比样本内好"或"崩了"，两种读法都是错的。这类折不进中位数，并且每折都写 `wfe_reason`。

## 5. 真实用例：ma_cross / 000001.SZ / 2010-01-04 → 2026-05-22

契约 `docs/gates/specs/H_L3_MACROSS_000001.json`，`train=504 / test=126 / step=126`（约两年训练、半年测试），网格 15 点（`fast<slow` 约束后），跨度 2010-01-01 起（避开 2005–2006 数据稀疏期）。

| 项目 | 结果 |
|---|---|
| 折数 | **27**（全部完成，0 折失败） |
| 训练窗正收益折占比 | **81.48%**（22/27） |
| 测试收益均值 / 中位 | **+4.00%** / **+0.95%** |
| 测试收益范围 | −11.21% ~ +34.12%，标准差 11.96% |
| 正收益折 | **14/27 = 51.85%**（阈值 60%） |
| 「训练正、测试负」 | **10/27 = 37.04%**（阈值 50%） |
| 中位 WFE | **0.0000**（22 个可算折） |
| 测试回撤中位 / 最大 | 10.10% / 26.81% |
| 参数集 / 稳定性 | **10 个不同参数集**，最常用者仅占 18.52% |

**判定链结论：`L3_REJECTED_INCONSISTENT_FOLDS`。**
不是"背离"（符号背离与非超限两条都过），而是**没有一致性**：训练窗 81.5% 为正、测试窗只有 51.9%，中位 WFE 恰好落到 0。典型形态是——训练期年年有趋势，测试的半年窗有一半时间在横盘或急跌，均线交叉在那里反复止损。

**为什么最终终态是 `L3_BLOCKED_PREREQUISITE`**：L1a 判 `L1A_REJECTED_BOUNDS`（回撤 32.84% > 25%）、L1b 判 `L1B_BLOCKED_PREREQUISITE`、L2 判 `L2_REJECTED_EXTREME_DEPENDENCE`。按逐级闸门原则，前序未放行时本闸门的任何结论都不构成放行依据，终态降为 `BLOCKED_PREREQUISITE`，但判定链自身的结论仍被保留在 `preliminary_verdict` 与报告头部。

### 5.1 参数稳定性是这次最刺眼的数字

27 折里选出 **10 个不同参数集**，最常用的 `{fast:3, slow:60}` 只出现在 5 折（18.5%），相邻折改参数的次数 15/26。这说明"最优参数"对窗口边界高度敏感——L1a 用单一窗口选出的 `{3, 60}` 在这个视角下只是众多"局部最优"之一。

这条不进否决项（表 7 没这么要求），但它解释了为什么 L1a 挑出的参数在 L2 里表现为"收益依赖十几个交易日"：参数本身就没有稳定解。

## 6. 验收（六项，全部实测）

证据文件：`reports/L3_GATE_EVIDENCE.json`。

| # | 标准 | 实测 | 结论 |
|---|---|---|---|
| 1 | 窗口结构自证 | 27 折与主跑完全一致；**27/27** 折训练末根的下一天是测试首根；测试日重叠 **0 天**；未用尾部 98 个交易日 | **PASS** |
| 2 | 选参/打分分离 | 20 折 × (4 网格点 + 1 测试) = **100 次回测**，与预期 100 完全一致；每折训练窗参数两两不同、测试窗恰好 1 次且用的是训练最优 | **PASS** |
| 3 | 判定链可分辨 | 三种合成市况分别落 `L3_PASSED` / `L3_REJECTED_SYSTEMATIC_DIVERGENCE` / `L3_REJECTED_INCONSISTENT_FOLDS` | **PASS** |
| 4 | 终态分类不混用 | 折数不足与窗口重叠 → `INCONCLUSIVE`；跨度数据不足 → `REJECTED_DATA`；切不出折 → `REJECTED_WINDOW`；契约非法 → `REJECTED_SPEC` | **PASS** |
| 5 | 不构造连续净值 | 结果中无 `equity_curve`/`nav` 等字段；禁令写进两条 `limitations`；反例数字已标注"不得引用" | **PASS** |
| 6 | 前置可追溯 | 三个前序终态全部读自各自结果文件（`L1A_REJECTED_BOUNDS` / `L1B_BLOCKED_PREREQUISITE` / `L2_REJECTED_EXTREME_DEPENDENCE`），缺失记 `UNKNOWN` 绝不默认通过 | **PASS** |

### 6.1 标准 3 为什么必须有

只会说"通过"的闸门等于没有闸门。三种合成市况是判定链的最小检验集：

| 市况 | 折数 | 训练正收益折 | 测试正收益折 | 背离折 | 中位 WFE | 终态 |
|---|---|---|---|---|---|---|
| 全趋势 | 19 | 100% | 100% | 0 | +0.455 | `L3_PASSED` |
| 趋势震荡交替 | 20 | 70.0% | 65.0% | 7 | −0.396 | `SYSTEMATIC_DIVERGENCE` |
| 趋势后转震荡 | 19 | 57.9% | 47.4% | 1 | +0.455 | `INCONSISTENT_FOLDS` |

第三行值得单看：这是最像真实情况的一种——趋势结束后长期震荡。它的训练窗里也混进了震荡段（训练正收益折 57.9% < 60%），所以**不满足"符号背离"的前提**，落到 `INCONSISTENT_FOLDS`。如果只写了判据 3，这个案例会被误报成"背离"。

### 6.2 每次都无条件写入的限制

- **折收益不可拼成连续净值**（每折资金重置、起始空仓）。
- **本闸门的"样本外"只针对参数选择**：整段历史在 L1a/L2 阶段已被看过，测的是**参数随时间的稳健性**，不构成前瞻样本外证据。
- 预热 120 个交易日：训练窗起点之前的数据只用于让滚动指标有值，不计入收益；每折测试窗仍从空仓起步。
- 训练窗固定 504 天滚动：早期折可用的历史少于后期折，折间训练样本量不等（rolling 的固有特征）。
- 可用折 < 10 时额外提示：折级统计功效很低，一折之差就能改变结论。

## 7. 踩坑记录

1. **anchored 模式切窗死循环**。首版 `train_start_idx = 0 if anchored else cursor*step`，但 `train_end_idx` 仍按 `train_start_idx + train_days - 1` 算——anchored 下 cursor 不参与任何计算，`test_end_idx` 永不前进。表现不是报错而是**测试挂住 4 分钟**。已改为「锚定 = 起点固定、长度逐折 +step」，并加进度守卫：测试窗不再前进就抛错，宁可失败不能挂死。
2. **`check_frame` 遇到 `DatetimeIndex` 且无 `date` 列会 `KeyError`**。真实数据经 `load_frame` 一定有 `date` 列，所以这个洞一直没暴露；一旦调用方（测试、Notebook、`normalize_daily_data` 的产物）传索引式数据，拿到的不是否决项而是异常——"门禁崩了"和"门禁发现数据有问题"是两件完全不同的事。已在入口把索引落成列。
3. **数据门禁窗口用错了对象**。首版沿用 `hypothesis.in_sample`（2016–2021），而 L3 实际走 2010–2026：等于让 2010–2015 与 2022–2026 两段完全裸奔。现在门禁用**声明跨度**，并在切窗前先把数据切到跨度。
4. **取证与主跑算了两套折数**。取证脚本直接在**全量数据**上 `build_folds` 得到 36 折，而主跑按跨度限制是 27 折，两者都"看起来对"。已改为取证先切跨度，并断言折数与 `l3_result.json` 一致——交叉验证只比各自算出来的东西，等于没验。
5. **测试夹具被数据门禁先拦下**。几个用例的合成序列只有 140–260 行，先触发"样本内 ≥250 行"覆盖不足，返回 `REJECTED_DATA` 而不是要测的那条路径；断言 `KeyError: folds_total` 才发现。教训与项目铁律一致：**测试自己也要先满足前置条件，否则测的是错误的那条分支。**
6. **`MaCrossStrategy` 只在交叉当天出信号**。合成单边趋势里它只建仓一次、后续窗口零成交，导致"零收益折"看起来像"策略失效"。测试与取证改用状态型 `TrendStateStrategy`（快线在上就持有），保证每折都会重新建仓。这是**夹具**问题，不是策略问题——但它提醒：**用一个只为单次回测设计的策略去做跨折比较，会得到满屏的 0。**

## 8. 未完成与限制

- **L3 走日线引擎，不是事件驱动内核**。与 L1a 的成交假设一致（含费率、整手、涨跌停拦截），但没有 L1b 的参与率/排队/冲击模型。要"在保真引擎上做 Walk-Forward"需要把 `EventKernel` 接进 `run_sweep`，属新阶段。
- **单标的、单条价格路径**。27 折并不独立：同一只股票的波动体制有延续性。组合级 L3（多标的、共享资金）未实现。
- **折不是前瞻样本外**。真正的样本外只能靠时间前进，不能靠切窗制造。
- **`declared_grid_points` 与 `grid_points()` 的口径**沿用 L1a：分母是约束过滤后的组合数。
- **WFE 中位数为 0** 是真实结果（22 个可算折里中位落在 0.0000），不是格式化误差；`wfe_samples` 一并报出，便于判断这个中位数的样本基础。
