## 0. 为什么必须升版，且为什么不能回改

v1 执行后登记了 3 条缺陷（D1/D2/D3）。本轮资金口径对照又证实并新增了 2 条（D2 扩展、D4）。

但**改判据去重判同一批数据，等于把样本外变回样本内**。
所以：v1 的判定 `R4_INCONCLUSIVE` **保持不动**，v2 只对下一批数据生效。

> 一条纪律：判据可以升版，结论不能重判。看过数字之后再改判据，改的就不是判据，是结论。

## 1. v1 的 5 条缺陷与 v2 的修法

| # | 缺陷 | 性质 | v1 做法 | v2 修法 |
|---|---|---|---|---|
| D1 | E2 用跨标的中位数，任一只零成交就把中位数钉在 0 | **真缺陷** | `sign(E2中位)` | 改用**超额收益**的符号，且逐标的取符号后投票，不用跨标的中位数 |
| D2 | `zero_trade_ratio` 分母只含 `valid` 窗口 | 口径缺陷 | 忽略选择失败 | 新增 `unfillable_ratio`，分母 = **全部窗口**（含失败、含剔除） |
| D2b | `trades=0` 被当成空壳 | **本轮新增** | 未涉及 | 空壳判据改用 `orders>0 且 fills=0`。`trade_count` 只数**已平仓**，买而未卖也是 0 |
| D3 | R1 未命中 | **不是缺陷** | — | 保留原样。20 个高度相关观测里 7 个为正，符号检验 p≈0.13，本来就拒斥不了随机。**不要为了"能出结论"去放宽它** |
| D4 | `all_rejected` 未按原因区分 | **本轮新增** | 未涉及 | 必须按引擎的 `Order.reason` 归因。实测 4 个全拒窗口里只有 **1 个**是资金不足，另 3 个是 `insufficient_position`（空仓卖出，正常行为） |

## 2. 前置闸门（v1 没有，v2 必须有）

跑之前必须全部通过，任一不过则**不产生判定**（记 `GATE_FAILED`，不记 `NO_POWER`）：

| 闸门 | 判据 | 工具 |
|---|---|---|
| G1 数据指纹 | 全部数据文件 sha256 与冻结清单一致 | `scripts/oos_2026_run.py` 第一步（沿用） |
| G2 资金充足性 | 池内每只标的在**每个窗口**都满足 `一手 ≤ 资金`（`strict`） | 新增：`scripts/universe_preflight.py --strict` |
| G3 名义池 = 有效池 | `n_nominal == n_effective`，否则必须在报告里单列差集 | 新增 |
| G4 盲测声明 | 该区间从未出现在任何已产出的结果文件里 | 人工 + 数据指纹 |

> G2 是本轮新增的硬闸门。v1 缺了它，才会出现"6 只池实际 4 只在跑"却没人知道的情况。
> 若 G2 不过，**正确做法是改池或改资金后重新冻结**，不是带着缺口往下跑。

## 3. 主判据（v2）

### 3.1 两个检验，主次不变

- **E1（主）**：滚动窗口，取 `oos_start >= 冻结起点`。
- **E2（次级）**：训练段选一次参数，整段不重选。

### 3.2 主判据改成"区间 + 符号检验"，不再单看中位数落点

v1 的 R3（`IS p10 ≤ E1中位 ≤ IS p90` 且与 E2 同号）有两个问题：
区间太宽（p10~p90 覆盖 80% 的分布，几乎必然落进去），且依赖 D1 那个坏掉的符号。

v2 改为：

| 顺序 | 条件 | 判定 |
|---|---|---|
| R0 | `unfillable_ratio ≥ 0.50`，或 `n_executed < 20` | `NO_POWER` |
| R1 | E1 中位 < 0 **且** 正收益窗比例 ≤ 25% **且** E2 超额中位 < 0 | `REFUTED` |
| R2 | E1 中位 > IS p75 **且** E2 超额 > 0 **且** 符号检验 p < 0.10 | `IMPROVED` |
| R3 | IS p25 ≤ E1 中位 ≤ IS p75 **且** E2 超额同号 **且** 符号检验 p ≥ 0.10 | `CONSISTENT`（但标注"功效不足，不能声称有效"） |
| R4 | 其余 | `INCONCLUSIVE` |

关键改动：
- 区间从 `p10~p90` 收窄到 `p25~p75`（IQR），避免"几乎必然通过"。
- **任何判定都必须附符号检验 p 值**。p ≥ 0.10 时，`CONSISTENT` 后面必须写"功效不足"。
  v1 的教训是：R1 没命中不代表策略有效，只代表样本不够。

### 3.3 必须报告的执行形态（v2 新增，不参与判定）

沿用本轮 `exec_shape` 四分类，逐窗口计数：
`executed` / `holding_at_end` / `no_signal` / `all_rejected`（按 `reason` 细分）。

> 这四类**不改变判定**，但必须与判定同页呈现。
> 判 `NO_POWER` 时，读者要能立刻看出是"没信号"还是"有钱买不到"。

## 4. 样本消耗规则（补 v1 的漏）

v1 §8 只写了 `NO_POWER` 要消耗样本。**写漏了**。v2 改为：

> **只要产生了判定（R0~R4 任一），该区间即视为已消耗。**
> `INCONCLUSIVE` 不等于没跑 —— 数字看过了，盲测就结束了。

后续：该区间只能作为"已知结果的检验段"引用，不得再声称样本外。
