# 把研究池接进软件（2026-10-18）

## 1. 要解决的问题

上一版软件复审记下的第一条限制是：

> 界面只能选已登记的 5 只数据集，不能上传文件（API 刻意不接受客户端路径）。

这不是「少几个选项」，是两个池子不通：

| | 研究线 | 软件 |
|---|---|---|
| 数据位置 | `D:/DeepQuant power by txm/b50_v3/*.qfq.csv`（仓库外） | `<repo>/data/processed/*.parquet` |
| 标的数 | 50 | 5 |
| 关系 | 研究结论都建立在这 50 只上 | 与研究池没有任何一只重合保障 |

后果是：文档里说的「48 只」「600809.SH 在 OOS 有 9/48 个月持有」这些结论，
在软件里一个都复现不了。软件能跑，但跑的不是研究用的那份数据。

## 2. 做法：`scripts/import_pool.py`

不是「一个 for 循环调 ingest」，因为那样会在四个地方悄悄出错：

| 风险 | 处理 |
|---|---|
| 池在仓库外，路径写死只在某台机器成立 | `--pool-dir` 必填，不设默认值；目录不存在退出码 2 |
| 池清单里每只有 sha256，文件对不上也照导 | **先验指纹再读文件**，不一致即 `rejected(sha256_mismatch)`，不写任何文件 |
| 价格非正 / OHLC 矛盾 | **不修**，交既有闸门拒绝并记录错误码。修一修再导入会得到「能跑但没有任何文档对应」的结果 |
| 重复跑改 mtime、交换数据被静默覆盖 | 同 sha256 → `unchanged`（不重写）；已有不同 sha256 → `conflict`（不覆盖，退出码 1） |

另外两个刻意的选择：

- **`--dry-run` 不写任何文件**（连目录都不建），并逐只打印 `would_import / would_enrich / would_reject`；
- **研究线跳过、导入闸门却放行（或反之）必须报 `disagreements`** 并使退出码为 1。
  样本范围说不清时，宁可让命令失败，也不要让人以为「48 就是 50 减掉的那两只」。

## 3. 结果

`python scripts/import_pool.py --pool-dir <b50_v3> --extra-names data/extra_instrument_names.json`

```
[POOL ] b50_v3 · 清单 step75_research_summary.json（sha256 f7cec95fdb75）
[POOL ] 清单 50 只 / 找到文件 50 只 / 文件不在清单里 0 个
...
[SUM  ] unchanged 48 / rejected 2
[FILE ] data/pool_manifest.json
```

首次运行是 `imported 46 / enriched 2 / rejected 2`，之后每次都是 `unchanged 48 / rejected 2`。

| 状态 | 只数 | 说明 |
|---|---|---|
| `imported` | 46 | 本次导入，`source.name = b50_v3/<code>.qfq.csv` |
| `enriched` | 2 | `000001.SZ`、`600900.SH` 早已从 `step75/` 导入过，**sha256 与池内文件相同**（数据一致），只补了名称 |
| `rejected` | 2 | `000568.SZ` `invalid_price(1)`；`600809.SH` `invalid_price(131)` |
| 合计 | 50 | |

界面因此有 **51** 个数据集：

- **48 只** = 研究池 50 只中被数据闸门放行的部分；
- **3 只** = 早先手挑的 `600519.SH / 000858.SZ / 601318.SH`（不在研究池的 50 只里）。

### 一个可以直接引用的交叉验证

v2 研究线的「48 只池」= 50 只整只剔除 `000568.SZ` 与 `600809.SH`。
本轮的导入闸门**独立地**拒绝的正是这两只，且原因是最初的负价缺陷。两套判定在这一点上完全一致
——这解释了为什么界面上「池内 48 只」与历史 288 组研究的样本范围是同一个。

注意这只是**整只剔除**层面的一致：Gate 1 用的是逐日剔除（600809 大部分月份仍可用），
所以界面里没有 600809，Gate 1 的「排除 600809」对照无法在界面上复现。

## 4. 名称：为什么加，为什么只加在这个字段上

50 个只显示代码的下拉框不可用（`000858.SZ` 是五粮液这件事，不能要求用户背下来）。

- 名称来自池清单的 `stocks[].name`（同一次抓取快照，与行情一一对应），
  写进元数据的 `instrument.display_name`；
- 3 只手挑标的名称来自 `docs/DATA_GATE_FINDINGS_2026-10-17.md` 第 28–32 行的 GATE 日志，
  单独放在 `data/extra_instrument_names.json` 里并注明出处；
- **只补缺失、不覆盖已有**；池清单与补充文件打架时以池清单为准（那是研究结论的出处）；
- 名称**不参与任何计算**：只进元数据，行情表列集合不变（有测试钉住）；
- 历史元数据没有这个键 → 数据集照常可用，界面回落到只显示代码。
  名称存在而非法（空串/控制字符/超长）→ 该数据集列为不可用，宁可不让选，也不把乱码打进页面。

写入端（`data/pipeline.py`）与读取端（`api/datasets.py`）共用
`data/instrument.py` 的同一份规则。分开写两套校验会出现「写得进去、读不出来」，
而报错只会说「元数据无效」，不指向真正的分歧点。

## 5. 界面：48 项下拉框要能找得到

`DatasetSelector` 在数据集超过 12 个时出现筛选框（按代码或名称），并显示
「共 51 个可用数据集（筛选匹配 N 个）」。一个容易被忽略的细节：**筛掉的当前已选项仍保留在列表里**
——否则 `<select>` 的 `value` 找不到对应 `option`，下拉框显示成空白，看起来像「什么都没选」，
而表单里其实带着上一只的代码。此时提示语会写「含当前已选项」，并且不把匹配数说成 2。

## 7. 仍然不解决的事

1. **池是 2026-10 的成分股快照**，不是 2017 年的历史成分。界面上能选到这 48 只，
   不等于「当年的 300 成分股」——幸存者偏差照旧存在，任何收益类结论都不能从这里出。
2. **区间只有 2017-01-03 ~ 2024-12-31**。四只双创标的更晚（如 `688271.SH` 2022-08 起），
   起止日期会被真实数据截断，界面上不会提醒你「样本变短了」。
3. **仍然只能单标的回测**。48 只可以逐只跑，但界面没有横截面/组合入口，
   这是下一阶段（多标的组合回测界面化）的事。
4. **没有把 Gate 1 的结果接进来**。`gate1_run.py --execute` 还没跑，跑完后需要单独做结果面板。
5. 数据目录体积增加了约 46 只的 raw CSV + parquet（raw 是原样留存的证据，刻意不删）。
