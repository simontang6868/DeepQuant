## 1. 发现

预登记 §2.1 表中 U1（Gate 6 反转全 A 毛 alpha）一列的栏目标为
「记录 t_nw(L=3)」，值 4.3861083442。首跑 G1 闸门即报不通过：

- CSV 重算 NW(L=3)：**t = 4.644339**
- 而 mean_pp 与记录值逐位吻合（0.708446 vs 0.70844569）

t 不符而 mean 吻合 → 不是序列损坏，是**估计量口径不同**。

## 2. 查证（根因）

`scripts/run_gate6_allasof.py::stats_of()`：

```python
mean = sum(d) / n
sd = statistics.stdev(d)        # ddof=1
se = sd / math.sqrt(n)
t = mean / se                   # 纯 iid t，没有任何 HAC 调整
```

且 Gate 6 预登记（`docs/GATE6_ALLASOF_PREREG_2026-10-21.md`）全文未规定
Newey-West / 滞后 / 自相关处理——**Gate 6 从未指定 HAC 估计量，iid 是它的
既有口径**。数值复核：

| 口径 | t |
|---|---:|
| 记录值（Gate 6 summary） | 4.3861083442 |
| iid 重算（stdev/sqrt(n)） | 4.386108345447266 |
| NW(L=0) 重算 | 4.395391 |
| NW(L=3) 重算 | 4.644339 |

记录值与 iid 重算差 1.2e-9，坐实。

## 3. 影响评估

1. **Gate 6 判定不受影响**：iid 4.3861 与 NW(3) 4.6443 都远过 1.96，
   `SUCCESS` 判定在两种口径下都成立。
2. **但这是一个口径不一致**：项目自阶段 C 起全面使用 NW(3)（Bartlett L=3），
   而 Gate 1~6 时代的头条 t 是 iid。历史引用里「Gate 6 t=+4.39」与
   「阶段 I t=+6.357」混用了两种估计量，此前没有任何文件标注过这件事。
   （与 MEMORY 已记的「单侧 1.645 与双侧 1.96 混用过」是同一类历史遗留。）
3. **对本审计的影响**：U1 的 L 剖面照常测量（NW 网格）；但
   (a) G1 闸门对 U1 改为按**记录口径（iid）**复现——闸门的目的是证明
   「持久化序列能重现记录头条」，用记录当年实际使用的估计量才达成这个目的；
   (b) U1 的模板预测以 iid 记录值 4.3861 为基会低估整条剖面，
   但其**翻转预测**（不翻转）在两种基下都成立（NW(3) 基下 L=0 也有 3.32）。
