1. 执行摘要

1.1 系统定位

DeepQuant 是一个本地单机、A 股日线级、以可复现与可证伪为核心的量化研究平台。它的设计目标不是"多快好省地跑出漂亮曲线"，而是：

让一个策略假设在跑之前就被冻结，跑完之后无论结果好坏都不得修改判据，从而得到一个不会被自我欺骗污染的答案。

这个目标已经达成。它的副产品是一个能用的回测软件（Web 界面 + REST API + 历史库）；它的未达成部分是"找到可交易策略"，而这一部分受限于数据而非代码。

1.2 五条硬结论

# 结论 证据强度
C1 软件可运行、可回归、可复现：1997 passed / 1 skipped / 0 failed，非 research 覆盖率 96.81%，45/76 模块 100%；单端口启动、界面/API/历史库全链路实测通过 实测（作者机 + 独立沙箱双环境）
C2 回测引擎的记账与对账已闭合：单标的路径与组合路径对同一笔交易必须给出相同成交价/股数/费用/逐日权益（3 条断言），权益恒等式违反即抛错 实测

1.4 我认为最值得评审者先看的三件事

  1. Gate 1 的"失败"是可信的否定，不是"跑崩了"（§5.3）。它有预登记、有冻结哈希、有 CI、有敏感性、有排除对照。它证明的是"这个假设在这批数据上没有优势"，不是"动量无效"。

3. 第 2 层：回测计算是否可信

3.1 记账口径（写死在 docs/A3_ACCOUNTING_SPEC.md）

口径 规则 为什么重要
现金释放顺序 卖出先于买入 否则同日调仓会假性资金不足
最小佣金 权重记账下仍生效 否则小额成交成本被低估
停牌估值 冻结上一价 + 计数 否则停牌期净值凭空跳动
涨跌停 无法成交则顺延到下一可成交日 否则高估策略的成交能力

3.2 三重对账机制

机制 内容 状态
双路径对账 同标的、同一天、同一笔交易，单标的与组合路径的成交价/股数/费用/逐日权益必须一致 3 条断言全过
权益恒等式 每日 现金 + 持仓市值 = 权益，违反即 RuntimeError 不产出可疑净值
运行指纹 每次回测记录参数指纹与数据指纹，同参数二次运行逐位一致 实测通过

3.3 成本模型（含假设，必须随结论引用）

项 值 性质
佣金 券商参考值（broker_reference_common_2024） 可核实到"参考"，不可核实到"你的账户"
印花税 / 过户费 按现行规则 规则性，可信
滑点 单边 0.1% ⚠️ 纯研究假设，无法核实
涨跌停 flat 10%，无 per-symbol 通道 主板正确；2020-08-24 后对 9 只双创偏严 = 悲观方向
停牌 以"当日无行情行"近似，无标记 会低估停牌期间的机会成本
因此：任何结论都不得写成"按真实成本回测"。正确写法是"按含 0.1% 单边滑点假设的成本模型回测"。

3.4 明确不可信的边界

  • 容量 / 冲击成本：完全未建模。50 只池里若有大资金，结论不成立。
  • 券源：未涉及（当前无融券逻辑）。
  • 实盘滑点：未校准，0.1% 是行业惯例值，不是本项目实测值。
  • 分红再投：前复权为减法复权，长区间会出现非正价格（600809 有 131 行为负），因此低价股研究不能复用这批数据。

4. 方法论资产：这套东西真正的价值

这一节是给"懂行的人"看的。如果只看策略结论，会低估这个项目；如果只看软件，会高估它。

4.1 预登记（Pre-registration）机制

环节 时间 证据
预登记冻结 2026-10-18 19:30 gate1-prereg-v1.3，sha256 8b011551…
用户授权执行 2026-10-18 23:26 授权原话写入 summary.json
实际执行 2026-10-18 23:51 主实验 92.1 s
机械生成报告 2026-10-18 23:58 scripts/gate1_report.py，接口不提供"传入措辞"参数
执行后复核 2026-10-18 23:59 本地文件 sha256 与冻结值逐字符相同

协议先于结果的证据链完整。这不是形式主义：它排除了"跑完再改判据"这种最常见、也最难自察的作弊。

4.2 三档机械判定 + 多重检验

  • 档位：success / failure / inconclusive，冲突优先级 failure > inconclusive > success。
  • 12 组敏感性预先写死，不是根据结果挑的；BH 校正后 q 全为 0.8744（这是 BH 取右侧最小值的正确性质，不是 bug；应看原始 p 区间 0.3436–0.8744）。
  • 主实验自由度 = 0（单参数组合），因此不存在"换组参数再试试"的解释空间。

4.3 十二条纪律（R1–R12，节选最关键的）

规则 内容
R2 / R11 禁止调参、禁止择优、禁止事后换窗口
R3 禁止编造数据（缺失就报缺失）
R4 占位费率必须显式标注
R5 禁止删除失败结果
R6 禁止 reset / clean / restore 掉历史
R7 禁止弱化测试来让结果变绿
R8 禁止 push main / 禁止 merge
R12 窗口级统计 ≠ 连续账户收益，不得混用
这十二条不是装饰。它们直接对应量化研究里最常见的七种自欺：择优、删失败、改判据、弱化测试、混口径、编数据、悄悄重跑。

4.4 这套方法论能迁移到哪里

即使这个项目最终不产生策略，它的装置可以直接复用于：任何"先假设、后验证"的因子研究；任何需要审计链的模型评估；任何要回答"这个结果是不是我调出来的"的场景。这是本项目最可能被长期复用的资产。

5.4 一个容易被忽略的现实检验：资金充足性
