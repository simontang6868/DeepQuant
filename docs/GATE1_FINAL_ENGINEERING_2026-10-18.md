## 2. `--exclude-symbols`：三处刻意做严

预登记 §10.2 列的三条「证据不足」触发项里，前两条（S11 符号翻转、S9 成本转负）
已在上一轮自动判定；第三条「`600809.SH` 数据缺陷影响无法隔离」需要一次对照跑，
本轮补上。

判定方式固定为：主实验（含该股）与对照（排除该股）两版 `mean(d)` 符号是否一致。
真跑时回测次数从 26 次变 **28 次**（对照跑 = 1 组实验 × 策略 + 基准）。

三处「比别人想象的更严」的地方，都是为了防一类具体事故：

| 处理 | 如果不这么做会怎样 |
|---|---|
| `--exclude-symbols ""` **报错** | 被当成「没有排除」→ 用户以为跑了排除版，实际跑的是全池版，两版混淆直接污染第三条判定 |
| 不存在的代码**报错** | 静默忽略 → 「排除后重跑」实际没排除，对照跑退化成主实验的复制，符号必然一致，**于是错误地判「影响可隔离」** |
| 排除全部标的**报错** | 池子被清空 → 全月空仓，`mean(d)` 全是 0，判定完全失真 |

其中第二条是最容易悄悄发生的：它不会报错，只会给出一个「看起来没问题」的结论。

### 默认行为零变化的证明

要求是「不传 `--exclude-symbols` 时，`run_id` 与 dry-run 输出与之前完全一致」。
验证方式是拿证据，不是看一眼：

```
改动前 dry-run → gate1_dryrun_before.txt  sha256 2b903b804ad3bc25...  (204 行)
改动后 dry-run → gate1_dryrun_after.txt   sha256 2b903b804ad3bc25...  (204 行)
diff → 无差异
```

实现上靠「条件插入键」：`excluded_symbols` / `n_symbols_after_exclusion` /
`extra_control_run` 三个键只在真的传了排除参数时才出现在 dry-run 输出里。
不这样做、改成永远输出 `"excluded_symbols": []`，也能通过绝大多数测试，
但那就不叫「零变化」了。

真实数据下的排除路径也已实测：`50 只 → 剔除 600809.SH → 剩 49 只`，
`estimated_backtests` 从 26 变 28。

## 3. 报告生成器：让结论无法被手写

### 为什么需要它

跑完实验后有 13 组数字、12 个 q 值、48 行逐月配对。手写报告时最容易发生的不是算错，
而是**措辞漂移**：

- 「证据不足」被写成「基本有效」「趋势向好」；
- 「失败」被写成「参数还没调好」；
- 统计优势被顺口说成「策略可用」。

这三句都不是算错，但都改变结论。所以把结论措辞做成**一档一句的常量**，
报告渲染时按 `summary.json` 里的 `verdict` 机械选取，**接口上不提供传入措辞的参数**。

### 三档措辞（节选）

| 档位 | 必须写进去的话 |
|---|---|
| `success` | 「这不等于策略可交易」「也不等于可外推到 2017–2020」 |
| `failure` | 「失败档不需要用『参数没调好』来软化：主实验只有一个参数组合、自由度为零」 |
| `insufficient` | 「**不是失败，也不是成功**」「不得写成『基本有效』或『基本无效』」 |

### 最后一道自检

`render_report` 在返回前扫描全文：非 `success` 档若出现
`策略有效` / `验证有效` / `证明有效` / `显著优于基准` / `可以投入使用` 任一词，
**直接抛 `AssertionError`，拒绝输出报告**。

有一条测试专门验证这个守卫真的会触发：把「本实验证明策略有效」塞进失败档的模板，
断言抛错（`test_guard_catches_success_phrasing_leaked_into_failure`）。
守卫本身没有测试，就等于没有守卫。

### 数字不漂移

报告里的每个数都从 `summary.json` / `sensitivity.csv` / `monthly_paired.csv` 读出，
**渲染层不做任何重算**。数字对不上应当报错，而不是在渲染时算出另一个版本。

交叉校验包括：
- `summary.n_months` 必须等于 `monthly_paired.csv` 行数（防两处记载不同步）；
- `manifest.json` 记录的每个文件 sha256 必须与磁盘一致（防手改结果）。

第二条的理由：一份被改过的结果被渲染成报告，比没有报告更糟——报告会带着
预登记哈希前缀，看起来像是协议保证过的结论。

### 四层结论物理分离

`docs/GATE1_PREREGISTRATION.md` 与 B-4 都要求四层不可互相替代。报告第 5 节直接列表：

| 层 | 问题 | 本报告能否回答 |
|---|---|---|
| 1 | 软件功能是否正确 | 否（由全量 pytest 与各模块契约测试回答） |
| 2 | 回测计算是否可信 | 否（由 `docs/A3_ACCOUNTING_SPEC.md` 四项口径与引擎一致性测试回答） |
| 3 | 策略是否显示统计优势 | **是**（机械判定，依据第 2/3/4 节） |
| 4 | 是否具备真实交易可行性 | 否，且写明「**不得由第 3 层推出**」 |

第 4 层不给数字，只给「没检验什么」：容量、冲击成本、借券可得性、实盘滑点。
