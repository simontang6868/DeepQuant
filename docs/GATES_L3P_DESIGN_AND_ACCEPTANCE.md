## 1. 为什么要多这一级

单标的 L3 的结论里带着一条已登记的限制：**27 折并不独立，因为只有一条价格路径**。这条限制会让"折间不一致"这个结论无法归因——它可能是策略本身的性质，也可能只是这一只股票的运气。

组合化能回答的是后者，但要先说清它**不能**回答什么：

> **组合化降低的是横截面特异噪声，不降低共同因子风险。** 28 折仍是同一段历史的不同切片，折间仍共享市场体制。所以这条限制没有被"解决"，只是被"缩小到只剩共同因子"。任何把它说成"折已独立"的表述都是错的。

## 2. 三条口径决策（每条都排除了替代做法）

### 2.1 共享现金池，不是"把各标的收益平均"

把各标的的收益取平均，等于假设资金可以无限分摊、没有整手与现金约束。这正是项目已经踩过的坑（`weight_mae` 抓不住现金残留）。所以直接复用 `run_portfolio_backtest`：单一现金账户、同一执行日先卖后买、连续净值、逐日盯市。

验收标准 1 用一个可精确计算的反例把这件事钉死：

| 口径 | 结果 |
|---|---|
| A 涨 20%、B 跌 20%，权重 0.8 / 0.2 | |
| 共享现金池（正确） | **+12.00%** |
| 各标的收益等权平均（错误） | **0.00%** |

两者差 12pp，而且错误的那个"看起来完全正常"。

### 2.2 事件信号 → 状态重建

`MaCrossStrategy` 只在交叉当天给信号。月末调仓时，"当天恰好交叉"几乎不会发生——直接用事件序列选股，组合会静默变成全现金。

所以信号先重建为持仓状态：**持有到反向信号为止**。这不是换策略，而是换读法——单标的引擎本来也是收到 BUY 后持有、收到 SELL 才平仓。

验收里有一条**反证**：一条只在第 4 天出 BUY、之后全是 HOLD 的序列，按事件口径月末全是 HOLD（选不到票），按状态口径月末全是"持有"。

### 2.3 每折在窗口首日补一次建仓信号

月度调仓意味着折首最多空仓 29 天。这段现金拖累会把折收益系统性压低，且与单标的 L3 不可比。补一个首日信号，让组合从折的第二天起就有持仓。

## 3. 标的池：冻结、可复现、含生存偏差

验收标准 6 会用同一份冻结规则重跑抽样，确认能复现同一名单（30/30 一致）。

## 4. 判据同源

判定链**不重写**。`decide_from_summary` 只吃折级汇总，L3 与 L3p 共用同一个函数对象（验收里直接断言 `l3p.decide_from_summary is l3.decide_from_summary`）。

理由很实在：各写一套判据必然漂移，最后会变成"哪个闸门宽松就引用哪个"。终态只换前缀（`L3_*` → `L3P_*`），让报告能一眼看出结论出自哪一级。

**阈值也完全一致**（`train=504 / test=126 / step=126`，`min_folds=8`，正收益折 ≥60%，中位 WFE ≥0.3）。

## 5. 真实用例：ma_cross / 30 只等权 / 2010-01 → 2026-10

组合日历取标的池交易日的**并集**（某只停牌而其他照常交易的日子仍在），共 4,074 天，切出 **28 折**。

| 项目 | 结果 |
|---|---|
| 折数 | **28**（全部完成，0 折失败） |
| 训练窗正收益折 | **85.71%**（24/28） |
| 测试收益 均值 / 中位 | **+5.28%** / **+4.94%** |
| 测试收益范围 / 标准差 | −26.35% ~ +36.42% / 13.99% |
| 正收益折 | **19/28 = 67.86%**（阈值 60%） |
| 「训练正、测试负」 | 9/28 = 32.14%（阈值 50%） |
| 中位 WFE | **0.1361**（24 个可算折，阈值 0.30） |
| 训练收益均值 | +47.48% |
| 测试回撤中位 / 最大 | 12.40% / 38.88% |
| 平均持仓数（折中位） | **12.0** 只（7.3 ~ 16.7） |
| 参数集 / 稳定性 | 10 个 / **42.86%**（最常见 `{10, 15}`） |

**判定链结论：`L3P_REJECTED_INCONSISTENT_FOLDS`。**
失败项只有一条：**中位 WFE 0.136 < 0.30**。正收益折占比这次过了（67.86%），说明"每半年赚不赚钱"这个维度组合化确实改善了；但"赚到的比例"仍然很低——训练窗平均 +47.48%，测试窗只有 +5.28%，保留不到三成。

**最终终态 `L3P_BLOCKED_PREREQUISITE`**：L1a 被否、L1b/L2/L3 都未放行，按逐级闸门原则不构成放行结论；判定链自身的结论保留在 `preliminary_verdict` 与报告头部。

## 6. 与单标的 L3 的对照：改善在哪、没改善在哪

| 指标 | 单标的 L3（000001.SZ） | 组合 L3p（30 只） |
|---|---|---|
| 折数 | 27 | **28** |
| 测试收益均值 | +4.00% | **+5.28%** |
| 测试收益标准差 | 11.96% | 13.99% |
| 正收益折占比 | **51.85%** | **67.86%** |
| 「训练正、测试负」占比 | 37.04% | **32.14%** |
| 中位 WFE | 0.0000 | **0.1361** |
| 测试回撤中位 | 10.10% | 12.40% |
| 参数稳定性 | 18.52% | **42.86%** |

**两组数字不能逐折对齐**：组合日历是并集（4,074 天），单标的用的是 000001.SZ 自己的交易日；折数与折边界都不同。所以只能比"折级统计的形状"，不能比"第 k 折谁更好"。

能读出来的三件事：

1. **"每半年赚不赚钱"确实改善了**：51.85% → 67.86%。
2. **"赚到的比例"仍然很差**：中位 WFE 0 → 0.136，都远低于 0.30。组合化没有解决"训练期行情不可复制"这个根本问题。
3. **参数稳定性翻倍但仍不高**：18.52% → 42.86%，最常用参数 `{10, 15}` 只出现在 12 折。

## 7. 最刺眼的一条：对照臂说「选择」没有贡献

对照臂的设计很简单：**同池同期，每期等权持有全部 30 只，不做任何选择**。两条臂共享同一份费用、撮合与现金账户，所以收益差就是"选择"的贡献。

| 指标 | 值 |
|---|---|
| 可比折数 | 28 |
| 策略折收益均值 | +5.28% |
| 对照臂折收益均值 | **+5.02%** |
| 超额（策略 − 对照）均值 | **+0.26pp** |
| 超额中位 | +0.88pp |
| 跑赢对照的折 | **14/28 = 50.00%** |
| 策略臂现金占比中位 | 11.71% |
| 对照臂现金占比中位 | **14.89%** |

**只报 +0.26pp 会严重误导**：策略臂的现金占比比对照臂**低** 3.18pp（它更满仓），所以这个"正超额"里混着"投入比例差"。把两臂的现金拖累各自折算掉之后：

| 口径 | 策略 | 对照 | 差 |
|---|---|---|---|
| 原始折收益均值 | +5.28% | +5.02% | **+0.26pp** |
| 每单位投入资金（粗算，28 折） | +20.89% | **+28.77%** | **−7.87pp** |

**符号翻转。** 折算后策略明显更差。这条已写进报告的 §六 并单独加了一句提示，不允许只引用那个 +0.26pp。

这条与项目已有的 SP-5 归因结论（`F3_BUY_SIDE_ZERO`：2023 起买入端增量为零）方向一致：**收益来自持有这批股票，不来自"快线在上才持有"的过滤**。

### 7.1 现金残留从哪来

策略臂 11.71%、对照臂 14.89%——都不低。已定位到三个来源：

1. **窗口首日必然全现金**（1/126 ≈ 0.79% 的地板）。
2. **停牌/缺价**：目标权重买了但当天没有有效价格 → `no_price` 阻挡，现金留着。
3. **权重上限 0.20 在只选出 3–4 只时逼出 60%–80% 现金**——这是设计选择（集中度限制），不是数据问题。

第 3 条解释了为什么策略臂在某些折现金占比高达 32%：那些折里"快线在上"的标的只有 3–4 只。**上限是跑之前写定的 0.20，没有因为看到结果而调整**；想看不设上限的版本，是一个需要重新预登记的新实验。

## 9. 踩坑记录

1. **`parents[2]` 指到了 `backend/` 而不是仓库根**，端到端测试的 5 个用例被 `pytest.skip` 成绿色。`s` 不如 `F` 刺眼，但"全绿"里少跑了一半。教训：**测试里的路径要断言存在，不要靠 try/skip 兜底**。
2. **现金占比高得不正常（11.7%）先被怀疑成引擎 bug**，查下来是三个来源叠加，其中权重上限是主因。**但诊断脚本自己漏传了 `max_weight_per_asset`**，导致同一折复算出 −0.0801 而存档是 −0.0766——差点被当成"引擎不可复现"。修正后逐位一致（−0.076605）。教训同 L3：**复算时参数必须与主跑逐项相同，否则"对不上"是脚本的错**。
3. **组合日历是并集，折数与单标的必然不同**（28 vs 27）。第一版文档里差点写成"同样 27 折"，会被读成"两条曲线可逐折对应"。
4. **`PortfolioSpec` 若不进契约，调用方传 `HypothesisSpec` 时这段配置会被静默丢弃**——与 L1b 的 `execution` 字段是同一类坑。已加 `HypothesisSpec.portfolio`（只在非空时写进 `to_dict`，保住既有契约的 `spec_digest`）。
5. **只报 +0.26pp 是选择性报告**。两臂现金占比不同，必须先折算再下结论；折算后符号翻转，这正是"看起来有利的数字要先找它的口径"的例子。

## 10. 未完成与限制

- **组合化不解决共同因子风险**：28 折仍共享市场体制，不能称"折已独立"。
- **生存偏差**：池为当前快照，结果只能作上界估计。
- **30 只 ≠ 全市场**：名单已冻结，换种子会得到不同结论；结论只能限定在这份名单上。
- **weights 记账不受整手约束**：不产生整手现金残留，因此收益与资金规模无关（有测试守着）。可执行性需另用 `lots` 口径复核，那是新实验。
- **单标的口径不可逐折对照**：折数、折边界都不同，只能比折级统计的形状。
- **对照臂不是可投资基准**：它每期全换手、不做成本优化，只用于隔离"选择"的贡献。
- **权重上限 0.20 会逼出空仓**：不设上限的版本需要重新预登记，不能拿本次结果反推。
- **未接事件驱动内核**：与 L3 一致，走日线引擎；L1b 的参与率/排队/冲击模型未参与。
