# 检查器 / 变异测试分类与执行规范（2026-11-19）

> 来源：专家审查 H9 修复阶段性报告的四项裁决（Q2/Q3），经账户持有人授权纳入规范。
> 适用范围：本项目所有判据邻接 bugfix、所有变异测试与检查器。
> 性质：流程规范，不是判据变更；不改变任何既有门控阈值或口径。

---

## 1. bugfix vs 判据变更：三零一不变判别式（专家 Q2）

修复属于 **bugfix（不需新预登记）** 当且仅当同时满足：

| # | 条件 | 含义 |
|---|---|---|
| 零 1 | 判据**文本**零改动 | 预登记/授权里的判据描述不变 |
| 零 2 | **阈值**零改动 | 门限、容差、时间窗一律不变 |
| 零 3 | **判定函数**零改动 | 做判定的函数体不改（只改喂给它的输入） |
| 一不变 | 对修复前**已可解析的合法输入**，判定结果不变 | legacy 兼容测试即此证明 |

形式化：修复只把"永远到不了判定函数的垃圾输入"变成合法输入；判定函数本身
及其对合法输入的行为未动。**恒 UNPARSEABLE / 恒 FAIL 从来不是预登记意图——
修复是恢复意图，不是修改意图。**

> 反面：若改动判定函数体、阈值，或对原合法输入的判定结果变了 ⇒ 判据变更，
> 必须新预登记 + 书面授权。此判别式必须显式引用，防止豁免被惯性滥用。

**H9 实例**：只改 `paper_account_adapter._plain_value`（输入序列化），
`sim_reconcile.check_exec_timestamps`（判定函数）零改动、阈值 ±10min 不变、
旧 ISO 输入判定不变 ⇒ 符合三零一不变，定为 bugfix。

## 2. 变异测试两条强制规则 + 三态结局（专家 Q3）

### 2.1 规则一：金丝雀前置（canary）

每次变异运行**必须**先证明"变异体是活的"：直接调用被变异单元，在一个已知
输入上，变异体必须与基线产生**可观测差异**。金丝雀不过 ⇒ 该次运行判
**VOID（无效实验）**，不是 MISSED。

- `MISSED`：金丝雀已过（变异体活着），但测试仍全绿 ⇒ 有信息量：测试覆盖不足。
- `VOID`：金丝雀没过（变异体没真正生效或被覆盖）⇒ 无信息量：实验根本没做。
- `DETECTED`：金丝雀过 + 测试变红 ⇒ 变异有效且被检出。

**混淆 MISSED 与 VOID 会污染变异分数**；更危险的是从坏实验（VOID）得出
"测试没问题"的结论。

### 2.2 规则二：直接调用被测单元

变异探针必须 `importlib` 按文件路径加载变异副本并**直接调用**，禁止经会
`sys.path.insert` 原文件的 pytest 收集路径。

> 实证（2026-11-19）：`created_at_fix_mutation_test.py` 首版经 pytest 收集，
> 测试文件顶部 `sys.path.insert(0, "scripts")` 令 pytest 重新 import 磁盘原文件，
> 覆盖注入的变异模块 ⇒ 探针实际测的是原实现 ⇒ 假 MISSED（实为 VOID）。
> 改为直接调 `_probe(mod)` 后 DETECTED。

### 2.3 三合一退出条件

变异脚本退出码必须同时满足：`base_ok ∧ detected ∧ sha_stable`。
任一不满足 ⇒ 非 0。`sha_stable` 保证变异未污染源文件（恢复后哈希逐位一致）。

## 3. 普适条：任何检查/变异必须带阴性对照（专家 Q3 泛化）

这是"仪器不测它声称的东西"错误类。两类同构实例：

- H9：验收判据因格式不匹配**恒假**——检查器声称在测时点，实际永远到不了判定。
- 假变异：探针声称在测变异体，实际 import 了原文件——仪器测错了对象。

**强制**：每个检查器/变异都必须有阴性对照——一个**已知坏输入必须被检出**；
若坏输入也通过，则检查本身无效，不得计入 PASS。对应项目铁律
「没检出 ≠ 没问题」。

## 4. 落地检查清单（实施新检查/变异前逐条过）

- [ ] 若改了判据邻接代码：用 §1 三零一不变判别式分类，bugfix 也要显式记录判别过程。
- [ ] 金丝雀前置存在，能区分 DETECTED / MISSED / VOID。
- [ ] 探针直接调用被测单元，不经 pytest 收集路径。
- [ ] 退出条件含 sha_stable，变异后源文件哈希恢复。
- [ ] 至少一个已知坏输入的阴性对照，证明检查会红。
