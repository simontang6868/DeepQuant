## 1. 结论（分两层，不要只看第一层）

**第一层｜在当前约束下，自研方案明显更合适。** 当前约束是：单市场（A 股）、日频、无实盘接入、已有 T1–T6 与 L1a 契约。在这个范围内，自研在交付成本、合规、集成成本、可复现性四项上有决定性优势，在成交保真与能力覆盖上落后但落后得不多（因为外购的优势需要分钟/逐笔数据才能真正兑现，而我们没有）。

**第二层｜这个结论不能外推。** 一旦约束改变——要接实盘、要上多资产、要分钟频、要订单簿级保真——外购的两项优势（D3 成交保真、D5 能力覆盖）会立刻从"用不上"变成"补不上"，而自研要补这两项需要重做撮合与数据层。所以本次结论的适用范围必须与当前约束绑定。

**一句话**：不是"NautilusTrader 不好"，是"我们现在的数据与需求，配不上它的能力，也付不起它的适配成本"。

## 3. 逐维说明：哪些是实测，哪些是推断

### 3.1 自研侧的分数全部来自实测

- D1：本轮实际交付物在这台机器上跑通，测试数与验收项可复算（`reports/L1B_GATE_EVIDENCE.json`）。
- D2：**这是唯一一个"两面都摸过"的维度**。同一 `MaCrossStrategy(fast=3, slow=60)` 对象在日线引擎和事件驱动内核上各跑一次，46 笔成交的日期/方向/数量/价格逐笔一致，期末权益同为 202,311.04。但它只证明了"两种回测口径同构"，**没有证明"回测与实盘同构"**——我们没有实盘，所以给 2 不给 4。
- D3：明确是 bar 级参数化模型。内核自己在 `limitations` 里写了"不重建订单簿，排队位置是参数不是观测值"。
- D4/D6/D7/D8：代码事实与产物事实，可直接复核。

### 3.2 外购侧有五个维度是"未实测"

| 维度 | 未实测的具体内容 |
|---|---|
| D1 | 6 人周是**预算**，不是实际投入；实际可能更短也可能更长（第三方一致反映文档是短板） |
| D2 | "三模式复用"是其架构声明，我们没有跑过一个策略在三种模式下的表现 |
| D3 | FillModel 库的存在是核对源码得到的事实，但**没有在我们的数据上配置过、也没有比对过结果** |
| D7 | A 股适配器需自研，工作量未估；与其事件总线共存更是纯推断 |
| D8 | 没有产物 |

按本项目"不编造"的纪律，这五项只能标 `未实测`。**把未实测分数当真，就是拿别人的宣传材料做自己的技术决策。**

### 3.3 一个容易被忽略的对称性

外购方案的 D3 优势（3 分）建立在"模型库更丰富"上，但**默认配置是乐观的**：`prob_fill_on_limit=1.0` 意味着永远假设自己在队首，`prob_slippage=0.0` 意味着零滑点。也就是说，如果不显式配置，它的"保真"和我们关掉摩擦的内核一样乐观。

真正的差别是：**它提供了更多的模型可选，我们只提供了三个**。这是覆盖度差距，不是有无差距。而覆盖度差距在我们只有日线数据的前提下，兑现不了。

## 4. 这个分数不能说明什么（重要，比分数本身重要）

1. **不能说明"自研更先进"**。自研只做了 3,798 行、单市场、日频、单标的。它在能力面上是**更窄**的，不是更强。
2. **不能说明"外购不划算"**。如果需求变成多资产或实盘，外购的 D3/D5 会直接从"用不上"翻成"必须有"，而自研要补这两项是重做量级的工作。
3. **不能跨约束比较**。8 个维度里 D5 的口径就是"单市场日频 = 2 分"，这等于**在评分表里就写进了"我方当前是单市场日频"这个前提**。换个前提取同样的表打分，结论会变。
4. **未实测项不应参与决策**。26 : 19 这个差距里，至少有 9 分来自外购侧的"未实测"，那部分不是"它差"，是"我们不知道"。

因此正确的用法是：**把这张表当作"当前约束下的可行性判断"，而不是"技术选型排名"。**

## 5. 什么情况下应该重启方案一

给出可判定的触发条件，而不是"以后再看"：

| 触发条件 | 为什么它会改变结论 |
|---|---|
| 拿到分钟级或逐笔行情数据 | D3 的差距立刻兑现：有数据才能让它的 FillModel/LatencyModel 有用，而我们的 bar 级模型无法利用更细的数据 |
| 需要接实盘通道 | D2 的差距兑现：我们完全缺这一段；且 T1–T6 的审计/风控要重新对接 |
| 策略扩展到多标的组合 | 自研的单标的撮合需重做共享资金与流动性竞争，工作量接近重写 |
| 团队规模扩大到 3 人以上且有长期维护预算 | D6 的"自持成本"优势会被稀释，外部社区的分摊价值上升 |

**若触发，第一步不是立项，而是做那件最便宜的事**：用现有内核作为参照物，跑一次"同策略、同区间、无摩擦配置"的双引擎对比（`ENGINE-OPTION-A-001` §5 的 W2 任务）。现在这个参照物已经有了——这正是本轮最实际的产出之一。

## 6. 本轮对比的方法论复盘

| 做对的 | 说明 |
|---|---|
| 维度在动手前冻结 | K0 于 2026-10-27 写定 8 维与口径，K5 才打分。若事后按结果设计维度，就是选择性报告 |
| 同时报原始分与合计 | 合计值掩盖未实测项，原始分让读者自己判断哪些分可信 |
| 方案一实测为 0 也照实写 | 没有把"公开文档"当成"已验证" |

| 做得不够的 | 说明 |
|---|---|
| 外购侧的 6 人周没有实际执行 | 严格说 D1 的 2 分是"预算推算"，若真跑一遍可能得到不同结论 |
| 只有一个用例（ma_cross / 000001.SZ） | 自研侧的可维护性判断基于 3,798 行，样本很小 |
| D2 只验证了"回测↔回测" | 真正的价值主张是"回测↔实盘"，这部分双方都没有证据 |
