# DeepQuant 可用版：怎么启动、能做什么、验证到哪一步

> 交付时间：2026-10-18 19:55 GMT+8
> 形态：**单端口本地应用**。双击一个 `.bat`，浏览器自动打开，无需再开第二个终端。
> 相关：`backend/src/deepquant/api/ui.py`、`scripts/start_deepquant.py`、`start_deepquant.bat`

## 1. 怎么启动（三种方式，任选一种）

```text
方式 A（推荐，双击）
    D:\DeepQuant power by txm\DeepQuant-main\start_deepquant.bat

方式 B（命令行）
    python scripts/start_deepquant.py

方式 C（只自检，不启动）
    python scripts/start_deepquant.py --check
```

启动后：

| 用途 | 地址 |
|---|---|
| 界面 | `http://127.0.0.1:8123/`（端口被占用会自动顺延，控制台会打印实际地址） |
| API 文档 | `http://127.0.0.1:8123/docs` |
| 健康检查 | `http://127.0.0.1:8123/health` |

停止：控制台按 `Ctrl+C`，或关掉那个窗口。

## 2. 界面上能做什么

| 功能 | 说明 |
|---|---|
| 选数据集 | 已登记 5 只 A 股日线（`000001.SZ` `000858.SZ` `600519.SH` `600900.SH` `601318.SH`，2017-01-03 ~ 2024-12-31，各 1943 行） |
| 选策略与参数 | 目前注册 1 个：`ma_cross` 双均线交叉（`fast_window` / `slow_window`） |
| 设资金与区间 | 初始资金、起止日期、信号延迟 |
| 看结果 | 净值曲线、回撤曲线、绩效卡片、成交明细、委托明细、账户状态 |
| 历史记录 | 每次回测落 SQLite（`backend/data/backtests.db`），可回看、可比较两组 |
| 完整性 / 可复现 | 单次运行的完整性校验与可复现清单，界面上能直接点 |

**已实测的一条完整链路**（不是「应该能用」）：`000858.SZ` × `ma_cross(10, 60)` × 20 万 ×
2020-01-01~2024-12-31 → `24` 笔成交、`1212` 个账户状态点、年化 `10.11%`，
历史/完整性/可复现三个接口均 200。

## 3. 这一版新增了什么（相对「两个终端 + 开发服务器」）

| 项 | 之前 | 现在 |
|---|---|---|
| 启动 | 终端 1 起 uvicorn(8123) + 终端 2 起 `npm run dev`(5173) | **一个进程、一个端口** |
| 前端来源 | Vite 开发服务器（未压缩、需 node 常驻） | `frontend/dist` 构建产物（629 KB JS） |
| `/api` 前缀 | 靠 Vite 代理转发并去前缀 | 服务端 `StripApiPrefix` 中间件去前缀 |
| 端口冲突 | 用户自己看 traceback | 自动顺延并打印实际地址 |
| 数据根 | 默认 `backend/data/`（**空的**，数据集在仓库 `data/`） | 启动器自动挑「已登记数据集」的目录 |
| 浏览器 | 手动打开 | 健康检查通过后自动打开 |

其中「数据根」一条是本次最容易踩的坑：默认值指向 `backend/data/`，而数据集实际在仓库
`data/`。不修的话界面长得完全正常，只是数据集下拉框空着——那种状态最容易被误判成
「软件坏了」，所以启动器把它当成错误处理（`--check` 会以退出码 1 报告）。

## 4. 交付边界（必须知道的三件事）

1. **这是单机研究工具，不是交易系统。** 不连券商、不下单、不接实时行情。
2. **费用与滑点是模拟占位参数**（`fee_source=simulation_placeholder`，佣金万 3）。
   响应里会带 `fee_source` 标明来源，不要当成真实费率。
3. **只能用已登记的数据集。** 新增标的要走导入流水线（`deepquant.data.pipeline`），
   不支持在界面上传文件——这是刻意的：API 不接受客户端提供的任何文件系统路径。

## 8. 复审记录（2026-10-18 20:35）：11 处问题与修复

### 8.1 最重要的一条：默认引导参数跑出 0 成交

按 `START_HERE.md` 的三步（`600519.SH` × `ma_cross(5,20)` × **10 万** × 2021–2024）：

```
n_orders = 60   n_filled_orders = 0
30 × BUY  rejected  insufficient_cash
30 × SELL rejected  insufficient_position
final_equity = 100,000    cumulative_return = 0.00%
```

一条横线，而界面写着「回测完成」。同参数换 100 万本金：**59 笔成交，期末 814,728，
−18.53%**——同样的信号，差别只在买不买得起 1 手（茅台 1 手约 20 万）。

修法两处：**默认资金改 100 万** + **新增「0 成交」提示**（拒单原因分布 + 整手规则 +
可执行建议）。这条提示在用户自己把资金改回 10 万时同样生效。

## 9. 数据池接入（2026-10-18 21:0x）：界面可用数据集 5 → 51

完整报告见 `docs/DATASET_POOL_2026-10-18.md`。这里只记与本交付有关的结论。

### 9.1 做了什么

`scripts/import_pool.py` 把 `b50_v3` 的 50 只 qfq 行情导入成可用数据集：

| 状态 | 只数 | 说明 |
|---|---|---|
| `imported` | 46 | `source.name = b50_v3/<code>.qfq.csv` |
| `enriched` | 2 | `000001.SZ`/`600900.SH` 早已从 `step75/` 导入，sha256 与池内文件相同，只补名称 |
| `rejected` | 2 | `000568.SZ` `invalid_price(1)`、`600809.SH` `invalid_price(131)` |

界面因此有 **51** 个数据集 = 池内 48 只 + 早先手挑的 3 只（`600519.SH`/`000858.SZ`/`601318.SH`）。

### 9.2 四条「看起来成功其实不对」的处理

1. `--pool-dir` **必填**：池在仓库外，写死相对路径只在某台机器成立；
2. **先验 sha256 再读文件**：版本对不上就拒，不导入另一版行情；
3. **价格非正不修**，交闸门拒绝并记录错误码；
4. 同 sha256 → `unchanged`（不重写、mtime 不变），不同 → `conflict`（不覆盖，退出码 1）。
   研究线跳过而闸门放行（或反之）→ `disagreements` + 退出码 1。

### 9.3 名称与筛选（48 项下拉框要用得了）

- 元数据新增可选 `instrument.display_name`，API 新增 `display_name` 字段；
  写入端与读取端共用 `data/instrument.py` 同一份规则（分开写就会出现「写得进去、读不出来」）；
- 名称**只进元数据，不参与计算**；历史元数据没有该键 → 照常可用，界面回落显示代码；
- 数据集超过 12 个时出现筛选框（按代码或名称）；**被筛掉的当前已选项仍保留**，
  否则 `<select>` 值找不到 option，下拉框显示空白而表单里其实带着代码。

### 9.4 验证

| 检查 | 结果 |
|---|---|
| `/api/datasets` | 51 条、`invalid_datasets` 0 条、51 条都有名称 |
| `601398.SH` × ma_cross(5,20) × 100 万 × 2020–2024 | 200，77 笔成交，+25.58%，年化 4.85% |
| `688271.SH`（2022-08 起 573 行）× 同参数 | 200，573 个状态点（区间被真实数据截断） |
| `000568.SZ` 回测 | 404 `dataset_not_found` |
| 后端 | **1675 passed / 1 skipped / 7 xfailed / 0 failed**（1611 + 本轮 46 + A 线 walkforward 契约 18，含 1 xfail） |
| 前端 | **168 passed（16 文件）**（162 + 6） |

### 9.5 这一版之后仍然不解决的

池是 **2026-10 的成分股快照**（幸存者偏差照旧）；区间只有 2017–2024；

界面里没有 `600809.SH`，所以 Gate 1 的「排除该标的」对照无法在界面上复现。

## 10. 组合回测 + 不可用标的可见（2026-10-18 23:0x）

§9.5 列的五条遗留里，这一轮处理了两条、把两条改成「可核对的事实」、一条不动。

### 10.1 多标的组合回测（上一版第 3 条：只能单标的）

新增 `POST /portfolio-backtests` 与界面上的「组合回测」标签页。

- 引擎没有新写：走 `backtest/portfolio.py` 的 `run_portfolio_backtest`（共享现金池、
  卖出先于买入、停牌冻结估值、涨跌停顺延），`api/portfolio.py` 只做接线；
- 默认参数即 Gate 1 主实验口径（月度调仓 / 动量 60·5 / 等权 top 20% /
  `min_assets=5` / 初始 100 万 / flat 10% 涨跌停），因此界面默认跑出来的结果与研究
  报告同口径；改任何字段都会在 `limitations` 里标注偏差；
- 界面有「标的多选（可搜索 / 全选）」、选股口径（动量 / 全池等权）、
  记账方式（权重 / 整手）、资金与区间；结果含绩效、净值曲线、被阻挡订单、
  成交明细、`limitations` 原文、逐标的数据指纹。

**实测**（51 只 × 2019-01-02 ~ 2024-12-31，100 万）：

| 口径 | 累计 | 年化 | 最大回撤 | 成交 / 被阻挡 | 耗时 |
|---|---|---|---|---|---|
| 动量 top20%（正式口径） | +168.76% | 18.66% | 45.72% | 938 / 47 | ~5 s |
| 全池等权 | +207.55% | 21.46% | 21.49% | 3132 / 164 | ~5 s |
| 动量 + 整手记账 | +165.52% | 18.41% | 45.06% | 912 / 74 | ~5 s |

三种口径 `consistency_issues` 均为 0 条。证据等级 `low`（51 只 < 100），
系统自己标注「不足以支撑策略结论」。

### 10.2 不可用标的可见（上一版第 4 条：界面没有 600809）

`GET /datasets` 新增 `unavailable_datasets`，列出**导入时被闸门拒绝**的标的：

```json
[{"symbol":"000568.SZ","display_name":"泸州老窖","reason":"invalid_price(1)"},
 {"symbol":"600809.SH","display_name":"山西汾酒","reason":"invalid_price(131)"}]
```

与 `invalid_datasets` 的区别写进了 schema docstring：那个是「元数据已存在但坏了」，
这个是「从未入库」。它只解释缺失，不能用来回测（仍 404）。

**更准确的说法**：界面里的 51 只**已经等于**「排除 600809 与 000568」的池，
所以 Gate 1 那条「排除对照」在软件里无法复现的原因是**缺干净数据**，
不是缺功能。

### 10.3 区间上限与幸存者偏差：改成可核对的事实

- 区间停在 2024-12-31 是**数据源上限**，已实测：50 个原始 CSV 全部止于该日；
  `/datasets` 新增 `coverage`（起止、条数、不可用数、一句说明），
  组合结果里也有 `coverage.note` + 逐标的 `symbol_end_dates`；
- 幸存者偏差**没有解决**（无历史成分股数据），但不再只写在文档里：
  `/datasets` 的 `coverage.note`、组合结果的第一个 banner、`limitations` 三处都有。

### 10.4 顺手修掉的真 bug

3 只等权回测稳定抛 `组合回测内部一致性检查失败`：`total_equity` 是
`round_money(cash+mv)`，与未舍入和恰差 0.01 时浮点表示是 `0.0100000000093`，
旧代码 `> 0.01` 判成不一致（实测 59 个交易日全中）。改为
`ACCOUNTING_TOLERANCE = MONEY_EPS + 1e-9`，并加 5 条回归测试锁住
「一分不报、两分仍报」。
