# L3s 截面信息含量检验：设计与验收

- 实验 ID：`H-L3S-IC-000001`
- 预登记：`docs/gates/l3s_prereg.json`，sha256 `61929483c81d78a6b9acefae247b7197dfa8d142587fc02b4261edf167718dc5`
- 产物：`reports/gates/H-L3S-IC-000001/{l3s_result.json,l3s_report.md}`、`reports/L3S_IC_EVIDENCE.json`
- 模块：`backend/src/deepquant/gates/ic_test.py`｜CLI：`scripts/l3s_ic.py`｜测试：`backend/tests/gates/test_gates_ic.py`（13 项）
- 成熟度：M0｜**diagnostic_only = true**（诊断实验，不是闸门）

## 1. 要回答什么

L3r 把「选股有没有用」这个问题判定为 `INCONCLUSIVE_POWER`：MDE 0.926pp、事后功效 16.87%。
L3s 换一把尺子再问一次：**把池内数百只标的按「快慢线乖离」排序，排名靠前的下一期是否真的涨得更多。**

这不是同一个问题的复述，而是同一问题的**另一种测量方式**：

| 维度 | L3r（R2 截面） | L3s |
|---|---|---|
| 截面标的数 | 24（30 只池中可定价者） | 378（518 只全池） |
| 信号形式 | 0/1 持有状态 | 连续分数 `fastMA/slowMA − 1` |
| 统计量 | 选中组与全体的收益差 | 秩相关 IC + 五分位剖面 |
| 用途 | 判断组合有没有超额 | 判断**指标**有没有排序能力 |

## 2. 事前更正：我上一轮说错了一件事

上一轮我对用户说「改用截面 IC 与分组单调性，标准差会低一个量级，功效可以从 17% 拉到可用区间」。
写预登记时先做算术，发现这句话在 24 只截面上是**错的**：

- 二元信号下 IC 只是「选中组均值 − 全体均值」的单调变换，**功效完全相同**；
- 即便换成连续分数，N=24 时 se(IC)≈0.21/期、197 期，折算 MDE 也只从 0.926pp 降到约 0.74pp（≈25%）。

真正起作用的杠杆是**扩大截面标的数**（se(IC)∝1/√N），不是「换成 IC」。这条更正写在预登记
`correction_to_prior_claim` 字段里，在跑数之前落盘——避免事后把增益归功于选错的原因。

## 3. 设计

### 3.1 池与口径

- 池：`data/_pool_518_a_share.txt`（518 只，冻结），全部有 qfq 文件，无剔除。
- 跨度：2010-01-01 ~ 2026-10-16，与 L3p 同跨度。
- 折：沿用 L3p 的 28 折。**日历取自 L3p 同一个 30 只池的并集**，脚本启动断言 `len(folds)==28`
  且逐折 `test.start/test.end` 与存档逐字相同，否则拒跑——否则窗口挪一天，`best_params` 就对不上了。
- 参数：逐折沿用 L3p 存档 `best_params`，不重选、不搜索。10 套参数、28 折。

### 3.2 分数与收益

- 分数 `score_i(t) = fastMA_i(t)/slowMA_i(t) − 1`，滚动均值只用 t 及以前的数据。
  预热期（slow 未填满）为 NaN，自然剔除。
- 收益 `r_i(k) = close_i(exec(k+1)) / close_i(exec(k)) − 1`。
  `exec(k)` 是信号日之后的首个交易日；**期收益必须配到下一期的执行日**，
  取「执行日的下一个交易日」算的是 1 日收益，是错的（首版实现踩过）。
- 纳入：分数有效 **且** 期初、期末两端都有价。两端配对剔除，使「缺一端」的标的不只影响一侧。
- 折内最后一期用窗口末日收盘价，与前 27 折口径一致。

### 3.3 统计与判定

- 逐期：Spearman 秩相关；五分位等权收益。
- 汇总：均值、中位、iid t、NW(3) t、胜率、stationary bootstrap 95% CI（reps 2000、块长 3）。
- MDE：`2.8016×se`；折算收益口径 = `MDE_IC × σ_r × E[z|top20]`，`E[z|top20]=1.400`（标准正态上 20% 尾均值）。
- 判定顺序：**先看功效，再看符号**。功效不足时只能报 `IC_INCONCLUSIVE_POWER`，不得报「无信息」。

| 终态 | 条件 |
|---|---|
| `IC_INFORMATION_DETECTED` | mean IC > 0 且 t_nw3 ≥ 1.96 且 单调性 ρ ≥ 0.8 |
| `IC_SIGN_REVERSED` | mean IC < 0 且 t_nw3 ≤ −1.96 |
| `IC_NO_INFORMATION_DETECTED` | \|t_nw3\| < 1.96 且 折算 MDE ≤ 0.30pp |
| `IC_INCONCLUSIVE_POWER` | 折算 MDE > 0.30pp |

不设 `L3S_BLOCKED_PREREQUISITE` 降级：本实验是诊断，不是闸门（否则前序未通过时任何新实验都自动作废，
诊断信息也就永远拿不到）。所有产出强制带 `diagnostic_only=true`。

## 5. 本轮最重要的发现：瓶颈是时间，不是截面

| 量 | 数值 |
|---|---|
| 实测逐期 IC 的 sd | 0.1968 |
| 独立抽样噪声 1/√(N̄−1) | 0.0515 |
| 抽样噪声占方差比例 | **6.85%** |
| 压到 0.30pp 所需期数 | **738 期 ≈ 61 年** |

把截面从 24 只扩到 378 只，只消掉了抽样噪声那一小块（占方差 6.85%）；
逐期 IC 的波动 93% 以上来自**风格轮动**（或截面相关性带来的额外波动）。
因此 MDE 只从 0.926pp 改善到 0.565pp（1.64×），远不到预登记 P6 要求的 3 倍。

**推论（比结论本身更重要）**：在月度频率 + 2005–2026 的数据上，任何「把截面做大、把统计量做精」的
路线都不可能把分辨率压到 0.3pp/月。这个下界由风格轮动的幅度决定，与估计量无关。
L3r 算出「需 56 年」、L3s 算出「需 61 年」，两条独立路径给出同一个量级——这本身就是交叉验证。

## 6. 预测核对：6 条中 2 条成立，4 条被反驳（照原样保留）

| 编号 | 预测 | 实测 | 被反驳 |
|---|---|---|---|
| P1 | 平均标的数 ∈ [350,520]，2010–2012 < 450 | 377.9 / 355.1 | 否 |
| P2 | mean IC ∈ [−0.02, +0.03] | −0.0232 | **是**（略低于下界） |
| P3 | MDE_IC ≤ 0.012 且折算 ≤ 0.30pp | 0.0382 / 0.565pp | **是** |
| P4 | 单调性 \|ρ\| < 0.9 且 spread \|t\| < 2 | −0.100 / t −0.290 | 否 |
| P5 | sd ≤ 1.6×1/√(N̄−1) | 比值 3.82 | **是** |
| P6 | 折算 MDE 至少改善 3 倍 | 1.64× | **是** |

P2/P3/P5/P6 被反驳都指向同一件事：**我低估了逐期 IC 的时间波动**。预登记里 P5 正是为这条设的自检，
它如期抓到了「有效信息量远小于名义 N」。反向说明这个自检设计是有效的——它抓住的不是实现 bug，
而是我先前的模型错了（把截面独立抽样当成了主要噪声源）。

## 7. 已知限制

- 固定名单池含退市与停牌区间，每期只纳入两端有价者 ⇒ 生存偏差，方向不明确。
- IC 序列混合了 10 套参数（逐折 walk-forward），不是单一参数的纯 IC。
- 月度不重叠，但折与折首尾相接处可能有一天重叠；NW(3) 只处理残差自相关。
- 折算系数 `E[z|top20]=1.400` 假设分数与收益近似二元正态，实际分布更厚尾。
- **IC 显著 ≠ 组合有 alpha**：不含费用、整手、涨跌停、现金约束，不得作为可用性证据。

## 8. 变异测试（确认测试真的能抓住错）

按纪律，新判定逻辑必须先证明「测试不是摆设」。两处变异都**真改了程序行为**，且都被抓住：

| 变异 | 改动 | 结果 |
|---|---|---|
| M1 | `decide_ic` 里删掉 `and mde_return <= target_mde`，变成「t 不显著就报无信息」 | `test_decide_ic_requires_power_before_declaring_no_information` 失败 ✓ |
| M2 | `build_period` 里把 `if p0 is None or p1 is None` 改成只查 `p0` | `test_build_period_drops_symbols_missing_either_end` 失败 ✓ |

变异后均已还原（模块 sha256 前缀 `03e42a9661be`），预登记字节未变（`61929483c81d78a6`，6990 字节）。

## 9. 本轮踩到并已修的坑

1. **期收益配对**：首版用「执行日的下一个交易日」，算的是 1 日收益；必须配到**下一期的执行日**，折末用窗口末日。
2. **qcut 索引对齐**：`ret_s.groupby(pd.qcut(...))` 会按索引匹配（股票代码 vs 0..k−1），静默产出全 NaN；
   必须传**数组**（按位置对齐）。这个 bug 会让 spread 变 `None` 而不是报错。
3. **未排序行情**：滚动均值依赖日期升序，加载后应确认 `index.is_monotonic_increasing`（实测 518 个文件全部已升序）。
4. **Markdown 表格里的 `|ρ|`** 必须转义成 `\|ρ\|`，否则表格被劈成两列（L3r 犯过一次，这次改成渲染时统一转义）。
5. **「有值」与「无值」必须分开**：`_value_at` 对缺失日期返回 None 而**不做 ffill**——前值填充会把
   「停牌中」当成「分数仍然有效」，等于假装当天能排序。
6. 独立复算：用 numpy 手写秩相关 + 手写滚动均值复算最负期（2014-12-31，IC −0.6033），
   与模块结果逐位一致；该期五分位收益 +14.3%→−10.3% 严格单调，确认是真实的风格轮动月，
   不是实现 bug。
