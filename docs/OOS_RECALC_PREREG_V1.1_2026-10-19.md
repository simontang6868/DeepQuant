## 1. v1 为什么作废（一分钟版）

写规格时我说"只换价格口径"。这个说法当时是错的：

| | v1 池 `data/step75_ext` | 乘性池 `data/qfq_mult` |
|---|---|---|
| 起始日 | **2017-01-03** | **2016-01-04** |
| 行数（600519） | 2374 | 2618 |
| 跑出来的窗口数 | **29** | **32** |

差了 244 行 = 一整个 2016 年。窗口边界全部错位，训练段也跟着变。
那就不是"只换口径"，是**同时换了样本区间和价格口径两个自变量**——恰恰是本轮要避免的混淆。

**缺陷在写 v1.1 之前发现，v1 那次运行被中途终止，没有产出任何结果文件**（`docs/OOS_RESULTS_RECALC_2026-10-19.json` 不存在）。

```
data/oos_recalc_pool（2016-01-04 起）→ date >= 2017-01-03 且 <= 2026-10-16 → data/oos_recalc_pool_2017
```

三条自证：

1. **逐标的行数与 v1 池逐个相等**：600519 2374 / 000001 2374 / 601318 2374 / 000858 2374 / 600900 2363 / 300750 2025
2. **裁剪只删行不改数**：裁剪前 vs 裁剪后在重叠日逐列最大数值差 **0.0000000000**
3. **窗口数应为 29 / 29**，与 v1 的 `window_structure` 逐只一致 —— 这是结构性检查，不等就作废重来
