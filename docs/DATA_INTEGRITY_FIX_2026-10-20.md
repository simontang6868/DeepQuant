> 触发：回补 2005-2015 行情时，在**看任何收益数字之前**对 EXEC/ADJ 做完整性检查。
> 结果查出两个实质缺陷 + 一处旧批次截断。本文记录证据、修复方式、残余风险。
> 关联：`docs/GATE3_REVERSAL_LONGSAMPLE_PREREG_2026-10-20.md` §0.1、§2.3

## 0. 一句话结论

**宽池 549 只里有 249 只（全部退市股）的 ADJ 从未复权**——东财分红表对它们返回空，
而 A4 判据对"零事件"标的不适用，于是这 249 只既没被调整、也没被检查。
3-A 报告的"548/549 通过（99.8%）"中，**其中 249 只是免检通过**。
修复后池子重算为 **532 只**（剔除 17 只），Gate 2 的 2016-2026 结果随之改变。

## 1. D-1：东财分红表对退市股全空

### 1.1 证据

```
data/exec/_div_cache/ 共 549 个文件，其中 249 个内容为 []
这 249 个 = data/qfq_mult/delist/ 的 249 只退市标的（完全重合）
```

接口层复核（东财 `RPT_SHAREBONUS_DET`，分别用 `SECURITY_CODE` 与 `SECUCODE` 两种过滤）：

| 过滤方式 | 000005.SZ（退市） | 000616.SZ（退市） |
|---|---:|---:|
| `SECURITY_CODE="xxxxxx"` | 0 行 | 0 行 |
| `SECUCODE="xxxxxx.SZ"` | 0 行 | 0 行 |

→ **不是我们的参数写错，是东财该报表不含退市标的**。

### 1.2 后果（为什么这不是"小瑕疵"）

`rebuild_adj_from_exec.py` 的 A4 判据有一条豁免：

```
③ 【零分红事件】ADJ ≡ EXEC，根本没有做调整——此时 A4 检验的对象不存在，不适用。
```

即：**事件表为空 → 跳过涨跌停检查**。两个缺陷叠加后：

1. 这 249 只的 ADJ **就是未复权原价**；
2. 它们**从未被任何涨跌停判据检查过**（A4 直接不适用）；
3. 每次 10送10 / 10转10 都会在 ADJ 里留下 **−50% 的假跌幅**。

**实证（000616.SZ）**：

| 除权日 | 真实方案 | ADJ 里的单日涨跌 | 该日是否被 A4 检查 |
|---|---|---:|---|
| 2008-05-09 | 10送2转3派0.3 | **−37.69%** | 否（零事件豁免） |
| 2009-04-23 | 10转5派0.5 | **−33.77%** | 否 |
| 2010-06-01 | 10转1派1.0 | **−12.80%** | 否 |
| 2011-05-25 | 10转2派1.0 | **−20.90%** | 否 |
| 2013-05-28 | 10转2派0.4 | **−16.41%** | 否 |

这五天的"暴跌"全部是除权，不是价格行为。对反转策略尤其致命：
**买"跌得多"的多头腿会系统性地把这些假输家选进来**。

### 1.3 修复：新增新浪 F10 事件源

`scripts/fetch_dividends_sina.py` → `data/exec/_div_cache_sina/`

- 数据源：`https://money.finance.sina.com.cn/corp/go.php/vISSUE_ShareBonus/stockid/<6位代码>.phtml`
- 解析 `id="sharebonus_1"` 表：公告日期 / 送股 / 转增 / 派息(税前) / 进度 / **除权除息日**
- 单位与东财一致（每 10 股），直接 /10
- **抓取结果：549/549 成功，0 错误**，仅 1 只零事件
- 覆盖性抽样：000616（20 个事件，起 1997）、000540（16 个事件，起 1995）、000001（30 个事件，起 1991）

重建改用 `--div-source merge`：

| 情形 | 用哪个源 | 理由 |
|---|---|---|
| 东财有数据（300 只在市） | **东财**（默认不变） | 与 Gate 2 完全一致，可作回归对照 |
| 东财为空（249 只退市） | **新浪** | 唯一能补齐的免费源 |

### 1.4 两源交叉核验（300 只在市股）

| 项 | 数值 |
|---|---:|
| 东财事件数 | 5253 |
| 新浪事件数 | 5284 |
| **同一日期且数值逐字段一致** | **5228（占新浪事件 98.9%）** |
| 同一日期但数值不同 | 16 |
| 仅东财有 | 5 |
| 仅新浪有 | 39 |

数值差异的性质（逐一看过）：**全部是派息金额口径差异，没有一例是送转比例差异**。
例：

| 代码 | 除权日 | 东财（元/股） | 新浪（元/股） | 差 |
|---|---|---:|---:|---:|
| 600989.SH | 2019-09-27 | 0.27545 | 0.32091 | +0.045 |
| 600989.SH | 2021-05-20 | 0.26472 | 0.32091 | +0.056 |
| 600025.SH | 2019-07-05 | 0.14713 | 0.178 | +0.031 |
| 600900.SH | 2016-07-19 | 0.12946 | 0.40 | +0.271 |

→ 影响量级：单次除权日 ADJ 偏差约 0.05~3%，远小于送转口径错误的 20~50%。
由于 merge 规则**东财优先**，这 16 例在最终产物里用的都是东财值，**不影响本池**。

### 1.5 残余风险（必须记下来）

**249 只退市股的新浪事件没有第二源可核。** 东财不覆盖，无第三方免费源。
现有间接证据只有两条：

1. 两个源在 300 只在市股上 98.9% 逐字段一致 → 说明解析与单位正确；
2. 修复后这 249 只**第一次真正接受 A4 检查**，结果暴露出 30 例新的涨跌停违规
   （修复前它们全部"免检通过"）——详见 §3。

## 2. D-2：股改对价送股不在任何分红表里

### 2.1 机制

股权分置改革（2005-04 ~ 2006-12）的对价送股是"对价"，不是利润分配，**东财与新浪都不登记**。
但交易所层面它**确实除权**。

**实证（600031.SH 三一重工，股改第一股）**：

| 日期 | 收盘（不复权） | 说明 |
|---|---:|---|
| 2005-06-15 | 23.82 | 停牌前最后交易日 |
| 2005-06-17 | 16.61 | 复牌，**−30.3%**；方案 10送3.5派8 → 理论除权价 (23.82−0.8)/1.35 = 17.05 |

ADJ 里没有这个因子（事件表无记录），于是 **−30.3% 被当成真实暴跌**留下来。

### 2.2 为什么 A4 没抓到

A4 的两条豁免把这个缺陷**盖住了**：

- 「停牌复牌缺口 > 4 自然日」→ 股改停牌通常数周，**绝大多数直接被豁免**；
- 「零事件 → 不适用」→ 对本身没有分红记录的标的整只跳过。
- 最终只有停牌 ≤ 4 天的 **9 只**被 A4 抓到（600031 / 000301 / 000725 / 000425 / 000776 / 600066 / 600115 / 600660 / 600515）。

### 2.3 量化（`scripts/pre2016_event_gap_diag.py`）

对每只标的找「与上一根 bar 相隔 > 8 自然日」的复牌点，看复牌日原始跌幅是否 ≤ −10% 且该日无已登记事件：

| 年 | 疑似未登记除权 | 已登记事件复牌 | 复牌暴涨(≥+15%) |
|---|---:|---:|---:|
| 2005 | 46 | 0 | 0 |
| 2006 | **115** | 0 | 9 |
| 2007 | 6 | 0 | 6 |
| 2008 | 21 | 1 | 0 |
| 2009 | 4 | 0 | 2 |
| 2010 | 4 | 0 | 3 |
| 2011 | 8 | 0 | 1 |
| 2012 | 3 | 1 | 2 |
| 2013 | 6 | 1 | 3 |
| 2014 | 11 | 0 | 1 |
| 2015 | 42 | 1 | 0 |

**549 只中 158 只在 2005-2007 至少命中一次。**

2008 之后的数字不能直接读作"未登记除权"：其中相当一部分是**重组/借壳复牌暴跌**
（真实价格行为，ADJ 不需要修正），启发式无法区分。

### 2.4 处置

**2005-2006 整段排除，实验窗口从 2007-01 起。**
依据是数据可用性（股改集中度 46+115 例 vs 其他年份个位数），**与任何收益率结果无关**。
不做"逐只补股改对价"的工程——那需要用公告文本重建 158 只的送股比例，成本高且同样无第二源可核。

## 3. 修复后的验收变化（前后对照）

### 3.1 全样本 A1~A7（549 只，2004-12 ~ 2026-10）

| 事件源 | 通过 | 失败 | 失败构成 |
|---|---:|---:|---|
| 东财 only（**修复前**） | 540 | 9 | A4 × 9 |
| **merge（修复后）** | **510** | **39** | A4 × 38、A7 × 1 |

**通过数下降不是退步。** 修复前那 249 只根本不进 A4 的检验范围；
修复后它们第一次被检查，暴露出 30 例新的超限日。这个数字才是真实的缺陷率。

### 3.2 窗口内（2007-01 ~ 2015-12）完整性判据

`scripts/gate3_pool_manifest.py`（窗口版 A1/A4 + 覆盖度，事件按交易日对齐）：

| 判据 | 结果 |
|---|---|
| W1 窗口内价格全为正 | 全部通过 |
| W2 窗口内单日 \|收益\| ≤ 板块限幅 + 1.5pp（除权日/停牌复牌豁免） | 14 只失败 |
| W3 自身可交易区间内覆盖率 ≥ 60% | 3 只失败 |
| **合并剔除（R1~R4）** | **17 只** |
| **最终研究池** | **532 只** |

> 该脚本第一版有两处口径错误，已修正并留档（同样是"判据自身出错"的教训）：
> ① 事件只按 `ex_date` 排除，没按"第一个 ≥ ex_date 的交易日"对齐 → 误报 331 只；
> ② 覆盖率用整个 2007-2015 当分母 → 把所有 2010 年后上市的标的判死。
> 修正后失败数从 331 降到 16。

## 4. D-3：旧批次分页截断（002916.SZ）

新旧批次重叠段逐行比对（`scripts/verify_exec_long_overlap.py`）：**548/549 完全一致**。

唯一例外：

| 项 | 旧（`data/exec/`） | 新（`data/exec_long/`） |
|---|---|---|
| 首个交易日 | 2021-07-05 | **2017-12-13**（真实上市日） |
| 行数 | 1280 | 2142 |

旧批次在分页时被"连续两页无新数据"的终止条件截断，**少取 861 个交易日**。
新批次已修正。该股保留在池内（它的问题在旧文件，不在数据本身）。

> 这条同时说明：`fetch_exec_prices.py` 的缺口探针（`probe_gap`）并不总能发现截断——
> 当接口对探测请求也返回同样的截断结果时，探针无信号。**重叠段交叉验证才是可靠手段。**

## 6. 复现命令

```bash
# 1) 长区间 EXEC（约 4.5 分钟，549 只）
python scripts/fetch_exec_prices.py --codes "$(cat data/_codes_broad_549.txt)" \
  --start 2004-12-01 --end 2026-10-16 --out data/exec_long \
  --adj-dir data/qfq_mult/listed --workers 6 --sleep 0.3

# 2) 重叠段交叉验证（必须 548/549 一致）
python scripts/verify_exec_long_overlap.py

# 3) 新浪分红事件（约 27 秒，549 只）
python scripts/fetch_dividends_sina.py --workers 3

# 4) 重建 ADJ（merge 事件源）
python scripts/rebuild_adj_from_exec.py --codes "$(cat data/_codes_broad_549.txt)" \
  --exec-dir data/exec_long --div-source merge --out data/qfq_rebuilt_broad_long

# 5) 股改/未登记除权诊断
python scripts/pre2016_event_gap_diag.py --start 2005-01-01 --end 2007-06-30

# 6) 窗口完整性 + 数据台账
python scripts/gate3_pool_manifest.py
```

> 注意：第 4 步必须用 `--div-source merge`。用默认的 `em` 会**回到修复前的缺陷状态**
> （249 只退市股 ADJ 未复权），且脚本不会报错——这正是这个缺陷能潜伏这么久的原因。
