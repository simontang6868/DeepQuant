## 1. 背景：为什么必须有 L1b

L1a 闸门（`docs/GATES_L1A_DESIGN_AND_ACCEPTANCE.md`，已完成）是向量化粗筛，其成交假设是"T 日收盘信号 → T+1 开盘价成交，无排队、无部分成交"。这对中低频横截面策略勉强可接受，但对任何依赖**盘中执行**的策略会系统性高估收益——挂单排不上、只成交一部分、止损被滑点吃掉，这些在向量化回测里全都不存在。

表 7 因此把 L1 拆成两级：

| 闸门 | 方法 | 通过标准 | 一票否决 |
|---|---|---|---|
| L1a | 向量化粗筛 | 参数覆盖完整、无未来函数、样本内外切分清晰、收益回撤在边界内 | 数据不达标；检测到未来函数 |
| L1b | 事件驱动精验 | 粗筛存活策略在事件驱动引擎下重跑：**收益衰减在阈值内、成交价与滑点可解释** | **精验后收益符号反转**；**成交率较粗筛下降超过预设阈值** |

L1b 的三个判定项（衰减、成交率、符号）都需要一个能做"部分成交"和"滑点归因"的执行内核。本仓库目前没有，这就是两条路的起点。

## 2. 两方案的定义（严格按上位文件表述，不自行加码）

### 方案一：NautilusTrader 立项评估

上位文件 §4.3 原文定位：候选中唯一同时满足「协议可接受、维护活跃、回测实盘代码同构」三项条件的方案；架构价值在于策略类、事件处理器、组合与风控组件在回测 / 仿真 / 实盘三种模式下**完全复用**，仅替换数据与执行适配器。

立项评估须回答四个问题，**任一项不通过则本项目不进入实施，仅保留其架构思想作为自研参考**：

| 维度 | 评估内容 | 通过条件 |
|---|---|---|
| 合规 | LGPL-3.0 在"专有系统链接使用、不分发修改版"场景下的具体义务 | 法务书面意见，明确无需开源自有策略代码 |
| 适配 | 存量通道与行情源的适配器自研工作量（官方适配器以海外市场为主） | 完成一个最小适配器原型，跑通单标的回测 |
| 保真 | 同一策略、同一历史区间在自有引擎与该引擎上的成交价、滑点、收益差异 | 差异可解释、可归因，无系统性偏差 |
| 成本 | 学习曲线与团队上手周期（第三方易用性评分偏低，文档为明显短板） | 两人三周内可产出可运行策略，否则重新评估 |

工作量：两人三周。需独立隔离环境，不接入生产通道。

### 方案二：自研轻量事件驱动内核

上位文件 §4.1 / §4.3 的隐含路径：若方案一不通过，则**仅保留其架构思想**（事件驱动、回测实盘同构、组合与风控分离）作为自研参考。本方案即该路径的显式实施：

- 范围限定：**单市场（A 股）、日频至分钟频**，不做多资产、不做高频、不重建订单簿
- 数据现实：本仓库只有日线（`data/exec_all/`、`data/qfq_all/` 均为日频），无分钟、无逐笔、无 L2 快照
- 因此保真上限是：**事件驱动的时序与账务是真的，成交细节是参数化模型**——这一点在第 4 节 K2 和最终报告里都必须显式写清，不得表述为"复现真实撮合"

## 3. 推进顺序与理由

```
K0 计划+方案一档案 ──► K1 骨架 ──► K2 成交模型 ──► K3 L1b 闸门 ──► K4 验收回归 ──► K5 对比
                                                                                    ▲
方案一（本轮仅留档，不投入评估工时）────────────────────────────────────────────────┘
```

**为什么方案二优先**（三条，按重要性排序）：

1. **方案一的"适配"与"保真"两项都需要参照物**。没有自研内核，"差异是否可解释"无从判断——只能拿别人的文档当标准，那等于放弃评估。
2. **方案二的产出立即可用**。L1b 是表 7 的必经闸门，做完就有；方案一即使评估通过，仍需两到三周适配器原型才能产出第一个可比数字。
3. **方案二是不可逆知识的沉淀**。项目已有 T1–T6 六项工程改造与 L1a 闸门，事件驱动内核与之同属自有代码，能力可复用；引入外部引擎则是把可逆性押在一个我们无法控制发版节奏的依赖上。

**方案一在本轮仍要完成的事**（不因优先方案二而省略）：把背景、候选对比、四维清单、风险与未知项完整落档，并在 K5 用同一套维度与自研版本对比——**留档不等于放弃**。

## 5. 过程记录机制（可追溯性要求）

三层，缺一不可：

1. **进度台账**（本文件第 8 节）：每阶段完成即更新状态、产物路径、验证命令与结果。状态只能是 `未开始 / 进行中 / 已完成 / 受阻`，受阻必须写原因。
2. **决策记录**（本文件第 7 节）：凡是"改了原计划"或"在两可之间做了选择"，记一行——决策、备选、理由、时间。
3. **工作记忆**（`.workbuddy/memory/YYYY-MM-DD.md`）：跨会话可读的坑与结论，只记有长期价值的，不记临时路径与工具报错。

另：所有产物目录按 `reports/` 与 `docs/` 分离，脚本可重跑，**禁止手工改产物数字**——数字只能由脚本生成。

## 6. 对比维度预登记（冻结于 2026-10-27，动手之前）

> 冻结声明：以下 8 个维度与打分口径在方案二实施**之前**写定。K5 只允许按此表打分，不允许新增维度、不允许改口径、不允许因结果不好看而调权重。若发现维度有缺陷，另开文档说明并保留本表原文。

| # | 维度 | 打分口径（0–4 分） | 数据来源 |
|---|---|---|---|
| D1 | 交付成本 | 4 = 一人周内产出可用版本；2 = 两人三周；0 = 超过两个月 | 实际工时记录 / 方案一为评估工时 |
| D2 | 回测-实盘同构度 | 4 = 同一策略类三模式直接复用；2 = 需适配层；0 = 两套代码 | 代码事实（同一类是否被三处调用） |
| D3 | 成交保真度 | 4 = 逐笔/队列级；3 = 分钟级 + 排队模型；2 = bar 级 + 参数化模型；0 = 仅收盘价 | 能力清单 + 所需数据是否具备 |
| D4 | 合规与许可 | 4 = 自有代码无义务；2 = 弱传染（需法务意见）；0 = 强传染 | 许可证文本 |
| D5 | 能力覆盖 | 4 = 多资产 + 分钟频 + 全事件类型；2 = 单市场日频；0 = 仅单标的 | 实测或官方文档 |
| D6 | 可维护性 | 4 = 自持代码 < 5k 行且测试覆盖；2 = 外部依赖需跟版本；0 = 依赖已停更 | 行数 / 发版节奏 |
| D7 | 与现有系统集成成本 | 4 = 直接接入 T1–T6 与 L1a 契约；2 = 需适配；0 = 需重写 | 接入点清单 |
| D8 | 结论可复现性 | 4 = 产物 + 脚本 + 哈希齐全；2 = 部分可复现；0 = 黑盒 | 产物清单 |

**为什么是这 8 个**：上位文件表 5 的四维（合规/适配/保真/成本）覆盖了 D1、D3、D4 与 D7 的一部分；D2 是 §4.3 的架构价值主张，必须单独量；D5、D6、D8 是长期持有成本，方案一"通过立项"后仍要付。缺 D2 就无法验证"消除两套代码"这个核心卖点，缺 D8 就无法判断评估本身是否可信。

**加权说明**：本轮只做等权汇总，并**同时报出各维度原始分**。等权是"没有正当理由偏袒任何一方"的默认值，不是为了凑结论；若后续需要加权，须另行预登记权重。

## 9. 风险与停止条件

| 风险 | 影响 | 应对 |
|---|---|---|
| 无日内数据导致"保真"名不副实 | 高（结论可能被误读为"已验证实盘可成交"） | 报告中固定段落声明保真上限；所有模型参数标注"模型假设"；不得以 L1b 结果论证实盘可行 |
| 自研内核与日线引擎结论差异过大 | 中（说明其中一方有 bug） | 同一策略、同一区间先在**无摩擦配置**下对齐（滑点=0、费率=0、100% 成交），差异必须收敛；不收敛则先查实现而非调参 |
| 范围蔓延（想顺手做多资产/分钟频） | 中 | 严格按 §2 范围；新需求登记为后续任务，不并入本轮 |
| 方案一留档后被遗忘 | 低 | K5 强制逐维打分；档案文件顶部写"待对比"标记 |

**停止条件**（任一触发即停手并报告，不硬推）：

1. 无摩擦对齐做不到（说明内核有未定位的实现错误，继续往上叠模型只会掩盖）
2. 发现必须改动既有 `backtest/` 或 `gates/` 的行为才能继续（属改动已验证模块，需授权）
3. 验收证据中出现无法用已知原因解释的数字
