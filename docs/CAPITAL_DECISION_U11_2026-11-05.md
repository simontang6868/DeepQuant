### 1.1 为什么给区间而不是一个数

**8.9% 是一次抽样。** 每只的余数 = 预算 mod 一手金额，落在 `[0, 一手)` 的哪一段完全看运气；
4,000 元预算、4 只标的一手金额 541/777/941/1,570 元 ⇒ 解析期望 12.0%，实测 8.9% 属**偏好的一次**。

敏感性表里可见同样的锯齿：15 万（每只 6,000）单次抽样反而比 10 万差（90.6% < 91.1%）。
**整手浪费不是预算的单调函数**，只有取期望才单调：

| 本金 | 每只预算 | 整手投入率（本次抽样） | 期望投入率 | 混合年化（抽样 / 期望） |
| ---: | ---: | ---: | ---: | ---: |
| 10 万 | 4,000 | 91.1% | 88.0% | 7.66% / **7.50%** |
| 20 万 | 8,000 | 96.0% | 94.0% | 7.91% / 7.80% |
| 50 万 | 20,000 | 96.9% | 97.6% | 7.95% / **7.99%** |
| 100 万 | 40,000 | 98.7% | 98.8% | 8.04% / 8.05% |

复算命令（只读，不写台账、不发单）：

```bash
python scripts/dryrun_decision_day.py --lot-sweep
```

## 2. 口径限定（引用必带）

1. **单月、4 只标的**的实测；期望值只用了这 4 只的一手金额，不是全池分布。
2. 这是用既有产物做的**算术**，**不是新回测**。要给出长期分布须新预登记（换口径 = 新实验）。
3. 未建模：预算变小后换手/费率/5 元佣金下限会变（费率按同一比例缩放的假设不成立）。
4. 混合年化沿用「满额投入 +8.11%」这一锚；闲置部分按现金 3% 计息。锚本身是样本内数字。
5. `7.50%~7.66%` 仍是**样本内**推算，样本外证据为 **0**。

## 3. 没有因此改动的东西

| 不被本次决定改动 | 理由 |
| --- | --- |
| 8% 年化门槛 | 结果不达门槛时改门槛，就是用判据凑结果（R2/R11） |
| `n_hold` 5 只、20% 仓 | 改参数需新预登记；且本次无「择优」依据 |
| `sp4_config_v2.json`（sha `32fb5fee`） | 冻结文件不改，决定记在本文与 STATUS |
| 价格上限/流动性门槛 | 同一档，改则牵动全部账本 |

**明确不做的**：不因为「整手浪费大」就去调 `n_hold` 或仓位来把年化做回 8%——那是拿同一批数据择优。

## 4. 何时重开这条决定

触发任一条件即回到用户面前（不自动改配置）：

1. 本金上调到 **≥50 万**（期望年化回到 ≈8.0%）；
2. 标的**一手金额中位数**相对本次（541~1,570 元）上升 ≥50%，即每只预算能覆盖的整手数下降；
3. 出现连续 2 个月的实盘整手闲置 >15%（台账 `weight_mae` + 未投资比例双记录）。

## 5. 与既有结论的关系

- U-5 的「<50 万时 5 元最低佣金主导成本」与本文的「整手」是**两条独立理由**，方向一致：10 万本金下，费用与整手各自吃掉一块，**8% 门槛在 10 万上本来就贴着走**。
- R4-8 的成本余量 0.11pp、本文的整手缺口 0.34~0.50pp，**不可相加**：一个是费率，一个是投入率，口径不同；同时成立时以本文的区间为准（成本已包含在 8.11% 里）。
- 结论方向不变：**10 万可执行，但预期年化 7.5%~7.7%，低于策略自身 8% 门槛**。这是用户已知情接受的缺口，不是需要隐瞒的偏差。
