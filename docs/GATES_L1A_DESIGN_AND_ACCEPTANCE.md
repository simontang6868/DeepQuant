## 1. 落地边界（先说不做什么）

1. **不做 L1b 的撮合保真**。L1a 跑的是现有日线引擎（下一根 K 线开盘成交、常数滑点），
   它回答的是"值不值得进更贵的引擎"，不是"实盘能不能赚钱"。
2. **本仓库没有事件驱动引擎**（计划 §4 的引擎选型仍是待决策项）。因此 L1b 目前**无载体**，
   L3 Walk-Forward 也只是引擎的一个用法。这一点不掩饰：L1a 通过 ≠ 可以进 L4。
3. **回测跑在研究层（复权）数据上**。本仓库的约定是 `qfq` 算收益、`exec` 判交易状态；
   L1a 不承担撮合保真，用不复权价反而会让除权日跳空污染收益。交易层只用于跨源抽检。
4. **闸门是纯计算**：不落盘、不改数据（有专门测试守着）。写文件是 CLI 的职责。

## 2. 契约：为什么边界必须先冻结

闸门最怕的不是严格，是"再试一次就过了"。所以所有可变输入都进契约文件，并算出摘要：

- 策略 id、参数网格、**参数间结构约束**、声明点数
- 样本内 / 样本外区间
- 6 条边界（含 `max_oos_degradation`）
- 数据源（研究层 + 交易层）

契约自带完整性检查，任一不满足直接 `L1A_REJECTED_SPEC`：

| 检查 | 触发例 |
|---|---|
| 字段缺失 | 删掉 `boundaries` |
| 区间重叠 | `out_sample.start ≤ in_sample.end`（等于用样本外调参） |
| 声明点数与有效组合数不符 | 声明 4，实际有效 3（约束把 `fast≥slow` 排除了） |
| 回撤写成百分数 | `max_in_sample_drawdown = 30` |
| 未支持的选参指标 | `selection_metric = "sharpe"` |
| 约束排空网格 | `fast=[20], slow=[15]` |

摘要只覆盖内容，不含生成时间。**改边界 ⇒ 摘要变 ⇒ 报告与旧结论对不上**，这是有意的摩擦。

### 2.1 真实用例的边界与依据

| 边界 | 取值 | 依据 |
|---|---|---|
| 样本内累计收益 | ≥ 0.58 | 项目既定 8%/年目标 × 6 年（1.08^6−1 ≈ 0.587） |
| 样本内最大回撤 | ≤ 0.25 | 单标的容忍上限 |
| 完成交易笔数 | ≥ 10 | 少于 10 笔的绩效不具统计意义 |
| 样本外累计收益 | ≥ 0.00 | 对齐表 7 中 L3 的「样本外收益符号反转即否决」 |
| 样本外最大回撤 | ≤ 0.25 | 与样本内同口径 |
| 样本外收益保留率 | ≥ 0.50 | 待研究员校准的初值（表 7 允许"建议初值"） |

这六个数**在跑之前写进契约**，跑完没有改。第一版草稿用了 0.30/0.30，发现那是我先看过
一次运行结果才写的，属"事后填边界"，已作废重写为上面这套有外部依据的取值
（判定不变，仍是 `L1A_REJECTED_BOUNDS`）。

## 3. 否决链：顺序就是判定逻辑

```
契约 → 数据 → 未来函数 → 网格覆盖 → 收益/回撤边界
```

先跑便宜且能一票否决的检查，是为了避免在脏数据或带泄漏的策略上浪费几百次回测。
实测：泄漏命中时 `sweep == {}`，一次网格都没跑（有测试守着这条）。

## 4. 未来函数：静态认写法，动态认行为

| 检测 | 手段 | 能抓 | 抓不到 |
|---|---|---|---|
| 静态 | AST 扫策略类源码 | `rolling(center=True)`、`shift(-k)`、`bfill()`/`fillna(method='bfill')`、`pct_change(-k)` | 只在 helper 函数里写坏（**不递归**）；换马甲的实现（自定义倒序卷积） |
| 动态 | 8 个时点截断重算 | 任何"用到了 t 之后信息"的实现，含全样本 z-score、全期归一化 | 必须全样本才能算的指标（会误判）；短窗口算不出的实现（记为跳过并留原因） |

动态判据不需要辩论合理性：**t 时刻能拿到的数据就是 `df[:t+1]`**。用 `df` 算出来却与
`df[:t+1]` 不同的信号，一定用到了未来。

实测：`rolling(center=True)` 两种检测同时命中；全样本 z-score 只有动态能抓到；
真实策略 `ma_cross`（内部走 `rolling_mean` helper）静态 0 命中、动态 8/8 一致 ——
这条正好暴露了"静态不递归"的局限，已写进 §8。

## 5. 网格与覆盖率：分母必须是有效组合数

- 分母 = 「通过约束过滤后的组合数」，不是笛卡尔积，也不是"实际跑成功的点数"。
  否则少跑几个点就能把覆盖率做成 100%。
- 跑失败的点（构造失败/回测异常）计入**未覆盖**，逐条记录错误。
- 约束排除掉的组合**单独报数量**（真实用例 16 个组合里 `fast=20,slow=15` 被排除 → 15 点）。

选参与样本外：

1. 全网格只在样本内跑；
2. 按 `selection_metric`（默认累计收益）选最优，并列取参数顺序靠前者（确定性）；
3. 样本外**只跑一次**，并把 `oos_evaluations` 写进报告——不等于 1 就判 `INCONCLUSIVE`；
4. 参数高原：与最优点"只差一个参数、各差一格"的邻域里，收益为正的比例（最小可辩护定义）。

## 6. 诚实指标：三态，不允许"填个数"

`Metric` 构造时就校验：无数值必须是 `not_computable` 且**必须带理由**。
写不出理由的"不可计算"会被拒绝——理由本身是证据。

边界判定只接受 `ok` 的指标；`not_computable` 记为 `passed=None`，汇总时优先级：
**fail > undetermined > pass**。即：只要有一条明确失败就说失败；没有失败但有判不了的，
就说 `INCONCLUSIVE`；全过才 `PASS`。

实测 `INCONCLUSIVE` 用例（样本外区间落在未来）：`out_sample.*` 三个指标全部
`value=null` 且带理由，报告表格里显式显示"**不可计算**"。

## 7. 真实行情上的一次完整判定

**假设**：`ma_cross` 在 `000001.SZ` 上，样本内 2016-01-01~2021-12-31，样本外 2022-01-01~2026-06-30，
网格 `fast × slow = 4 × 4`（约束过滤后 15 点）。

| 环节 | 结果 |
|---|---|
| 数据 | 5140 行；OHLC 0 违例；跨源日期覆盖 1.0000、收益不一致 **19 天 / 0.37%**（门槛 5%）→ 通过 |
| 未来函数 | 静态 0 命中；动态 8/8 一致 → 通过 |
| 覆盖 | 15/15 = 100% → 通过 |
| 选参 | `fast=3, slow=60`（仅样本内选）；参数高原 2/2 邻域正收益 |
| 样本内 | 累计 **+93.18%**、年化 12.03%、最大回撤 **32.84%**、23 笔平仓 |
| 样本外 | 累计 **−12.84%**、年化 −3.14%、最大回撤 23.41%、25 笔平仓 |
| 判定 | **`L1A_REJECTED_BOUNDS`**：回撤 32.84% > 25%；样本外收益 −12.84% < 0；保留率 −13.8% < 50% |

**引用限定**（必须一起引用）：该结论只对**这只股票、这个区间、这套边界**成立。
它与既有的 `ma_cross` 独立复核（`CONFIRMED_NEGATIVE_EDGE_IN_TESTED_DESIGN`，48 只沪深300 ×
walk-forward × 三档费率）**对象不同**，不能互为证据；只能说方向上不一致性没有出现。

## 8. 限制与未决（如实列出）

1. **静态扫描不递归 helper**：`ma_cross` 的均线在 `analysis.rolling.rolling_mean` 里，
   静态看不到；靠动态兜底。要真正覆盖需做调用图分析（未做）。
2. **动态检测对"必须全样本"的实现会误判**：把"全期 z-score"这类写法判成泄漏。这类写法
   在实盘本来也无法实现，判泄漏是合理从严；但如果将来引入"滚动 z-score"，需确认
   `rolling` 而非 `expanding` 全期。
3. **样本外只有一次评估，功效很低**：一次 OOS 判定的信息量有限，这也是 L3 Walk-Forward
   存在的理由；L1a 的 OOS 只用来抓"符号反转"这种粗粒度问题。
4. **没有交易成本口径的选择**：默认用引擎的模拟占位费率。真实费率敏感性属 L2/L4，
   但意味着 L1a 的边界判定对费率不敏感——**不要**用 L1a 的收益数字去谈"成本后 alpha"。
5. **L1b 无载体**：本仓库没有事件驱动引擎，计划 §4 引擎选型仍未决。L1a 的"通过"目前
   只能接到日线引擎的其它用法上，接不了真正的精验。
6. **真实用例只有一只股票**：单标的不是组合策略，L1a 的组合级用法（横截面选股）尚未实现。
