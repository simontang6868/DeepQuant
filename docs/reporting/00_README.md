## 这个目录是什么

按任务书第 66 行与 §5 2.10，向券商办理程序化交易报告需要提供：**资金规模、申报速率或单日笔数、主要策略、交易软件信息**。本目录是这四项的材料草稿。

| 文件 | 对应申报项 |
| --- | --- |
| `01_策略说明.md` | 主要策略 |
| `02_申报速率与单日笔数上限.md` | 申报速率、单日笔数 |
| `03_交易软件说明.md` | 交易软件信息 |
| 本文件 | 说明用法、标注待填项、声明哪些数字还不是运行时事实 |

**不包含**：券商账号、密码、token、客户号——一个都没有，也不要往这里加。本目录若需提交，请自行核对无凭证。

## §2 两项前置（**未完成前不得提交申报**）

### ① 限速器尚未接入发单循环

`execution/rate_limit.py` 已实现并有 22 条测试，但 **Phase 2 没有会发单的循环**（SHADOW 不发送、LIVE 未启用）。所以 `02` 里的「2 笔/秒、突发 2」目前是**设计上限**，不是运行时保证。

把设计上限当运行时保证提交，性质与填错数字不同——前者是承诺不实。**必须等 Phase 3 接入后、实测过一轮再提交。**

### ② 重定价与顺延调度尚未实现

`02` 里写的「10:30、14:30 各最多重定价一次」「收盘未成交顺延，最多 10 个交易日」来自 Phase 2 验收标准的预登记值，**实现里目前只有 `client_order_id` 的 `-r1` 版本号语义，没有调度器**。见 `reports/PHASE2_10_REPORTING_DRAFT_2026-11-03.md` §5 的更正记录。

## §3 本目录三个数字的可核查性

申报材料最容易出的问题不是写错，而是**写完没人再核对**，于是代码改了、材料没改。所以这份草稿里的关键数字不靠人抄：

| 数字 | 写在 | 由什么保证一致 |
| --- | --- | --- |
| 单日笔数 12 | `02` §2 | `test_max_orders_per_day_matches_risk_gate` |
| 价格偏离 0.3% | `02` §3 | `test_price_deviation_matches_planner` |
| 整手 100 股 | `02` §3 | `test_lot_size_matches_planner_default` |
| 每秒上界 4 笔 | `02` §1 | `test_upper_bound_claim_matches_implementation` |
| 「12 笔约 6 秒」 | `02` §1 | `test_single_order_window_claim_is_consistent`（实跑验证） |
| 策略 n_hold=5 | `01` §2 | `test_n_hold_matches_strategy_config` |

全部在 `backend/tests/execution/test_execution_config.py`。数字的唯一来源是 `research/stock_pick_2026-10-25/forward/execution_config_v1.json`，其中每个数值都标了 `_source_<键名>`。

## §4 一个必须说清的边界

这套系统目前的状态是：**策略与风控代码完成，尚未接入真实券商，LIVE_ENABLED 全程 false**。

因此本目录的材料描述的是「**投产后将如何运行**」，不是「现在正在如何运行」。两者的区别必须在提交时向券商说明清楚——尤其是「申报速率」这一项，它的含义是"我的程序最多以这个速率发单"，而程序现在还不发单。

如果券商要求"已实际运行"，那需要先跑完 SHADOW 20 个交易日（依赖 D8 运行机器），本目录的材料在那之后才具备提交条件。
