# F3 处理方案对比（配置 ↔ 实现不一致）· 交用户选择

**日期**：2026-11-05
**缺陷**：`CONFIG_PRICE_FILTER_MISMATCH`（价格上限 配置 1–50 / 实现 1–200）、`CONFIG_LIQ_PCT_DENOMINATOR_MISMATCH`（分位 配置写"全市场" / 实现是"可买子集内"）
**状态**：**默认不动**。本文只做对比，不改任何文件，等用户选择。
**禁止**：`LIVE_ENABLED` 仍为 false；11-30 前不改任何策略参数。

---

## 1. 先回答"配置到底参不参与运行时读取"

这是选择的前提，实测结论：**参与，但不是所有字段都以你以为的方式参与**。

日更链路 `deploy/bin/daily_chain.sh` 只调用 6 个脚本：`update_exec_incremental` / `p17_universe_filter` / `is_due` / `rebuild_adj_from_exec` / `verify_qfq_rebuild` / `p13_forward`。
其中只有 **`p13_forward`** 与策略参数有关，它通过 `scripts/sp5/strategy_params.py::load_params()` 读配置：

| 配置字段 | 运行时是否读取 | 读到哪 | 行为影响 |
| --- | --- | --- | --- |
| `price_filter` = [1, 50] | ✅ 解析成 `price_hi=50` | 只赋给 **对照列** `CLOSE_HI_CFG` | **主口径不读它**：`CLOSE_HI_MAIN = KNOWN_DIVERGENCES["price_hi"]["code_value"] = 200` |
| `band` = "amt20 全市场分位 < 20%" | ✅ 正则取 **数值 0.20** | `LIQ_MAX`（主口径**真的用它**） | 数值用；**"全市场 vs 子集"这句文字解析器不看** |
| `f3_filter_entry` | ✅ 解析 `0.70` | `THRESH`（主口径用） | 有效 |
| `liquidity_filter` | ✅ 解析 500 万 | `AMT_MIN`（主口径用） | 有效 |
| `n_hold` | ✅ | 主口径用 | 有效 |

**两个不一致的真实性质不同**：

- **价格上限**：配置里的 50 **没有进入主口径**，主口径硬取 200（并已在 `KNOWN_DIVERGENCES` 里登记为待办）。
  ⇒ 这是**配置文档漂移**，不是实盘行为错。若真按 50 跑，选股会全变：`sp5_out/p13c_rule_diff_check.json` 实测 3 个月 **top5 重合 0/5**。
- **分位分母**：`LIQ_MAX=0.20` 被**真的使用**，只是分母在 `p13_forward` 里是**子集内重算**（`g["liqpct"]=g["amt20"].rank(pct=True)`，g 已过滤）。
  配置写"全市场分位" ⇒ **实现与文字不符，且实现被回测沿用**。这一条比上面那条更实质。

## 2. 方案 A：只改文字/配置，对齐到"已回测、已前瞻"的实现

**方向必须写死：50 → 200、文字 → "可买子集内分位"**（对齐到实现，不是反过来）。理由是反过来等于换策略：回测从未跑过 50 口径。

| 改动点 | 内容 |
| --- | --- |
| 新配置 | 出 `sp4_config_v3.json`（不改 v1/v2 冻结文件）：`price_filter` [1,200]、`band` 文字改"可买子集内 amt20 分位 < 20%" |
| 代码 | `PARAMS_VERSION` 常量同步；`KNOWN_DIVERGENCES["price_hi"]` 标为已解决（保留历史，不删除） |
| 对照列 | `CLOSE_HI_CFG` 退化为与主口径相同 ⇒ 停用该列，历史产物保留为 `legacy` |
| 证明无行为变化 | ① 一致性测试：同月末用 v3 与 v2 生成的目标名单**逐位相同**；② AST 测试（已有）确保没有新的硬编码；③ 全量回归 |
| 回测账本 | **不动、不重跑** |

**成本**：改动点 4 处 + 新配置 1 份 + 2 条测试；预计半天。**零账本重跑。**
**对证据的影响**：**无**——所有产物（`sp5_tradability*.json`、7 条可引结论）都基于 200 口径与子集分母，方案 A 不碰它们。
**风险**：v3 会被误读成"新策略版本" ⇒ 必须在 diff 字段写明"**仅文字对齐，无行为变化**"，并把一致性测试结果挂进产物；否则三个月后没人能证明它没改行为。

## 3. 方案 B：改实现，让代码服从配置文字

| 改动点 | 内容 |
| --- | --- |
| 价格上限 | 主口径由 200 改为读配置 50 |
| 分位分母 | `liqpct` 改为**全市场**分母（`rank` 在过滤前算） |
| 牵连脚本 | `p13_forward`、`strategy_params`、`p03`/`p03e`/`p04` 等 sp5 全链、`p13c` 对照逻辑 |
| 重跑范围 | **257 个月 × 4 档成交假设 × 200 条路径**的账本；d4 / d4aff 两套预登记结果；块自助法；成本校准表；申报材料 §5/§5.3 |
| 需重算的结论 | 至少 `phaseo_netBASE`（sp4 池 + 成本）必须重算；其余 6 条的受影响范围**须由脚本逐一核对后列出**，不在文档里拍脑袋 |
| 流程要求 | 换池 = 新实验 ⇒ **必须新预登记**（R2/R12），旧结论只能标"旧口径"，不能与新口径混引 |

**成本**：改动点 6+ 处、全链重跑、新预登记 1 份；**按既有节奏是"周"级，不是"天"级**。
**对证据的影响**：**全部作废重算**。而且 11-30 的样本外时点会与现有前瞻记录**不同源**（10-30 台账是 200 口径生成的），等于把唯一的样本外窗口往后推。
**唯一的好处**：配置文字与代码从此单一真源。

## 5. 建议（供参考，不代替用户决定）

**建议 A，且必须带一致性测试**。理由：实现是目前唯一被 257 个月回测跑过、且 10-30 台账（已生成、待 11-30 判定）所用的口径；
把文字改成实现，是让文档追上事实；把实现改成文字，是让事实去追一份没跑过的描述。
后者需要新的预登记 + 全量重跑，而**当前唯一稀缺的东西是样本外时间**，不是文档整齐。

**若选 A，需要你确认一句话**：「允许出 v3，且 v3 仅是**文字对齐**（`price_filter` 50→200、`band` 措辞），不产生任何选股行为变化；v1/v2 冻结文件不改。」

**若选 B，需要你确认**：「接受可引结论需按新口径重新预登记（范围由脚本核对后确认），11-30 的样本外判定相应后移。」
