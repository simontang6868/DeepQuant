## 2. 预登记 v1.1 修订（在写代码前发现）

v1 的第 3 节写着：

```
P2  t 日及 t-64 ~ t-5 窗口内所有交易日的 open/close/high/low 均 > 0
P3  动量窗口内有效交易日数 ≥ 窗口长度的 90%
```

**P3 是死条款**：P2 若成立，窗口内有效率恒为 100%，P3 的「≥90%」永远为真。
而且 P2 会把「窗口内停牌一天」的股票整体排除，与第 2 节「停牌只能用日期缺失近似」
的声明自相矛盾。

改为：P2 只管信号日当日（必须可定价、可成交），P3 管窗口覆盖率。
修订记录见预登记附录 A，**修订时尚未运行任何回测**。

这条修订值得单独记一笔：它不是「看到结果后调参」，是**写代码时被规格逼出来的**
——一实现就发现 P3 永远不会触发，说明这两条在文字阶段就没想清楚。

## 3. 实现中的四个关键决策

### 3.1 日历用并集，不用交集

用交集会把「某只股票晚上市」的那些月份整段砍掉——那等于用「它后来上市了」
这个事实来决定样本期。用并集 + 覆盖率门槛处理缺失，与预登记第 2 节的声明一致。

**但并集也带来一个真实代价**：`CrossSectionPanel` 原本只从数据推日历，
所以删掉某一行会让整个日历平移、「信号日」跟着漂移。因此加了显式 `calendar`
参数——回测区间固定时必须由调用方指定，不能由数据反推。

### 3.2 非正价置空，但「有没有这一行」要单独记

`_aligned_frame` 把 `≤0` 的价格置为 `NaN`（复权缺陷产物不能当有效价格）。
但对齐后，「价格被污染」和「压根没有这一行」变成同一个值。

实测证据：`600809.SH` 2017 年既有负价行、也有整行缺失。若不区分，报告只能写
「那天没有数据」，无法回答「是因为停牌、因为未上市、还是因为复权缺陷」。

所以另存一份 `_has_row` 掩码，把剔除原因分成 5 类而不是 1 类。

### 3.3 「未上市」必须与「停牌」分开

第一版把所有「当日无行」都记成 `no_row_on_signal_date`，实测得到 **390 次**。
按标的拆开一看：

| 标的 | 次数 | 实际原因 |
|---|---|---|
| `688271.SH` | 64 | 2022-08-22 才上市 |
| `600938.SH` | 60 | 2022-04-21 才上市 |
| `688082.SH` | 55 | 2021-11-18 才上市 |
| `300896.SZ` | 41 | 2020-09-28 才上市 |
| `688981.SH` | 39 | 2020-07-16 才上市 |

**这 5 只占了 259 次**，与它们的上市日期完全吻合。这些不是停牌，是「当时还不存在」。
拆开后：`not_yet_listed` 363 次 / `no_row_on_signal_date` 仅 **27** 次。

这个区分不是措辞问题——它把「池子的时间不一致」从「交易约束」里分离了出来。

### 3.4 模块里不允许出现交易逻辑

`cross_section.py` 只出「分数」，不出「成交」。测试用静态检查断言该文件不含
`commission` / `lot_size` / `slippage` / `total_equity` / `PortfolioFill` 等标识符，
一条都找不到——这是「没有第二套撮合」最直接的证据。

## 4. 候选集实测（真实 50 只，只统计池子）

脚本：`scripts/gate1_candidate_audit.py` → `gate1_candidate_audit.json`

| 指标 | 实测 |
|---|---|
| 日历 | 1943 天（2017-01-03 ~ 2024-12-31） |
| 月末信号日 | 96 个 |
| **有候选的月份** | **93**（前 3 个月因窗口不足空仓） |
| 可用区间 | **2017-04-28 ~ 2024-12-31** |
| 候选数 | min **33** / 中位 **46** / max **50** |
| top20% 实际持股 | min **7** / 中位 **10** |
| 候选 < 10 只的月份 | **0** 个 |

**结论：横截面规模足够。** 最少的月份也有 33 只候选、持股 7 只，
不存在「只有 1~2 只可挑」导致 top20% 失去意义的情况。

### 4.1 剔除原因分布（累计「标的·月」）

| 原因 | 次数 | 占比 | 含义 |
|---|---|---|---|
| `ok`（进池） | 4153 | — | |
| `not_yet_listed` | **363** | 56% | 当时还没上市 |
| `insufficient_history` | 150 | 23% | 前 3 个月全员（窗口不足） |
| `insufficient_window_coverage` | 91 | 14% | 窗口有效日 < 54 |
| `no_row_on_signal_date` | 27 | 4% | 当日缺行（停牌/数据缺口） |
| `endpoint_price_missing` | 13 | 2% | 窗口端点缺失 |
| `nonpositive_price_on_signal_date` | 3 | 0.5% | 信号日价格非正 |

### 4.2 这个分布说明了一件对结论有影响的事

**候选池随时间单调变宽**：2017-07 有 33 只，2024-07 有 50 只。

原因不是「停牌减少」，而是**池子里有 10 只是 2019 年后才上市的公司**。
这批公司在早期月份根本不存在，所以早期候选池是「33 只已经活到 2026 年、
且仍在沪深 300 里的老公司」。

**这加重了幸存者偏差，而且是单向的**：早期样本的「赢家化」程度高于后期。
因此：

- 若 OOS（2021–2024，候选 45~50 只）出现正超额，**不能**据此推断 2017–2020 也有效；
- 若 IS（2017–2020，候选 33~44 只）表现更好，要怀疑是不是「存活者更集中」的假象。

这条必须写进 Gate 1 最终报告的结论限制里。

### 4.3 `600809.SH` 的实际处置

| 信号日 | 剔除原因 |
|---|---|
| 2017-07-31 | `insufficient_window_coverage:16/60` |
| 2018-01-31 | `no_row_on_signal_date` |
| 2018-07-31 | `ok` |
| 2019-01-31 | `insufficient_window_coverage:49/60` |
| 2019-07 起 | `ok` |

负价不是连续整段，而是分散在 2017–2019 的 131 行里。所以 P3 的覆盖率门槛
把大部分污染月份挡住了，P2 只在信号日恰好撞上非正价时生效（3 次）。

**这个处置是机械的**：规则对 50 只一视同仁，只是这只股票恰好留下了负价证据。

## 6. 第二阶段要做什么（等授权）

按预登记执行即可，不需要新增设计：

1. `CrossSectionPanel` → `scores_by_date` → `build_rebalance_schedule(top_fraction=0.2)`
2. 基准：同面板 + `top_fraction=1.0`
3. 两者各跑一次 `run_portfolio_backtest`（同一 config、同一成本档）
4. 取 OOS（2021-01 ~ 2024-12）48 个月的月度配对差 `d_t`
5. 按第 10 节三档判据判定；12 组敏感性按第 11 节跑，BH 校正

预计纯计算量不大（50 只 × 96 个月度调仓），主要时间在敏感性 12 组。

### 6.1 提前说明一个可能的结局

预登记第 14 节第 6 条已写：OOS 只有 48 个月度观测，`mean(d)=0.003、σ≈0.06` 时
t 检验需要约 160 个月才能检出。**最可能的结果是「证据不足」**。

如果确实如此，报告的正确写法是「在 48 个月样本上无法区分该策略与零超额」，
而不是「策略无效」或「策略基本有效」。这两句话都不成立，因为：
- 「无效」需要拒绝 `E[d] > 0`，而功效不足时无法拒绝任何东西；
- 「基本有效」是把「不显著」当成「接近显著」，这是同一枚硬币的另一面。

第 4.2 节那条单向幸存者偏差，会进一步削弱「绝对收益为正」这类说法的意义。
