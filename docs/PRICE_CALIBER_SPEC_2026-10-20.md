# 三层价格口径规格与字段命名（阶段 2 · P1-1）

> 生效日期：2026-10-20 ｜ 阶段：数据体系修复（路线图 §6 · P1-1）
> 对应 **A1 两层数据架构**：研究数据层 vs 交易模拟数据层
> 前置：`docs/DATA_PIPELINE_SPEC_2026-10-20.md`（主池已切乘性 qfq，末日 2026-10-16）
> 性质：**字段与口径的命名规范**。目的：让"混用口径"这种错误在命名层就暴露，而不是在结果里。

---

## 1. 一句话

> 四类价格口径**各有明确字段名，禁止混用**。研究层（因子/收益/指标）只能用**调整后价格 ADJ**；
> 交易模拟层（成交/现金/费用/股数）只能用**实际成交价 EXEC**；**价格收益**与**总收益**是两个不同的口径，
> 不能互相冒充。当前 served 数据只有 ADJ 一种，其余三种的可用性见 §4。

---

## 2. 四类口径（三类 + 一个研究层输入）

| 口径 | 代号 | 定义 | 字段命名（规范） | 数据源 | 谁用 |
|---|---|---|---|---|---|
| **调整后价格** | `ADJ` | 乘性前复权价格 `hfq_t × raw_anchor/hfq_anchor` | `close_adj` / `open_adj` / `high_adj` / `low_adj` | `data/qfq_mult/listed/*.qfq.csv`（末日 2026-10-16） | **研究层**：因子、回归、技术指标、回测收益序列 |
| **实际成交价** | `EXEC` | 当日真实可成交的**不复权**价 | `close_exec` / `open_exec`（真实价） | 真不复权行情（腾讯 `kline/kline`，注意 §5 的坑） | **交易模拟层**：成交、现金、费用、股数、一手成本 |
| **价格收益** | `PRICE_RET` | 不复权价格的变动率，**不含股息** | `ret_price` | `EXEC` 派生 | 报告"纯股价涨跌"；与 `TOTAL_RET` 对照 |
| **总收益** | `TOTAL_RET` | 价格收益 + **股息再投资** | `ret_total` | `PRICE_RET` + 股息数据（**当前无**） | 长期持有真实回报、全收益基准 |

> **`ADJ` 是研究层的输入，不是"价格收益"也不是"成交价"**。它只保证**收益率正确**（乘性缩放不改变日收益），
> 其**价位水平**与真实价不同（见 §4）。

---

## 3. 两层数据架构（A1 落地）

```
        ┌──────────────────────── 研究数据层 (RESEARCH) ────────────────────────┐
        │  输入: ADJ（close_adj, ...）                                          │
        │  产出: 因子值 / 收益序列 / 技术指标 / 回测的“账面收益”                 │
        │  红线: 不得把 ADJ 当成交价去做现金/费用/股数计算                        │
        └──────────────────────────────────────────────────────────────────────┘
                                      │  需要“真的能不能买、要花多少钱”时
                                      ▼
        ┌──────────────────── 交易模拟数据层 (EXECUTION) ───────────────────────┐
        │  输入: EXEC（close_exec, 真实不复权价）                                │
        │  产出: 成交价(经滑点) / 现金 / 费用 / 股数 / 一手成本                    │
        │  红线: 不得用 ADJ 的价位去判“买得起/买不起”或算手续费                   │
        └──────────────────────────────────────────────────────────────────────┘
```

**为什么必须分开**：`capital_adequacy.py` 已明确——qfq（ADJ）以最新价为基准回推，
**历史价通常低于当时真实成交价**（分红送转会下调历史价）。因此：
- 用 ADJ 算"一手成本"是真实成本的**下界**；
- 用 ADJ 判"买不起"→**保守方向**（真实只会更买不起，结论安全）；
- 用 ADJ 判"买得起"→**不足以下结论**（可能真实买不起）。

## 4. 当前 served 数据的口径可用性（2026-10-20 实测）

| 口径 | 当前 served 是否可得 | 说明 |
|---|---|---|
| `ADJ` | ✅ 唯一可得 | `data/processed/*.parquet` 的 `open/high/low/close` 即 ADJ，52 只，末日 2026-10-16 |
| `EXEC` | ❌ **不可得** | ⚠️ 见下"命名隐患" |
| `PRICE_RET` | ❌ 不可得（需 EXEC） | 只能从 v0.9.0 备份的真不复权价算，且备份只到 2024-12-31 |
| `TOTAL_RET` | ❌ 不可得 | 无股息字段 |

### ⚠️ 本轮发现的命名隐患（必须在代码/文档层修掉）

切换 qfq_mult 后，`scripts/import_pool.py` 把 **qfq_mult 源（ADJ）** 写进了 `data/raw/<code>.raw.csv`。
实测 000001.SZ：`data/raw/000001.SZ.raw.csv` 末行 = `11.4322,11.5000,...`（= qfq 源），
而**真不复权**末行（v0.9.0 备份里）= `10.72,10.49,...`。

> **结论：`data/raw/` 的 "raw" 已名不副实——它现在装的是 ADJ，不是真不复权。**
> 谁若按字面把 `data/raw/` 当 EXEC 用，就会用调整价算真实成交，方向错且看不出来。

**修复建议（按优先级）**：
1. **短期（命名层，零成本）**：在 metadata 的 `source` 或新增 `price_basis` 字段写明 `"qfq_mult"`；
   文档/代码里把 `data/raw/` 读作"摄入源副本"，不再称"不复权"。
2. **中期（数据层）**：重新取真不复权价（腾讯 `kline/kline`）作为独立 EXEC 层，落 `data/exec/`，
   与 `data/raw/`（=ADJ 副本）物理分开，文件名区分 `*.exec.csv`。
3. **总收益**：需股息数据（`div`），当前无；见 P1-3 数据源评估。

## 5. 取真不复权价（EXEC）的坑（沿用 MEMORY §7）

- 腾讯「不复权」序列 `web.ifzq.gtimg.cn/.../kline/kline` 与 `hfq` **股本基准可能不一致**；
  判据 `raw起点/qfq起点 ≥ 1`，红宝丽实测 **0.963（反了）**，潞安/中建正常。
- 该序列**只有 2 位小数**，日收益有量化噪声（会高估波动率）；**起止点可用，日收益慎用**。
- → EXEC 层用于"成交价水平/一手成本/现金约束"是安全的；**不要**用它算日收益序列（那是 PRICE_RET 的活，
  且 PRICE_RET 的正确算法是从 EXEC 起止点算，不是从 2 位小数日序列累乘）。

## 6. 硬规则（写进代码评审清单）

1. **研究层只用 ADJ**：因子/收益/指标一律读 `*_adj`（或 processed 的 `close` 等，语义=ADJ）。
2. **交易模拟层只用 EXEC**：`backtest/costs.py` 的 `execution_price(base_price)` 的 `base_price`
   **必须传 EXEC**，不得传 ADJ。传错会让滑点后成交价落在错误的价位基准上。
3. **`capital_adequacy` 的 `price_basis` 必须如实标注**：用 ADJ 就写 `qfq`，用 EXEC 就写 `raw`；
   "买得起"的结论只允许在 `price_basis=raw` 下成立。
4. **价格收益与总收益不得互相冒充**：报告"涨了多少"若用的是 ADJ 价位差，须注明"复权口径、不含股息"；
   若宣称"总收益"，必须有股息数据支撑。
5. **字段名必须带口径后缀**：`_adj` / `_exec` / `ret_price` / `ret_total`，禁止裸 `close` 跨层复用。
